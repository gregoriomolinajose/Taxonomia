# Story S49.12: Estabilización Arquitectónica del FormEngine y Stepper

## User Story (Connextra)
**Como** arquitecto de software de la plataforma,
**Quiero** que el FormEngine precargue dependencias indirectas (subtitleLookup) y el Stepper exponga una API limpia de eventos,
**Para** eliminar acoplamientos técnicos (monkey-patching) y resolver la regresión de fallos de visualización síncrona en catálogos.

## Contexto
Durante el Architecture Review (AR) de la historia S49.11 se identificaron dos problemas críticos:
1. **Regresión en TXSearchable**: El campo `Cargo` no se precarga porque el motor de hidratación (`FormEngine_Resolvers.client.js`) ignora la propiedad `subtitleLookup`.
2. **Deuda Técnica (Abstraction Leak)**: `FormRenderer_UI` secuestra el método `goToSection` de `UI_FormStepper` para actualizar los indicadores (puntos) del pie de página, violando el principio de encapsulación.

## Criterios de Aceptación (Gherkin)

### AC-1: Precarga de sub-dependencias en el Resolutor
```gherkin
Given el Schema_Engine.js expone campos con "subtitleLookup"
When FormEngine_Resolvers escanea las dependencias
Then debe incluir las entidades "subtitleLookup" en la cola de precarga paralela
And los datos deben almacenarse en window.DataStore antes de renderizar el formulario
```

### AC-2: Encapsulación de eventos del Stepper
```gherkin
Given que UI_FormStepper controla la navegación del Wizard
When un usuario cambia de paso
Then el Stepper debe despachar un evento o callback nativo (ej. onStepChange)
And NO debe existir monkey-patching sobre el método goToSection desde fuera
```

### AC-3: UI Progress administrado por el Stepper
```gherkin
Given que se requiere actualizar puntos de progreso (dots) en el footer
When el Stepper inicializa y cambia de paso
Then el UI_FormStepper administra directamente el estado visual de los puntos de progreso en el nodo proveído
And FormRenderer_UI se limita únicamente a inyectar el contenedor
```

## Restricciones
- **Cero cambios visuales**: La interfaz debe mantenerse idéntica a los avances logrados en S49.11.
- **Transparencia Asíncrona**: No se debe reintroducir asincronía en el componente atómico `TXSearchable`.
