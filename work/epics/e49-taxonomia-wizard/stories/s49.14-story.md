# S49.14: Graph Indexing & Traversal Utility

## User Story
Como arquitecto de sistema, quiero una utilidad centralizada y cacheada para navegar grafos temporales (`Sys_Graph_Edges`), de manera que se evite la duplicación de código de recorrido y se optimice el rendimiento (O(1)) en dispositivos de gama baja.

## Acceptance Criteria
- [ ] Centralizar la lógica de lectura y recorrido de grafos temporales en una nueva librería `JS_GraphUtils.client.js`.
- [ ] Incorporar un mecanismo de indexación en memoria (ej. Hash Maps por `origen` y `destino`) al momento de cargar `Sys_Graph_Edges` para evitar realizar bucles `find()` o `filter()` sobre listas de miles de aristas en dispositivos de escasa memoria RAM.
- [ ] El índice debe poder destruirse o actualizarse cuando el `AppEventBus` emite un evento de cambio sobre `Sys_Graph_Edges`.
- [ ] Refactorizar el componente `TXSearchable` (`_resolveSubtitle`) para consumir esta nueva API centralizada en lugar de acceder manualmente al arreglo lineal.
- [ ] Refactorizar `UI_DataGrid`, `UI_SubgridBuilder`, `DataView_UI` y `RelationBuilder` para usar la nueva utilidad.

## Technical Notes
- Mantener los principios de *KISS* y evitar que el índice requiera llamadas extra de red (Zero-Trust/Local RAM constraint).
- La indexación debe ocurrir como un *singleton lazily loaded* que reaccione al evento `DATASTORE::CHANGED`.
