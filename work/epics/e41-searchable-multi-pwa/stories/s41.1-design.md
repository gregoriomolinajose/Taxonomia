# S41.1 Design: Web Component API Contract (`<tx-searchable>`)

## 1. Responsabilidad Estratégica
El primer paso de esta épica es aislar el esqueleto del Web Component bajo el uso puro de la API `HTMLElement`. No introduciremos aún la lógica interna de búsqueda (que viene de `SearchableSingle`), sino que estableceremos el **contrato de interfaz**: las propiedades reactivas, configuración interna, constructores y métodos públicos.

## 2. Definición del Standard Custom Element
El Web Component se nombrará `tx-searchable` y estará albergado físicamente en `src/UI_Component_TXSearchable.client.js`. 
Se registrará globalmente mediante `customElements.define('tx-searchable', TXSearchable);`.

## 3. Modelo de Propiedades y Atributos (API Contract)

### Atributos Declarativos (HTML Nativos)
Estos atributos pueden setearse directamente desde el markup HTML o usando `element.setAttribute()`.
- `entity-name` (String): El nombre técnico de la tabla/dominio (ej. "Persona"). Usado para los queries ABAC y lookups.
- `multiple` (Boolean): Flag binario (true/false) que permuta el modo entre Selección Única o Selección Múltiple.
- `pre-selected` (String Opcional): Un arreglo/objeto en formato JSON para rellenar visualmente el componente al instanciarse (hidratación).

### Propiedades de Estado JS En Vivo
El componente expondrá propiedades internas a las que `FormRenderer_UI` puede acceder instanciando el nodo en Javascript.
- `get/set dataSource` (Array): Pool de datos crudos sobre el que buscará.
- `get/set value`: Getter del valor estricto unificado. Si `multiple` es falso, devuelve `String|null` (id seleccionado). Si es verdadero, devuelve `Array` de ids o proxies nativos para el FormRenderer.
- `getValidatedValue()`: Bridge method para mantener compatibilidad con las directivas de la Epica E35 de recolección de Nodos Táctiles (`node.getValidatedValue()`).

## 4. DOM Lifecycle Management (Safety limits)
Dado que será altamente re-instanciado en SPA Views, el componente suscribirá eventos, y por tanto, se aprovechará del callback estándar de Garbage Collection de los Web Components:
```javascript
connectedCallback() { ... }
disconnectedCallback() {
    // Purga forzada de Listeners (AppEventBus, etc.)
    // Desvinculación de referencias a arrays pesados para Memory Cleansing
}
```

## 5. Event Dispatching
El modo Multi y Single tienen naturalezas de cierre asíncrono.
- Si es Single: Al dar click en una opción se cierra el Popover e instiga el evento de cambio.
- Si es Multi: El usuario activa mutiples casillas, necesita un botón de cierre/submit, disparando el evento de cambio al finalizar el batch.
En ambos casos, destilarán su output estandarizadamente publicando un `CustomEvent('txChange', { detail: { value } })`.
