# S41.2 Design: Hybrid Architecture & State Engine

## 1. Responsabilidad Estratégica
La historia S41.2 inyectará el **Motor Híbrido de Renderizado** dentro de la función abstracta `_render()` del Web Component `<tx-searchable>`. Su responsabilidad es generar el HTML funcional que el usuario operará (Input, Tags, Modales Ionic), manteniendo el diseño responsivo establecido en `SearchableSingle` pero adaptado fluidamente para múltiples selecciones bajo demanda.

## 2. Abstracción del Layout: Modos Estructurales
Se definen dos entidades renderizables totalmente distintas bajo la misma clase.

### A. El Nodo "Trigger" (Visible siempre en el Formulario)
Es la cáscara del Custom Element que habita en el flujo natural del formulario.
1. **Container Base**: Div relativo que engloba un `<ion-input>` interactuando como máscara de un *Combobox*.
2. **Display de Identidad (Pills)**: Si `this._isMultiple` es verdadero y hay ítems seleccionados, el texto interno mostrará un conteo (ej. "3 ítems seleccionados") y, físicamente sobre el Input, inyectaremos pequeños "Badges/Pills" visuales que el usuario puede arrastrar o des-marcar sin abrir el cajón de búsqueda.

### B. El Nodo "Dropdown / Modal" (Overlay Reactivo)
Actúa diferente dependiendo de la inferencia de pantalla (Mobile vs Desktop) aplicando Patrones PWA:
1. **Desktop**: Se inyecta como un `div` flotante (absolute + z-index) anclado a la base del *Trigger*.
2. **Mobile (PWA)**: Se inyecta un `<ion-modal>` (Bottom Sheet Layout) a nivel de la raíz (`body`), robando la pantalla con gestos nativos de swipe to dismiss y previniendo el temido *overscrollY* (Pull-To-Refresh bug).

## 3. Estado Asíncrono de Búsqueda
El buscador (`currentSearchTerm`) vivirá como un estado efímero del componente. 
Al teclear, el motor buscará sincrónicamente dentro de `this._dataSource` instanciando un _debounce_ ligero para no asfixiar el reflow de `ion-list`, y reescribirá la lista HTML de forma destructiva (mismo patrón ligero de E35).

## 4. Diferenciación de Cardinalidad (Single vs Multi)
La *Lista* dentro del modal iterará y dictará su lógica dependiendo de `this._isMultiple`:
* **Single Mode:** Cada `ion-item` dibuja la línea. Al hacer click, el Modal hace dismiss `close()` y auto-despacha el `txChange`.
* **Multi Mode:** Cada renglón contiene un `<ion-checkbox slot="end">`. Hacer click no cierra el modal. Se dibujará adicionalmente un Header Toolbar Modal con un botón "Confirmar" (`[X] Aplicar`).

## 5. Security & Garbage Collection
El modal será estrictamente rastreado en memoria como `this._popoverNode`. Ya dejamos en S41.1 que `disconnectedCallback()` destruirá el nodo físico si el usuario navega fuera mientras el modal estaba a medio abrir.
