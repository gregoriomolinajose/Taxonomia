# Story S41.7: Desktop Fallback Architecture (Absolute DIV UI Clone)

## Goal
Implementar una solución de fallback "Pixel-Perfect" para `<tx-searchable>` en entornos Desktop (`!isMobile()`), devolviendo la renderización gráfica y de comportamiento exactamente a la del abandonado `SearchableSingle` sin quebrar el motor PWA subyacente.

## Context (Root Cause Analysis)
El uso masivo de `<ion-popover>` provocó:
1. Desincronización de cajas (Paddings groseros).
2. Constantes "robos" de focus que destruyeron el "Desktop Typeahead" y forzaron bugs de Blur.
3. Degradación estética de la caja de `slot="start"` de UI (colores saturados).

## Implementation Steps
### 1. Inyección de CSS Original
Restaurar los valores exactos paramétricos de `SearchableSingle` original en el `connectedCallback`, asignando `icon-color='step-200'` por defecto al slot en vez del color puro `primary` de Ionic. 

### 2. Bypass de `ion-popover`
Reemplazar la bifurcación lógica en `executeSearchAndOpen()`: en vez de generar `document.createElement('ion-popover')`, instanciar un contenedor `div` plano ajustado vía `.getBoundingClientRect()` directo al trigger-box.

### 3. Re-anexar Blur Anti-Races
Con el `div` custom restaurado, la "captación de clicks externos" requiere obligatoriamente repescar nuestro algoritmo estático S35.4 dentro de `ionBlur`, asegurándonos del cierre limpio automático.

## Acceptance Criteria
- [ ] En pantallas grandes, teclear directamente abre inteligentemente la lista debajo sin usar el `ion-popover` de Ionic.
- [ ] El ícono izquierdo tiene fondo gris claro (`var(--ion-color-step-200)`).
- [ ] No hay robos de foco; la escritura no crashea ni cierra la lista.
- [ ] El Modal (Bottom Sheet completo) para móviles continúa intacto.
