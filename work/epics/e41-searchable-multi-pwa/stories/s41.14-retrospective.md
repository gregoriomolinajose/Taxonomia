# Retrospective: Migración de Subgrids Legacy a TXSearchable (S41.14)

## Background & Context
El problema principal abordado en esta historia fue la consolidación de la arquitectura de UI. Anteriormente, la creación de registros anidados se gestionaba mediante `UI_SubgridBuilder.client.js` inyectando botones manuales desvinculados del flujo general. Con la introducción de `<tx-searchable>`, necesitábamos unificar esos flujos bajo el paraguas técnico unificado de este Custom Component, permitiendo tanto invocar el panel de selección, como desencadenar el formulario de creación (`window.renderForm`) interceptando el pipeline del padre.

## Technical Execution
- **Componente Nativo VCA**: Se integró el botón nativo de "Crear {Entity}" transparente a si el `tx-searchable` funge visualizado en Desktop (Popovers/Dropdowns) o Mobile (Modales o Inline Layouts).
- **Ruta de Cero-Colisiones**: En lugar de navegar utilizando un routing invasivo (`window.UI_Router`), el componente delega usando el Custom Event `txSearchableCreate` la inyección en el DOM, donde `UI_Component_RelationBuilder` lo escucha y orquesta la creación sobre la entidad pre-calculada (`target-entity` inyectado vía el factory).
- **Hardening E2E**: El mayor desafío técnico de la última milla fue reajustar los Playwright Tests (como `ui-resilience.spec.js`, `cardinality-resilience.spec.js`, `ghost-stealing.spec.js` y `hierarchy-stress.spec.js`). Playwright fracasaba consistentemente en resolver clics mecánicos demasiado rápidos ante Custom Elements con delays visuales (ShadowDOM hydration y `setTimeout` internos de `100ms`). La brillante mitigación final fue interceptar la API del Web Component (`await el.evaluate(el => el.executeSearchAndOpen())`) logrando bypassar las latencias del front-end. 

## Architectural Insights
- **DRY & Decoupling**: Removimos cientos de líneas de legacy Subgrids en los E2E, limpiando la base de pruebas y orientándola fuertemente hacia la Nodal Extraction Architecture de Playwright (intercambiando selectores vulnerables).
- **Playwright DOM Racing**: Hemos validado que el framework es letalmente rápido frente al engine UI asíncrono. Inyectar eventos mediante los Web Components APIs localmente (DOM manipulation) provee certidumbre determinista en los End-to-End Tests.

## What's Next
El cierre formal de esta historia marca la finalización íntegra de la Épica E41. Todas las pantallas de selección y validación han sido modernizadas a nivel SPA puro, permitiendo interacciones offline/PWA de excelente responsividad sin reflows ni reloads innecesarios.
