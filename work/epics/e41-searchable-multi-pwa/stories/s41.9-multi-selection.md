# S41.9: Finalización del Flujo Multi-Selección

## Contexto y Estado Actual
Tras culminar los rigurosos trabajos en `S41.8` y asentar perfectamente la arquitectura base del `<tx-searchable>`, el comportamiento del componente está operando de manera impecable para cardinalidad **Singular (`multiple="false"` o sin atributo)**. Sin embargo, su promesa primaria es soportar el modelo Unificado (`multiple="true"`) y reemplazar exitosamente la lógica huérfana de `UI_Component_SearchableMulti`. El motor interno inicial (`if (this._isMultiple)`) está trazado, pero requiere calibración, testeo integral E2E, y alineación de la UI con el FormRenderer.

## Tareas Clave (Pendientes)

### 1. Refinamiento en el Motor de Render de "Cards / Chips"
- Asegurar que cuando el estado acumula un número N de selecciones (`this._selectedState instanceof Set`), el contenedor visual (Cards container inferior o inline chips) instancie y refleje inmediatamente las selecciones sin lag.
- Validar interacciones en los Checkboxes o botones de adición dentro del Modal Bottom Sheet o Dropdown Desktop, cuidando de no disparar dobles re-renders (Race conditions). 

### 2. Saneamiento del Dispatch hacia el API de Formulario
- Actualmente la lógica extrae la colección como Array (`Array.from(this._selectedState)`) utilizando el método estandarizado `getValidatedValue()`. Validar que `FormRenderer` asuma, procese, y empaquete este Array sin quebrarse bajo SCD-2 o lógicas de guardado relacionales de EntityGraph.

### 3. Límites Numéricos y Guardrails
- ¿Habrá un máximo de selección nativo inyectado en metadata (Ej: `max-items="5"`)? Establecer estas validaciones programáticas para deshabilitar las casillas si se rebasa el cap logístico de cardinalidad.

### 4. Pruebas E2E Multi-Flow (Playwright)
- Ejecutar casos Playwright probando específicamente:
  - Apertura del searchable multi.
  - Selección de N entidades (Ticks).
  - Presionar "Aceptar Selección".
  - Corroborar renderizado visual y eliminación de un ítem particular haciendo click en su 'X' nativa de la Card.

## Requisitos de Éxito
- Reemplazo absoluto 1:1 de `SearchableMulti`.
- Nulo acoplamiento. Un `<tx-searchable multiple="true">` arranca, gestiona Set interno y expone su interface en arreglo nativa limpia y performante.
