# User Story: S57.6 Optimización de Reactividad y Latencia de Relaciones en el Lienzo

## Connextra
**Como** Arquitecto de Taxonomía
**Quiero** que al abrir y editar relaciones en el lienzo, los selectores de relaciones carguen de manera instantánea (0ms) y reactiva
**Para** no experimentar esperas de 6 a 8 segundos ni bloqueos en los componentes que impidan vincular elementos.

## Acceptance Criteria

```gherkin
Feature: High Performance Relation Selectors in Canvas

  Scenario: Zero Latency Catalog Loading
    Given the user is on the taxonomy canvas
    And the data for parent/child entities (e.g. Portafolio) is already loaded in the client-side DataStore
    When the user opens the edit form drawer for an entity
    Then the relation dropdown lists should populate immediately (0ms) using the local DataStore cache
    And no redundant network requests to getInitialPayload should be sent for already loaded catalogs.

  Scenario: No Programmatic Locking during Hydration
    Given a form is being opened and hydrated programmatically
    When the initial values are assigned to the relation components
    Then the component should NOT activate the 6-second optimisticLock
    And the selector should remain fully interactive and responsive immediately.

  Scenario: Strict User-Initiated Change Alerting
    Given the user manually changes a hierarchical relationship
    When the selection changes due to direct user interaction
    Then the system should trigger the hierarchy change confirmation alert
    And activate the optimisticLock to prevent race conditions during sync.
```
