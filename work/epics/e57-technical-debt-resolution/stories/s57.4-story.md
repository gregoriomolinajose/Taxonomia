# User Story: S57.4 Refactorización Desacoplada de Web Components Relacionales

## Connextra
**Como** Arquitecto de Software
**Quiero** refactorizar la lógica de reactividad jerárquica y el ciclo de vida del componente web `TXSearchable`
**Para** garantizar que su comportamiento dependa puramente de un estado central (State-Driven) y configuraciones del esquema (Metadata-Driven), eliminando el acoplamiento fuerte y reduciendo la deuda técnica.

## Acceptance Criteria

```gherkin
Feature: State-Driven Relational Web Components

  Scenario: Governance Configuration via Schema
    Given the schema defines a relational entity with a governance exemption metadata flag
    When the form renderer evaluates the schema rules
    Then the system should determine the 'readonly' state purely from metadata rules without hardcoded entity names.

  Scenario: Form Trigger Events Configuration
    Given the schema defines trigger rules for the 'nivel_tipo' field
    When the user changes the value of the field
    Then the form should generically publish the specified events to the EventBus without hardcoded field awareness.

  Scenario: State-Driven TXSearchable Lifecycle
    Given the TXSearchable component is rendered
    When the parent application changes its placeholder or disabled state via standard HTML attributes
    Then the component should reactively re-render itself using standard 'attributeChangedCallback' without relying on an injected 'updateConfig' function.
```
