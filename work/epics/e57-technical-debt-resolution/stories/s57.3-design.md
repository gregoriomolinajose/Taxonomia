# Design: S57.3 Habilitar TXSearchable para Relaciones Jerárquicas

## Arquitectura del Cambio
El marco general de la interfaz ya estaba preparado para el componente `TXSearchable` tras la épica E41 (Unified Searchable Web Component).
Las relaciones jerárquicas hacia abajo (hijos/subordinados) ya estaban definidas con `uiComponent: "searchable_multi"`.

La deuda técnica residía en que las relaciones hacia arriba (padres) estaban configuradas como `uiComponent: "select_single"`, lo cual dependía del elemento select nativo que, si bien funciona, carece de las capacidades de filtrado avanzado, renderizado de avatares y carga diferida (lazy loading) que ofrece `TXSearchable`.

### Definición de UI Components
- **`select_single`**: Elemento heredado de Ionic `<ion-select>`. Limitado, no es apto para listas extensas o entidades de topología compleja.
- **`searchable_single`**: Componente orquestado mediante `UI_Factory.buildSearchableSingle` que delega la experiencia al Web Component nativo `<tx-searchable data-searchable-single>`.

### Esquema Afectado (`Schema_Engine.js`)
1. **Dominio:**
   - Campo: `relaciones_padre`
   - Transformación: `select_single` -> `searchable_single`
   - Efecto Colateral (Visual): Cambio de la paleta de colores de `secondary` a `primary` en la metadata de la entidad para solucionar el contraste pobre en el avatar UI.

2. **Capacidad:**
   - Campo: `id_dominio_padre`
   - Transformación: `select_single` -> `searchable_single`

La integridad de los datos (`Sys_Graph_Edges`) y del guardado no cambia, dado que el `UI_FormSubmitter` abstrae correctamente el valor del campo sin importar el componente visual subyacente.
