# S57.1 Design: Refactorización de Lookups y ECharts

## 1. What & Why
**Problema:** La aplicación aún depende de una hoja de Google Sheets antigua (`Relacion_Dominios`) para el cálculo de dependencias y el renderizado visual de jerarquías de dominios.
**Valor:** Migrar esta lectura a la nueva estructura universal (`Sys_Graph_Edges`) permite eliminar la hoja obsoleta, unificando la lógica de relaciones y reduciendo la deuda técnica.

## 2. Approach
- **Controller_Lookups.js (Modify):** Actualizar la obtención de datos en `getDominioOptions()`. En lugar de `Engine_DB.list('Relacion_Dominios')`, usará `Engine_DB.list('Sys_Graph_Edges')` filtrando apropiadamente para buscar aristas activas cuyo tipo de relación sea el pertinente para la jerarquía.
- **Math_Engine.html (Modify):** Actualizar `buildEChartsTreemapData()`. Sustituir la asignación `cacheObject['Relacion_Dominios']` por `cacheObject['Sys_Graph_Edges']`. Asegurar que los filtros para las aristas activas (como `tipo_relacion === PRIMARY_RELATION_TYPE`) coincidan con los datos de Sys_Graph_Edges.
- **Engine_DB.js (Modify):** Eliminar líneas como `_invalidateCache("Relacion_Dominios");`.
- **Schema_Engine.js (Modify):** Eliminar la definición duplicada u obsoleta del esquema de `Relacion_Dominios`.

## 3. Examples
**Controller_Lookups (Before):**
```javascript
const rawRelaciones = Engine_DB.list('Relacion_Dominios');
```

**Controller_Lookups (After):**
```javascript
const rawRelaciones = Engine_DB.list('Sys_Graph_Edges');
```
*(Se aplicará lógica de filtrado correspondiente a tipo_relacion para Dominios si es necesario, dado que Sys_Graph_Edges contiene todas las relaciones).*

## 4. Acceptance Criteria
- **MUST:** `getDominioOptions` retorna el flag `hasActiveParent` correctamente.
- **MUST:** La UI del mapa ECharts se pinta sin errores extrayendo datos de `Sys_Graph_Edges`.
- **MUST NOT:** Debe haber cero (0) ocurrencias del string "Relacion_Dominios" en los archivos procesados.
