# Retrospective S57.5 Cálculo Automático de Niveles Jerárquicos

## Outcomes
- **Status:** Done
- **Deliverables:**
  - Automated calculation of the `nivel_tipo` field via `Math_Engine.calculateHierarchyLevel`.
  - Removal of frontend restrictions that blocked parent selection based on pre-existing hierarchy.
  - Updated `SubgridState.client.js` and `UI_FormUtils.client.js` to dynamically allow free parent assignment for `Dominio` and `Capacidad`.

## Metrics
- Story duration: ~3 hours
- Complexity: Medium-High (State Synchronization)

## Learnings
- **Data over UI Control:** Trying to enforce mathematical state solely via UI dropdown restrictions leads to edge cases (like root nodes not being able to select parents). Moving the calculation to the backend submission pipeline simplifies the frontend.
- **Topological Rules:** The topological rule `strictLevelJumps` was overly restrictive for assignment, it's better used as an integrity check post-assignment or simplified completely for parent-selection contexts.

## Process Improvements
- When implementing hierarchy constraints, default to auto-calculating dependent fields in the persistence layer rather than forcing the user to manually sequence their actions.
