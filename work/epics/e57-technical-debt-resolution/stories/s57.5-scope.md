# Scope: S57.5 Cálculo Automático de Niveles Jerárquicos

## In Scope
- **Schema (`Schema_Engine.js`)**: 
  - Convertir el campo `nivel_tipo` a estado de solo lectura (`readonly: true`).
  - Eliminar los `triggers` añadidos en la S57.4, dado que la reactividad del formulario para desbloquear el padre ya no es necesaria.
- **Topología (`SubgridState.client.js` / Reglas)**:
  - Eliminar el bloqueo del componente `TXSearchable` para relaciones padre. El componente debe estar siempre habilitado en modo de edición.
- **Lógica de Persistencia (`UI_FormSubmitter.client.js` o interceptores de Backend)**:
  - Implementar la lógica para autocalcular el `nivel_tipo` al momento de guardar (Submit).
  - Si el usuario seleccionó un padre, buscar el nivel de ese padre e incrementarlo en 1.
  - Si el usuario no seleccionó ningún padre, asignar el nivel raíz por defecto.
- **Interfaz (Modo Lectura)**:
  - Ocultar dinámicamente el componente del padre si el formulario está en modo lectura y el dominio no tiene un padre asignado.

## Out of Scope
- Migración masiva de la base de datos para re-calcular los niveles de los dominios existentes (se asume que la data histórica ya es correcta).
- Eliminación física de la columna `nivel_tipo` en la base de datos (se seguirá usando internamente).

## Done Criteria
- El campo "Nivel Tipo" no permite edición manual.
- El campo "Dominio Padre" está desbloqueado desde el inicio.
- Al guardar un nuevo dominio subordinado, su nivel se guarda correctamente en base de datos.
- Un dominio raíz (sin padre) no muestra un componente "vacío/bloqueado" del padre cuando es consultado.
