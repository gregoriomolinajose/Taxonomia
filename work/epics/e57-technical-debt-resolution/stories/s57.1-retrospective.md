# Story Retrospective: S57.1 (Technical Debt Resolution)

## Summary
- **Story ID**: S57.1
- **Dates**: May 18, 2026
- **Estimated vs Actual Time**: 30m vs 45m

## What went well
- The migration to `Sys_Graph_Edges` was successfully finalized without impacting the tree rendering capabilities in `Math_Engine.html`.
- Strict backwards compatibility logic (`DOMINIO_HIJO` || `Militar_Directa`) ensured zero visual downtime during the transition.
- Dead code paths like `SheetMatrixIO` and `_updateGraphEdges` were successfully completely removed from `Engine_DB.js`, significantly improving codebase cleanliness.

## What to improve
- The system uses legacy scripts like `ETL_Runner.js` that also needed updating. A global project codebase search (`grep_search`) should always be the first step when deprecating global database sheets like `Relacion_Dominios`.
- We encountered an encoding bug in the `rai` CLI on Windows with checkmark characters (`\u2713`). We should ensure future CLI outputs handle Windows console `cp1252` encoding safely.

## Heutagogical Checkpoint
1. **What did you learn?**  
   We learned that architectural debt spans deeper than the immediate controllers; removing `Relacion_Dominios` required touching the data layer (`Engine_DB.js`), the UI visualization (`Math_Engine.html`), the schema definitions (`Schema_Engine.js`), and even dormant ETL scripts (`ETL_Runner.js`).
2. **What would you change about the process?**  
   Before deciding a database sheet is "unused", we should run a project-wide search (`grep`) across `src/` to identify all hardcoded references. We did this later in the cycle, but it should happen before starting modifications.
3. **Are there improvements for the framework?**  
   The `rai signal emit-calibration` CLI command threw a UnicodeEncodeError on Windows. The CLI should handle non-UTF8 standard outputs gracefully to avoid crashing when emitting checkmarks.
4. **What are you more capable of now?**  
   We are more capable of safely untangling legacy systems (SCD-2 graph implementations) and consolidating them under a central Single Source of Truth (`Sys_Graph_Edges`).

## Patterns
- *Added*: "Global schema references require global codebase scans, not just controller inspections."
- *Reinforced*: "SCD-2 DAG implementations must consolidate under a single graph edge registry to avoid matrix inconsistencies."

## Actions Taken
- Dead code (`SheetMatrixIO`, `_updateGraphEdges`) permanently deleted.
- Data structures updated to exclusively use `Sys_Graph_Edges`.
- Calibration signal attempted (failed due to CLI environment bug).
