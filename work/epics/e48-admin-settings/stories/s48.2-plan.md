# Implementation Plan S48.2: Dynamic SSO Domain Configuration

## 1. Sequence of Work

### Task 1: Backend Storage Endpoint
- **File:** `src/API_Admin.js`
- **Action:** Crear la función `API_Admin_SaveSecurityConfig(payload)` con validaciones contra `null` (como dictó el QR de la S48.1) y guardado en `PropertiesService.getScriptProperties().setProperty('APP_SECURITY_CONFIG', JSON.stringify(...))`.
- **Validation:** Syntax check & manual review.

### Task 2: Core Authorization Engine (API_Auth.js)
- **File:** `src/API_Auth.js`
- **Action:** Modificar `getUserIdentity()` para extraer `APP_SECURITY_CONFIG` al principio de la lógica de evaluación de SSO. Reemplazar la asignación dura de `domains` con el valor parseado de la base de datos de propiedades, conservando el fallback.
- **Validation:** Verificar resiliencia usando try-catch para prevenir un bloqueo general del sistema.

### Task 3: UI Frontend Settings
- **File:** `src/Schema_Studio_UI.html`
- **Action:** Añadir un nuevo bloque dentro de la pestaña "Branding" o adyacente (por ejemplo, renombrando "Branding" a "Ajustes Globales") con el título "Control de Acceso SSO". Agregar un `<input>` y un botón para guardar. 
- **Action:** Implementar `saveSecurityConfig` en `window.SchemaStudio` que analice la cadena (separada por comas) y la transforme en un array de strings válidos antes de mandarla al servidor.
- **Validation:** Validar el AST y CSS inline.

### Task 4: E2E Integration and Deployment
- **Action:** Ejecutar `npm run deploy:dev:auto`. Ingresar a DEV, cargar dominios nuevos en el Schema Studio, probar el guardado e intentar iniciar sesión simulando un correo válido e inválido.

## 2. Dependencies
- No existen dependencias externas. La lógica de `API_Auth.js` solo afectará si el usuario está en la rama SSO (AuthMode !== 'LOCAL').

## 3. Risks
- Tocar `API_Auth.js` es de alto riesgo: un error de sintaxis en `getUserIdentity()` puede provocar la pantalla en blanco o de rechazo para todos los usuarios.
- **Defensa:** El despliegue de desarrollo (DEV) servirá como red de seguridad para validar el acceso con el administrador actual antes de considerar moverlo a PROD.
