# S48.7: Schema-Driven Relational Provisioning

## User Story

**Como** desarrollador y arquitecto del sistema,
**Quiero** mover la configuración de los interceptores M:N (`_provisionRelationalStubs`) a los metadatos de las entidades en `Schema_Engine.js`,
**Para** eliminar por completo las funciones pasacables (wrappers vacíos) de `Business_Interceptors.js` y hacer que el motor ETL sea completamente dirigido por el esquema (Schema-Driven).

## Acceptance Criteria (Gherkin)

**Escenario 1: Provisión Relacional desde Esquema**
- **Dado** que el `Schema_Engine` define la propiedad `relationalProvisioning` para la entidad `Persona`, con arreglos de configuración para roles y equipos,
- **Cuando** el pipeline de ingesta procese un batch de Personas,
- **Entonces** el router de interceptores debe leer automáticamente el esquema e invocar el motor `_provisionRelationalStubs` con las propiedades correctas sin requerir una función wrapper codificada a mano.

**Escenario 2: Limpieza de Código**
- **Dado** que se ha implementado el router dinámico,
- **Cuando** se inspeccione `Business_Interceptors.js`,
- **Entonces** no deben existir las funciones `AutoProvisionRoles` ni `AutoProvisionEquipos`, reduciendo la superficie de código y previniendo errores futuros.
