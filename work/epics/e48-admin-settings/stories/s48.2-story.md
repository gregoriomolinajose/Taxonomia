# Story S48.2: Configuración Dinámica de Dominios SSO

## User Story
Como **Administrador de Sistema**
Quiero **poder parametrizar los dominios de correo permitidos (SSO)** desde el panel de control (Schema Studio)
Para **evitar tener que desplegar código nuevo cada vez que necesito autorizar o revocar acceso a un dominio específico (ej. consultoras externas)**

## Acceptance Criteria
1. El panel de administración (pestaña Branding u otra dedicada a Seguridad/Acceso) debe permitir ver y editar los dominios permitidos actuales.
2. Los dominios deben guardarse en `PropertiesService` (ej. `APP_SECURITY_CONFIG`).
3. El motor de seguridad (`API_Auth.js`) debe leer dinámicamente estos dominios y usarlos como única fuente de verdad para la autorización en modo SSO.
4. Si la propiedad de la base de datos está vacía o corrupta, el sistema debe usar un fallback seguro (`ENV_CONFIG.ALLOWED_DOMAINS` o predefinido corporativo).

## Specification by Example
- **Scenario:** El administrador autoriza un nuevo dominio de agencia externa.
  - **Given** el sistema solo permite `@coppel.com` y `@bancoppel.com`
  - **When** el administrador añade `@agencia.com` en el panel de control y guarda
  - **Then** el sistema persiste la nueva lista de dominios en PropertiesService.
  - **And** el usuario `consultor@agencia.com` intenta acceder y el `API_Auth` le concede el acceso basado en la nueva configuración global en caliente.
