# Story Plan: S48.4 - Autorización OAuth2 (3-Legged) para Workspace Multi-Dominio

## Story Details
- **Story**: S48.4
- **Epic**: E48
- **Complexity**: M/L (5-8 SP)
- **Design Ref**: `work/epics/e48-admin-settings/stories/s48.4-design.md`

## Task Breakdown

### Task 1: Inyección de Dependencia OAuth2
- **Description**: Actualizar el manifiesto de Apps Script para incluir la librería oficial de OAuth2.
- **Files Affected**: `src/appsscript.json`
- **AC**: La librería `1B7FSrk5Zi6L1rSxxTDgDEUsPzlukDsi4KGuTMorsTQHhGBzBkMun4iDF` debe estar definida en el bloque `dependencies.libraries`.
- **Size**: XS
- **Verification**: `clasp push` debe ser exitoso sin errores de dependencias.

### Task 2: Motor Backend OAuth2 (`Auth_OAuth2.js`)
- **Description**: Implementar la maquinaria núcleo para el flujo 3-Legged OAuth2. Esto incluye: 
  - La construcción del servicio (`OAuth2.createService`).
  - La función para obtener la URL de login (`Auth_GetWorkspaceAuthUrl()`).
  - La función del callback (`Auth_HandleOAuthCallback(request)`), la cual intercambiará el código y llamará a `admin.directory.user.readonly` o `userinfo` para identificar de qué dominio proviene el token antes de guardarlo en `PropertiesService`.
  - La función de consumo (`Auth_GetTokenForDomain(domain)`).
- **Files Affected**: `src/Auth_OAuth2.js` (Nuevo)
- **AC**: AC2. El sistema debe gestionar el token y almacenarlo por dominio.
- **Size**: M
- **Verification**: Despliegue en Dev y validación mediante `DataAPI` de generación de la URL de autorización.

### Task 3: Enrutador HTTP de Callback (`Code.js`)
- **Description**: Modificar el punto de entrada de la aplicación (`doGet`) para que actúe como Redirect URI del flujo OAuth. Si la solicitud contiene `e.parameter.code`, delegarla a `Auth_HandleOAuthCallback`.
- **Files Affected**: `src/Code.js`
- **AC**: AC2. El servidor debe interceptar correctamente el redireccionamiento de Google.
- **Size**: S
- **Verification**: Ejecutar `doGet` simulando un objeto de evento `{ parameter: { code: 'test' } }` en el entorno Apps Script.

### Task 4: UI de Configuración de Dominios (`Schema_Studio_UI.html` y `API_Admin.js`)
- **Description**: 
  - Habilitar el botón "Conectar Dominio" en la UI, el cual abrirá un popup/nueva pestaña llamando a `Auth_GetWorkspaceAuthUrl()`.
  - Crear un endpoint en `API_Admin.js` (`API_Admin_GetConnectedDomains`) que liste los dominios autorizados leyendo `PropertiesService`.
  - Pintar la lista de dominios en la vista de *Workspace Sync*.
- **Files Affected**: `src/Schema_Studio_UI.html`, `src/API_Admin.js`
- **AC**: AC1. El administrador debe poder iniciar el flujo interactivo y ver el estado de sus conexiones.
- **Size**: M
- **Verification**: Interacción visual completa en la UI de *Schema Studio*.

### Task 5: Interceptación Activa de Consultas (`Engine_Workspace.js`)
- **Description**: Refactorizar `resolverDirectorioWorkspace`. Si el `queryEmail` es de un dominio conectado (existe token), utilizar `UrlFetchApp` enviando el Bearer token al endpoint REST de Directory API (`https://admin.googleapis.com/admin/directory/v1/users/`). En caso de fallo (401), realizar fallback degradado devolviendo error controlado.
- **Files Affected**: `src/Engine_Workspace.js`
- **AC**: AC3. Consultas a dominios secundarios deben resolver exitosamente usando la API REST + OAuth2 Token.
- **Size**: M
- **Verification**: Creación manual de un registro en `Persona` utilizando un email de un dominio secundario conectado para confirmar la hidratación automática de DTOs.

### Task 6: Integración Final y Pruebas E2E (Manual)
- **Description**: Ejecutar el ciclo completo desde la UI. Conectar un dominio de prueba, autorizar el acceso y posteriormente validar que el autocompletado en el formulario de la Persona resuelve nombres y cargos.
- **Files Affected**: N/A
- **AC**: Todos los AC listados.
- **Size**: S
- **Verification**: Demostración funcional completa del flujo 3-legged en DEV.
