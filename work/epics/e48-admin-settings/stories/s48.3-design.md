# Design S48.3: Workspace Sync Configuration

## 1. Context
La aplicación se apoya en Google Workspace (`AdminDirectory`) para enriquecer los perfiles de los usuarios en la creación (Avatar, Puesto, Área). Sin embargo, este servicio incurre en consumo de cuotas, es frágil si el usuario activo no tiene privilegios, y no soporta múltiples dominios nativamente sin delegación. Necesitamos una interfaz que permita apagar el motor de búsqueda en caso de emergencia/testing y configurar cuentas administrativas delegadas para futuras implementaciones de multi-tenant.

## 2. Architecture

### 2.1 Backend (Storage & Security)
- Reutilizaremos el endpoint genérico `API_Admin_SaveGlobalConfig` introducido en la S48.2. Simplemente añadiremos `APP_WORKSPACE_CONFIG` a la *whitelist* de claves permitidas.
- **Estructura del Payload (`APP_WORKSPACE_CONFIG`):**
  ```json
  {
    "syncEnabled": true,
    "domainMappings": [
      { "domain": "@coppel.com", "adminEmail": "gregorio@coppel.com" },
      { "domain": "@bancoppel.com", "adminEmail": "juan@bancoppel.com" }
    ]
  }
  ```

### 2.2 Core Logic (`Engine_Workspace.js`)
- **Master Toggle Interception:** En `buscarUsuario(queryEmail)`, el sistema leerá `PropertiesService` buscando `APP_WORKSPACE_CONFIG`.
- Si existe y `syncEnabled === false`, la función retornará un DTO nulo/vacío inmediatamente. Esto "apagará" la ingesta automática de datos sin romper la creación de la `Persona` (el usuario se creará, pero con los campos de Workspace vacíos).
- **Delegated Domains:** La lectura de correos delegados será implementada en la estructura para uso futuro. Por ahora, si `syncEnabled === true`, el sistema seguirá usando `AdminDirectory` con el usuario activo.

### 2.3 Frontend (`Schema_Studio_UI.html`)
- **Pestaña Nueva:** Sustituir el actual `<button class="ss-tab">` "Sincronizar Workspace" por una pestaña real.
- **Componentes Visuales:**
  1. **Master Toggle:** Un *switch/checkbox* rotulado "Habilitar consultas de directorio (Workspace Sync)".
  2. **Configuración de Dominios:** Una interfaz sencilla (dos `inputs` y un botón "Añadir") para crear la lista de mapeo (Dominio -> Correo), renderizada dinámicamente en el DOM.
  3. **Botón Manual:** El botón original que dispara `Job_WorkspaceSync` será movido al fondo de esta pestaña, bajo el rótulo "Ejecución Manual".

## 3. Data Flow
1. **Administración:** Super Admin ingresa al Schema Studio -> Pestaña "Workspace Sync".
2. **Edición:** El Admin apaga el toggle y añade dos mapeos de dominio. Hace clic en "Guardar Configuración".
3. **Escritura:** JS empaqueta el objeto JSON y llama `google.script.run.API_Admin_SaveGlobalConfig('APP_WORKSPACE_CONFIG', payload)`.
4. **Ejecución (Provisioning):** Un usuario normal entra al sistema por primera vez -> `Business_Interceptors` intenta crear su Persona -> Llama a `Engine_Workspace.buscarUsuario()`.
5. **Interceptación:** `Engine_Workspace` nota que `syncEnabled` es `false`, devuelve null. La Persona se crea exitosamente pero sin avatar ni puesto auto-llenado.

## 4. Alternative Analyzed
- **¿Manejar delegación de cuentas en Google Sheets?** Descartado. Estas configuraciones dictan el comportamiento core del sistema perimetral; usar Sheets introduce latencia masiva. `PropertiesService` es más veloz y apropiado.
