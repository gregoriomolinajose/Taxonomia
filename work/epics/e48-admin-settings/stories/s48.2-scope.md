# Scope S48.2: Dynamic SSO Domain Configuration

## In Scope
- Creación de interfaz en Schema Studio (`Schema_Studio_UI.html`) para editar la lista de dominios autorizados (ej. campos de texto separados por comas).
- Creación de endpoint en el backend (`API_Admin.js`) para validar y guardar `APP_SECURITY_CONFIG` en `PropertiesService`.
- Refactorización de `API_Auth.getUserIdentity()` para extraer la lista de dominios dinámicamente desde `PropertiesService` en lugar de variables harcodeadas.
- Actualización de `Code.js` (si es necesario) o centralización de la inyección para asegurar coherencia en el flujo de SSO.

## Out of Scope
- Modificación del flujo de Autenticación Local (`LOCAL`). Solo aplica para `AuthMode === 'SSO'`.
- Implementación de Single Sign-On OIDC real. Se asume que el sistema subyacente sigue usando la identidad activa de la sesión de Google (`Session.getActiveUser().getEmail()`).
- Creación de perfiles ABAC a nivel de dominio. El control de dominios sigue siendo una compuerta binaria de acceso (Bouncer).

## Done Criteria
- [ ] La interfaz de usuario permite ingresar dominios en formato CSV o lista, limpiando espacios y minúsculas.
- [ ] El backend persiste correctamente la lista de dominios.
- [ ] Las validaciones en `API_Auth.js` respetan los valores persistidos sin necesidad de un redespliegue de Apps Script.
- [ ] Un fallback seguro existe en caso de corrupción de la variable en base de datos.
