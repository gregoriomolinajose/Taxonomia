# Retrospective S48.2: Dynamic SSO Domain Configuration

## 1. What Went Well
- **Arquitectura Optimizada:** En lugar de replicar el mismo patrón de guardado para la configuración visual y de seguridad, identificamos mediante *Architecture Review* la necesidad de abstraer un endpoint genérico (`API_Admin_SaveGlobalConfig`), permitiendo futuras extensiones de configuración global con mínimo código.
- **Detección Temprana (QR):** Identificamos de manera crítica que `JSON.parse` podía lanzar excepciones al lidiar con un `APP_SECURITY_CONFIG` corrupto, lo que habría saltado el fallback predefinido y llevado a una falla sistémica. La intervención temprana separó el manejo de errores atómicamente.
- **Robustez en la Entrada de Usuario:** La interfaz grafica previene espacios extra y conversiones indeseadas de caja, garantizando que el backend reciba dominios completamente limpios listos para validación.

## 2. Challenges & Workarounds
- **Riesgo Operacional (SSO):** Tocar `API_Auth.js` siempre representa un riesgo severo, dado que es la puerta central del sistema en entornos productivos. Mitigamos este riesgo priorizando fallbacks deterministas; si todas las configuraciones dinámicas fallan, el sistema siempre retornará al entorno precompilado por seguridad.

## 3. Learnings
- **Whitelist Perimetral:** Usar el chequeo contra arreglos definidos (como `VALID_KEYS`) al guardar datos en `PropertiesService` es una forma eficiente de prevenir que usuarios expongan o sobre-escriban variables nativas y de entorno, protegiendo las credenciales.
