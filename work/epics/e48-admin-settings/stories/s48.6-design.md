# S48.6: Refactorización DRY de Interceptores M:N (Design)

## 1. What & Why
- **Problem**: La lógica de `AutoProvisionRoles` y `AutoProvisionEquipos` (relaciones `M:N`) es imperativa y está duplicada en un 95%. Esto aumenta la carga cognitiva y propicia la inyección de bugs cuando el código evoluciona. 
- **Value**: Extraer un nuevo motor generalizado `_provisionRelationalStubs(config)` elimina ~140 líneas de código duplicado, asegura consistencia criptográfica (`RELA-` + 8 hexadecimals) y simplifica drásticamente la incorporación de futuros campos de relaciones múltiples al motor ETL.

## 2. Approach
1.  **Crear el Motor `_provisionRelationalStubs(config)`**:
    -   Se implementará dentro del IFFE `Business_Interceptors`.
    -   Recibirá una interfaz de configuración análoga (pero simplificada) a `_provisionStubs`:
        -   `items`: Array de objetos en ingesta.
        -   `field`: Nombre del campo de origen (ej. `'roles_asignados'`).
        -   `targetEntity`: Entidad destino para buscar/crear stubs (ej. `'Rol'`).
        -   `idField`: Llave primaria de la entidad destino (ej. `'id_rol'`).
        -   `edgeType`: Nombre de la arista topológica (ej. `'PERSONA_ROL'`).
        -   `stubPrefix`: Prefijo para el ID temporal del nodo (ej. `'ROL-'`).
    -   Encapsulará la lógica de búsqueda, iteración de comas (`split(',')`), creación de registros *Stub* en memoria y la generación atómica del batch `Sys_Graph_Edges`.

2.  **Refactorizar los Interceptores Existentes**:
    -   `AutoProvisionRoles` se re-escribirá como un pasacables (wrapper) de 5 líneas hacia `_provisionRelationalStubs`.
    -   `AutoProvisionEquipos` se re-escribirá como un pasacables de 5 líneas hacia `_provisionRelationalStubs`.

3.  **Mantener Retrocompatibilidad Total**:
    -   La resolución UUID se mantendrá utilizando `Math.floor(Math.random() * 16).toString(16).toUpperCase()` de 8 caracteres para los prefijos `RELA-`.
    -   El borrado de los campos llanos (`delete p[field]`) se mantendrá intacto para proteger a la base de datos de mutaciones relacionales incorrectas.

## 3. Concrete Examples

### Interfaz Propuesta para el Wrapper
```javascript
AutoProvisionRoles: function(entityName, items) {
    if (entityName !== 'Persona') return;
    _provisionRelationalStubs({
        items: items,
        field: 'roles_asignados',
        targetEntity: 'Rol',
        idField: 'id_rol',
        edgeType: 'PERSONA_ROL',
        stubPrefix: 'ROL-'
    });
}
```

## 4. Acceptance Criteria
-   [x] El código duplicado se ha consolidado en un solo algoritmo `_provisionRelationalStubs`.
-   [x] Los UUIDs para aristas conservan la convención estricta (`RELA-[8 HEX]`).
-   [x] La suite general (carga manual o backend) funciona idéntico a nivel de caja negra.
