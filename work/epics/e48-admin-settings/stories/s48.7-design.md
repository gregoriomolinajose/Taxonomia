# S48.7: Schema-Driven Relational Provisioning (Design)

## 1. What & Why
- **Problem**: En la refactorización anterior (S48.6), logramos abstraer la lógica en `_provisionRelationalStubs`, pero mantuvimos funciones de envoltura ("wrappers") vacías (`AutoProvisionRoles`, `AutoProvisionEquipos`) en `Business_Interceptors.js`. Esto añade una capa de indirección redundante e infla el código con código boilerplate.
- **Value**: Siguiendo el principio de "Configuración sobre Código", mover las definiciones a la metadata del esquema (Schema-Driven) descentraliza la lógica. Para agregar una nueva relación M:N al motor ETL en el futuro (ej. "Habilidades"), ya no habrá que tocar el código fuente de los interceptores, bastará con declararlo en el esquema.

## 2. Approach
1. **Modificar el Esquema de Persona (`Schema_Engine.js`)**:
   - Eliminar `AutoProvisionRoles` y `AutoProvisionEquipos` de la matriz `mutationInterceptors`.
   - Añadir una nueva propiedad a nivel de metadatos de entidad: `relationalProvisioners: [...]`. Esta contendrá los arrays de objetos de configuración (idénticos a los definidos en los wrappers antiguos).

2. **Refactorizar el Enrutador (`Business_Interceptors.apply()`)**:
   - Ampliar la función `apply` para leer `schema.relationalProvisioners`.
   - Iterar sobre esta configuración, inyectando directamente `_provisionRelationalStubs(entityName, items, config)`.

3. **Limpieza (`Business_Interceptors.js`)**:
   - Borrar definitivamente `AutoProvisionRoles` y `AutoProvisionEquipos`.

## 3. Concrete Examples

**Configuración propuesta en `Schema_Engine.js` (Persona):**
```javascript
{
    // ... otros metadatos
    relationalProvisioners: [
        {
            field: 'roles_asignados',
            targetEntity: 'Rol',
            idField: 'id_rol',
            edgeType: 'PERSONA_ROL',
            stubPrefix: 'ROL-',
            extraStubFields: { nivel: "Nivel Base" }
        },
        {
            field: 'equipo',
            targetEntity: 'Equipo',
            idField: 'id_equipo',
            edgeType: 'PERSONA_EQUIPO',
            stubPrefix: 'EQUI-'
        }
    ]
}
```

**Nuevo Ruteador en `Business_Interceptors.js`:**
```javascript
function apply(entityName, items) {
    if (!items || items.length === 0) return;
    const schema = getAppSchema(entityName);
    
    // 1. Mutation Interceptors Clásicos
    if (schema.mutationInterceptors) { ... }
    
    // 2. Relational Provisioners (NUEVO)
    if (schema.relationalProvisioners && Array.isArray(schema.relationalProvisioners)) {
        schema.relationalProvisioners.forEach(config => {
            _provisionRelationalStubs(entityName, items, config);
        });
    }
}
```

## 4. Acceptance Criteria
- [x] La entidad Persona declara sus dependencias M:N directamente en su esquema, no en código.
- [x] El ruteador `apply` procesa `relationalProvisioners`.
- [x] El archivo `Business_Interceptors.js` no contiene ya referencias hardcodeadas a "roles" o "equipos".
