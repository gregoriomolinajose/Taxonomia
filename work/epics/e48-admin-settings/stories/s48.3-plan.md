# Implementation Plan S48.3: Workspace Sync Configuration

## 1. Sequence of Work

### Task 1: Backend Extension & Security Whitelist
- **File:** `src/API_Admin.js`
- **Action:** Agregar la constante `'APP_WORKSPACE_CONFIG'` a la variable `VALID_KEYS` dentro de `API_Admin_SaveGlobalConfig`. Esto permite al frontend escribir la configuración de forma segura.

### Task 2: Core Engine Interception (Master Toggle)
- **File:** `src/Engine_Workspace.js`
- **Action:** En la cabecera de `buscarUsuario`, extraer la variable `APP_WORKSPACE_CONFIG`. Implementar un "early return" silencioso (retornando `null`) si `syncEnabled` viene explicitamente como `false`.
- **Validation:** Verificar que las fallas de parseo asuman que el toggle está `true` (Fail-Open para la sincro por defecto).

### Task 3: UI Layout & Dynamic Mapping
- **File:** `src/Schema_Studio_UI.html`
- **Action:** 
  1. Modificar el menú lateral para que "Workspace Sync" sea un `data-tab="workspace"`.
  2. Implementar `renderWorkspaceTab(container)`.
  3. Crear lógica de JavaScript en memoria (`_tempDomainMappings`) para añadir y borrar filas de la tabla de dominios antes de guardar.
  4. Mover el botón existente de "Forzar Sincronización Manual" hacia esta nueva vista.

### Task 4: UI Controller Integration
- **File:** `src/Schema_Studio_UI.html`
- **Action:** Implementar `window.SchemaStudio.saveWorkspaceConfig()`, que toma el valor del checkbox maestro y el array `_tempDomainMappings`, lo valida, y dispara `API_Admin_SaveGlobalConfig`.
- **Validation:** Asegurarse de que `google.script.run` notifique el éxito o error adecuadamente.

### Task 5: End-to-End Validation (Dev Deployment)
- **Action:** Correr `npm run deploy:dev:auto`. Ingresar como admin, apagar el toggle. Forzar una creación manual de usuario o llamar a la sincronización para corroborar que la llamada al Directorio es omitida con éxito.

## 2. Dependencies
- Depende completamente de `API_Admin_SaveGlobalConfig` introducido en la S48.2.

## 3. Risks & Mitigations
- **Riesgo:** Si la lectura de `APP_WORKSPACE_CONFIG` en `Engine_Workspace.js` es lenta, retrasará cada inicio de sesión de nuevos usuarios.
- **Defensa:** `PropertiesService` es extremadamente rápido. Sin embargo, para no sobrecargar, `Engine_Workspace` solo se ejecuta durante el aprovisionamiento inicial de un usuario, no en cada recarga de página (A diferencia de `API_Auth`).
