# Retrospective S40.3: Integridad de Carga Masiva (ETL Hub Tests)

## Summary
- **Story IDs**: S40.3
- **Dates**: Abril 16, 2026
- **Estimated Time**: 120 minutes
- **Actual Time**: 160 minutes

## What went well
La integración de test aislados en Playwright que impactan la aplicación en vivo contra GAS evadió exitosamente los bloqueos de abstracción. El uso de validaciones RegExp y enlazamiento `google.script.run` nativo forjan una batería de resiliencia End-to-End sumamente valiosa para la base de datos Google Sheets.

## What to improve
Las invocaciones de limpieza (Teardown) estaban sofocando de manera predeterminada (`catch(() => null)`) los errores de red y firma. La falta de verbosidad frente a errores en operaciones transaccionales de test ocultó un bug donde no enviábamos correctamente los parámetros a la API.

## Heutagogical Checkpoint
1. **What did you learn?** 
   Aprendí que envolver rutinas E2E asíncronas hacia Google Apps Script (e.g. `window.DataAPI.call`) demanda pasar atributos puramente posicionales (como se reescribió en el BugFix del Teardown y los Reads) pues `google.script` omite transparentemente los objetos monolíticos incompatibles con las funciones backend expuestas explícitamente. Las omisiones en Catch silencian los errores que el Framework de Tests no puede auditar si se usan en hooks de `afterAll`.
   
2. **What would you change about the process?**
   Cambiaría irrevocablemente nuestra tolerancia al silenciamiento en test teardowns. En lugar de ignorar un error para "evitar que rompa la suite", todo `catch` de limpieza debe documentarse a través de `console.warn(...)`. 

3. **Are there improvements for the framework?**
   Para la heurística de `/rai-quality-review`: expandir formalmente la detección de `Silenced Errors` o "Swallowed exceptions" explícitamente para bloques de pruebas Teardown / `afterAll`.

4. **What are you more capable of now?**
   El sistema es ahora completamente capaz de probar interacciones de concurrencia optimista (OCC) y auto-healing subiendo lotes masivos de manera transaccional e idempotente sin destruir los recuentos ni impactar ambientes de Dev.

## Improvements applied
- **Clean Teardown Feedback**: Removido el patrón generalizado de `catch(() => null);` por un `catch(e => console.warn(e));` en sentencias sueltas (`etl-mass-upload.spec.js`), implementado exitosamente.

## Patterns Added/Reinforced
- Added: `suppressed-teardown-avoidance` (Process: Prevent silent catches in E2E Teardown blocks).
