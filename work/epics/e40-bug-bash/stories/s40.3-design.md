# Story Design S40.3: Integridad de Carga Masiva (ETL Hub Tests)

## 1. Contexto

Durante la estabilización de los pipelines de inyección masiva de datos y tras implementar exitosamente las correcciones funcionales base de UUID Corto, Formato Lexical, Conversión de Fechas (ISO 8601) y Versionamiento de Concurrencia Optimista (OCC); se identifica un vacío de Cobertura End-to-End. Si algún desarrollador en el futuro muta `Adapter_Sheets.upsertBatch` o `DataEngine_ETL._csvToJson`, el sistema podría corromper la Taxonomía estricta de manera silenciosa (regresión).

## 2. Objetivos y Metas

- **Integridad Semántica:** Fabricar una test-suite de aserción transaccional usando Playwright mediante llamadas de red directas (`window.DataAPI.call`) evadiendo cuellos de botella de UI.
- **Inmutabilidad (Resiliencia):** Configurar y limpiar la DB satélite nativamente a través del paso Teardown en cada ejecución (`DataAPI.call('delete')`) para NO contaminar el ambiente Dev.
- **Fail-Fast de Contratos:** Proteger las 4 reglas del ETL recién restablecidas.

## 3. Comportamiento Esperado

- **Test 1 - Fabricación de IDs:** Generación UUID en formato `[PREFIJO]-[ALFA5]` y de `lexical_id`.
- **Test 2 - Date Parsing:** Recepción de strings crudas DD/MM/YYYY o YYYY-MM-DD y aserción de que la BD expulsa UTC `[T00:00:00.000Z]`.
- **Test 3 - Concurrencia OCC:** Inserción doble consecutiva del mismo Payload sobrecargando la base para certificar `_version` autoincrementado por Google Sheets.

## 4. Criterios de Aceptación (DoD)

- [ ] Existe el archivo suite `__tests__/e2e/etl-mass-upload.spec.js`.
- [ ] La suite pasa 100% el script nativo de Test (`npx playwright test`).
- [ ] Utiliza estrictamente la envoltura `runWithCleanTeardown` u homólogo del `setup.js` para destruir registros residuales.
- [ ] No utiliza Mocking de Red (Intercept), sino que viaja a App Script y valida el I/O real con Google Sheets (Test de Integración DB).
