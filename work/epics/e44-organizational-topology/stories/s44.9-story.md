# S44.9: Mapeo Automático de Ingesta (Cargo Workspace Interceptor)

## User Story

**As a** System Architect / Integrator
**I want** an automatic ingestion mapping engine during the Webhook / Bulk Upload phase
**so that** any incoming raw string representing an external Workspace ID (e.g. `411`) is automatically resolved via the Cargo dictionary entity to its internal `id_cargo` topological equivalent without manual intervention.

## Acceptance Criteria

```gherkin
Feature: Cargo Ingestion Interception

  Scenario: Bulk Upload Pipeline maps External ID
    Given a raw JSON payload containing `cargo: "411"`
    When the ETL engine or Ingesta Onload hook attempts validation
    Then it triggers a pre-insert matcher lookup for `Cargo` mapped to `id_externo_workspace == 411`
    And finding `CARG-XYZ`, it morphs the payload property `id_cargo: "CARG-XYZ"` before saving
    And if mapping fails (not found), it logs a Missing Mapping flag or registers the text as a placeholder.
```

## Specification By Example

- Cuando el trigger del importador CSV o Hub lee el campo de Workspace puro, la función middleware `hook_ETL_Mapping` es invocada.
- Este matcher utilizará las utilidades de cache para O(1) Lookup: `{ "411": "CARG-..." }`.
