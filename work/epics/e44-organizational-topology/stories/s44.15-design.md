# S44.15: System Design

## 1. JIT Cache Refresh Architecture (Silent Rehydration)

El componente principal del diseño aborda la experiencia del usuario (UX) pos-ejecución masiva. En lugar de vaciar la memoria RAM (`window.DataStore.invalidate('Persona')`) lo cual causaría la renderización de un estado vacío hasta que el usuario recargue:

* **Trigger**: El evento resolutivo final de `window.SchemaStudio.triggerWsSync()`.
* **Proceso**:
  - Manipulación optimista del botón a estado `Refrescando memoria local...` para evitar múltiples clics.
  - Orquestación mediante un `Promise.all` que despacha simultáneamente `DataAPI.call('getInitialPayload', ...)` para las entidades mutadas (Persona, Cargo).
  - Reemplazo atómico de la data con `window.DataStore.set()`.
* **Broadcast**: Ejecución final de `window.AppEventBus.publish('DATA::UPDATED')`, indicando a `UI_DataView` y `UI_Form` que el contenido del origen base cambió, provocando que ejecuten un repintado de las vistas actuales si están montadas.

## 2. Ingestion Deduplication Matrix

Para la corrección de fallos a nivel backend (ETL), la arquitectura se actualiza de la siguiente manera:

* **Lectura Base**: `Engine_DB.list('Cargo', 'objects')`. En la arquitectura de GAS/Firebase, la lectura completa (`list`) en modo `objects` garantiza que se devuelva una colección sobre la cual se puede iterar para crear un Mapa Invertido en O(1) (`[cargoName.toLowerCase()] = cargoId`).
* **Saneamiento Determinista**: Cada vez que se crea un "Cargo Virtual" proveniente de un título en Google Workspace (`GeneradorId.crear('CARG')`), el ID alfanumérico generado aleatoriamente se convierte a mayúsculas usando `.toUpperCase()`. Esto cumple con el estándar de "Pointers" utilizado en la resolución relacional del motor transaccional.

## 3. UI Asset Consistency

Para resolver el problema de renderizado originado por limpiezas extremas de código:
* Los archivos HTML puros con tags `<style>` deben coexistir de manera controlada y estar especificados en el entorno, evitando scripts que compilen o "purguen" activos CSS nativos indispensables como `CSS_App.html`.
* **Semantic Tokens**: El icono `id-card-outline` y color `tertiary` se enlazan explícitamente en el mapa metadata de `Schema_Engine.js` dentro del catálogo `Cargo`.
