# S44.17: Ingesta JIT de Workspace (ETL)

## User Story

**As a** system administrator or data owner
**I want** the bulk ETL ingestion process to automatically trigger Workspace Sync logic for new or updated 'Persona' records
**So that** their 'Cargo' and topological relations (Sys_Graph_Edges) are automatically resolved and linked without requiring a secondary manual Workspace Sync step.

## Acceptance Criteria

```gherkin
Feature: Auto-Provisionamiento de Cargo durante Ingesta de Personas

  Scenario: Ingesta Masiva de Personas
    Given a bulk ETL payload of 'Persona' records with corporate emails
    When the ETL engine processes each row
    Then it must fetch the user's title from Google Workspace using their email
    And it must locate or create the 'Cargo' entity
    And it must automatically forge the Parent-Child edge in 'Sys_Graph_Edges'
    And the UI must show the complete relationship upon successful ingestion.
```

## Context

Actualmente, cuando se cargan Personas de forma masiva mediante el UI_ETL_Modal, el sistema inserta los registros correctamente. Sin embargo, para que se establezca su `Cargo` y la relación jerárquica en el grafo, el usuario se ve forzado a ejecutar posteriormente un "Sync Workspace" manual.

Se busca unificar la experiencia para que el motor ETL mande a llamar internamente a `Job_WorkspaceSync` (o a su lógica subyacente `resolverDirectorioWorkspace`) por cada correo ingerido, forjando las dependencias topológicas *al vuelo* y devolviéndolas ya hidratadas a la interfaz visual en un solo click.
