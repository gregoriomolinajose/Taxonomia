  - *Contexto:* El bloque `try/catch` envuelve `Engine_ETL.hydrateAndDeduplicate`. Si la rutina ETL falla o arroja un error (ej. OOM, timeout), el error se captura, se loguea como un `console.warn` y el flujo continúa.
  - *Por qué importa:* Al continuar, la base de datos de Google Apps Script guardará el `payload` crudo. Si el cargo venía como string ("Desarrollador Junior"), se guardará como ID y corromperá el grafo (el mismo bug que se pretendía solucionar).
  - *Sugerencia:* Para operaciones CUD unitarias de UI, en lugar de un *Fail-Open*, se recomienda un *Fail-Closed*. Deberías lanzar explícitamente el error (`throw e`) si falla el provisionamiento crítico de llaves foráneas, forzando al usuario a reintentar y protegiendo la integridad del motor de base de datos. (Puede aplicarse en la historia S44.14).
