# Diseño de Solución: Deduplicación y Manejo de Errores en ETL Masivo

## 1. Problema de Integración
El ciclo de vida de los datos durante la carga masiva (ETL) sufre de "falsos positivos" de éxito. El frontend asume éxito por defecto si la respuesta no coincide con su estructura de validación, y el backend utiliza mecanismos de seguridad transaccional (OCC) que están diseñados para interacciones singulares, resultando letales para cargas masivas por lotes. Adicionalmente, el puente de retroalimentación visual (Writeback) carece del proxy global de RPC, cortando el flujo final de la operación.

## 2. Arquitectura de Mitigación

### 2.1 Supresión Controlada de Excepciones OCC
El `Adapter_Sheets.upsertBatch` es el encargado final de insertar. Cuando evalúa la unicidad cruzando el índice, la bandera `payload._isDuplicateMatch` disparará un error `ERROR_CONCURRENCY`. En vez de permitir que este error rompa el hilo global de Apps Script, se envuelve el bloque en un `try-catch` aislado por fila. El bloque catch capturará el error, verificará si es de concurrencia y empujará un objeto al arreglo de resultados con la propiedad `status: 'duplicate'`.

### 2.2 Desanidación de Respuesta en Frontend
La capa `Controller_Action.js` fue refactorizada recientemente para devolver un objeto wrapper: `{ status: 'success', insertedCount: N, details: [...] }`. El cliente `DataEngine_ETL.client.js` ignora este patrón. Se actualizará la lógica del cliente para evaluar de manera defensiva todas las posibilidades de transporte de la API (`Array.isArray(res)`, `res.details`, `res.data.details`).

### 2.3 Exposición RPC de Feedback
La interfaz llama a `window.DataAPI.call('etl_writeback_feedback')`. El script `DataAPI` asume que cada endpoint de Controlador es una función explícitamente declarada en la capa raíz (Google Apps Script Global Scope). Se requiere inyectar la función `etl_writeback_feedback(entityName, payload)` dentro de `Controller_Action.js` como un proxy hacia el enrutador universal.

## 3. Componentes Modificados
- `src/Schema_Engine.js`: Activación de banderas de unicidad para forzar colisiones.
- `src/Adapter_Sheets.js`: Contención de `ERROR_CONCURRENCY`.
- `src/DataEngine_ETL.client.js`: Lógica de extracción de `detailsArray` para la métrica de progreso.
- `src/Controller_Action.js`: Declaración explícita del endpoint `etl_writeback_feedback`.
