# User Story: Shielding ABAC (Field Security)

**As a** System Administrator,
**I want** to strictly protect the assignment of Roles and Workspace metadata
**So that** random users cannot escalate their own privileges by hijacking API subnets or modifying the system configuration.

## Acceptance Criteria
- [ ] Si un operario común intenta enviar una mutación de `Persona` que altera su `id_rol` o el de otra persona, el Backend descarta silenciosamente ese campo (Field Security) procesando el resto del Payload lícito.
- [ ] Si el usuario tiene un Rol con privilegios absolutos (ej. `Super Admin`), sí se respeta la mutación del `id_rol`.
- [ ] La entidad `Config_Workspace` queda operativamente bloqueada de ser Mutada (Update/Delete) a menos que se trate del Creador Original (Domain Owner) o un `Super Admin`.
- [ ] La seguridad debe aplicarse imperativamente en la frontera del Servidor (Server-Side Shielding), no como una simple regla de front-end.
