# S44.4: Shielding ABAC (Field-Level Security & Workspace Lock)

## 1. Meta Context
- **Epic**: E44 (Organizational Topology)
- **Status**: Pending
- **Primary Objective**: Cerrar la brecha de escalación de privilegios impidiendo que usuarios sin jerarquía administrativa puedan mutar el campo `id_rol` de la entidad `Persona`, además de blindar la entidad de infraestructura `Config_Workspace`.

## 2. Boundaries & Context
- **In Scope**:
  - Extensión del motor `Engine_ABAC.validatePermission` para admitir validación a nivel de campo (Field-Level Security).
  - Bloqueo de escritura del campo `id_rol` en `Persona` durante la ingesta a base de datos.
  - Candado estricto (Zero-Trust) para las mutaciones (Update/Delete) sobre `Config_Workspace`.
- **Out of Scope**:
  - Implementación de UI para visualizar campos deshabilitados (se maneja pasivamente por el framework actual).
  - Creación de nuevos Roles (ya administrado en `Sys_Roles`).
