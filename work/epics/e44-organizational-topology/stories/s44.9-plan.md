# S44.9: Implementation Plan

## 1. Setup & Pre-requisitos
- Explorar `Job_WorkspaceSync.js` y `Engine_ETL.js` para localizar los nudos de hidratación donde se transfiere el String de Cargo recibido por webhook o importación hacia el payload final.

## 2. Lógica Core (Interceptor de Diccionario)
- Modificar `Job_WorkspaceSync.js` para precargar el catálogo `Cargo` desde la BD (`Engine_DB` o `DataAPI`).
- Construir un Diccionario en Memoria (Hash Map) `O(1)` utilizando tanto el `nombre` (conversión a minúsculas) como el `id_externo_workspace` para cruzar coincidencias.
- Interceptar `pToSave.id_cargo`: Si es un String en bruto, buscarlo en el caché.
  - Si hay un Match: Mutar el array inyectándole el `internalUUID` verdadero (`CARG-...`).
  - Si no hay Match (Missing Mapping): Anular cautelosamente el inyector (`delete pToSave.id_cargo`) y arrojar de manera segura un Log explícito de que no se encontró el mapeo (evitando la corrupción en `Sys_Graph_Edges`).

## 3. Despliegue Transparente (UX/UI)
- Validar retrospectivamente que, dado el carácter silente del Interceptor (Background Worker), no corrompa los Modales Frontend ni las interfaces transaccionales originarias.

## 4. Pruebas y Validación (E2E / CLI)
- Simular un Mock Payload de un correo ingresando un Cargo plano ("Gerente de Operaciones") y corroborar (via Dev Server logs) que el objeto mute exitosamente hacia `[{ id_cargo: "CARG-..." }]`.
