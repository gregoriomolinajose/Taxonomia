# S44.9: Implementation Plan

## 1. Setup & Pre-requisitos
- Explorar `Job_WorkspaceSync.js` y `Engine_ETL.js` para localizar los nudos de hidratación donde se transfiere el String de Cargo recibido por webhook o importación hacia el payload final.

## 2. Lógica Core (Interceptor Auto-Provisioner)
- `[x]` Modificaremos `Engine_Workspace.js` (específicamente la función `resolverDirectorioWorkspace`).
- `[x]` Al obtener el ID/Título crudo del empleado (Ej. "411"):
  1. Consultaremos la base de datos de Cargos (`Engine_DB.list('Cargo')`).
  2. Búsqueda de Coincidencia: Buscaremos si "411" ya existe en `id_externo_workspace` o `nombre`.
  3. Branch A (Existente): Si existe, extramos su `id_cargo` topológico (Ej. `CARG-XYZ`).
  4. Branch B (No Existente): Si no existe, auto-aprovisionamos el Cargo en ese momento ejecutando `Engine_DB.create('Cargo', { id_externo_workspace: "411", nombre: "411 pendiente por identificar", estado: "Activo" })`, y extraemos el ID recién creado.
- `[x]` Finalmente, inyectamos ese `id_cargo` real en el DTO devuelto al frontend. 
- `[x]` En el frontend, `UI_FormDependencies.html` automáticamente inyectará `CARG-XYZ` en el campo relacional "Cargo Oficial" (Select Single) de la UI.

## 3. Despliegue Transparente (UX/UI)
