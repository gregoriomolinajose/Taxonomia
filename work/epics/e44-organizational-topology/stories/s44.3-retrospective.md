# Retrospective S44.3: Mutación DataStore (_nombre_completo)

## Resumen
La historia S44.3 se enfocó en resolver la necesidad visual de mostrar nombres completos de las personas de forma unificada (Nombre + Apellidos) a lo largo de las vistas de cuadrícula y lista.

## Learnings
- **Deuda Técnica y H8 (Configuration Over Convention):** Inicialmente, la implementación inyectó condicionales duros (`if entityName === 'Persona'`) profundamente dentro de los motores base (`JS_Core.client.js` y `UI_DataGrid`). La arquitectura detectó rápidamente esto como una "Violación Severa" a la agnosis del motor.
- **Refactorización Declarativa:** Se aprendió que cualquier excepción visual de una entidad debe canalizarse mediante el `Schema_Engine.js`. La extracción del problema hacia las propiedades genéricas `computedFields: { concat: [...] }` y `uiConfig.dashboardCard: { subtitleFields: [...] }` permitió preservar la integridad arquitectónica de RaiSE sin sacrificar la UX solicitada.
- **Seguridad en Javascript (JS Truthiness):** El uso nativo de validaciones falsy cortas (`if (data[concat[k]])`) demostró ser altamente efectivo para evadir uniones anómalas (ej. "Juan undefined") durante procesos masivos de transformación de strings, evitando cracs silenciosos en la UI.

## Action Items
- Monitorizar constantemente en cada implementación UI si se introducen reglas de negocio estáticas que pertenezcan realmente al `Schema_Engine.js`.
- Ningún módulo Base UI (`UI_DataGrid`, `UI_FormSubmitter`, etc.) debe invocar `if (entity === 'X')` bajo ninguna circunstancia estructurada.
