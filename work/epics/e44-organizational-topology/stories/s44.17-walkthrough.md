# S44.17: Ingesta JIT de Workspace (ETL)

## 📌 Resumen de Implementación
Se integró la resolución automática de **Workspace Sync** y la creación de la topología organizacional (Cargos y Aristas) dentro del flujo de Ingesta Masiva (ETL) para la entidad `Persona`. 

### 🛡️ Diseño Seguro Anti-Timeouts
Tras el **Architecture Review**, se descartó realizar esta lógica directamente dentro del backend del Ingestor ETL (`upsertBatch`), ya que Google Apps Script tiene un límite estricto de ejecución de 6 minutos y la generación recursiva de grafos M:N es pesada.

En su lugar, se adoptó un modelo de **Orquestación en Cliente**:
1. El motor sube los datos a la Base de Datos como siempre (rápido y sin timeouts).
2. Justo antes de mostrar la pantalla de éxito, el cliente detecta si la entidad es `Persona`.
3. De ser así, se transforma la barra de progreso a **"Configurando Topología Workspace..."**.
4. Dispara asíncronamente el Job `runWorkspaceSyncJob`, el cual ya está optimizado para evitar límites de cuota de API (lotes de 50).
5. Se emite el evento reactivo `CACHE::GRAPH_HYDRATED` para que la UI se entere del cambio.
6. Se muestra el modal de resultados con normalidad. 

Cuando el usuario cierra el modal, la UI se recarga automáticamente y muestra las aristas recién dibujadas, **sin necesidad de dar ningún clic manual en "Sync Workspace"**.

## ✅ Criterios de Aceptación Cumplidos
- Un usuario puede subir un CSV/Sheet con correos corporativos.
- El backend inserta las Personas.
- El backend consulta automáticamente Workspace mediante el Job paralelo.
- Se crean/enlazan automáticamente los Cargos y se dibujan las aristas en el grafo.
- Todo sucede sin intervención manual (Zero-Trust Data Binding en acción).
