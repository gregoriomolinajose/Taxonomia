# S44.17: Ingesta JIT de Workspace (ETL) - Scope

## Boundaries

**In scope:**
- Modificar el backend del Motor ETL (`Engine_ETL` / `Adapter_Sheets`) para identificar cargas de la entidad `Persona`.
- Invocar el flujo de provisión (`resolverDirectorioWorkspace` o su equivalente en `Job_WorkspaceSync`) por cada registro procesado o al final del batch de ingesta.
- Asegurar que la creación de `Cargo` y la escritura de aristas topológicas (`Sys_Graph_Edges`) se realice en la misma transacción lógica que la ingesta.
- Devolver el payload hidratado completo para que el modal y el JIT Cache Refresh de la UI funcionen con normalidad.

**Out of scope:**
- Modificaciones a la UI del modal ETL.
- Cargas masivas de otras entidades no asociadas a Workspace.
- Refactorización de cuotas de Workspace Admin Directory API.

## Done Criteria

- [ ] Un usuario puede subir un CSV/Sheet con correos corporativos.
- [ ] El backend inserta las `Personas`.
- [ ] El backend consulta automáticamente Workspace.
- [ ] Se crean/enlazan automáticamente los `Cargos`.
- [ ] Se dibujan las relaciones topológicas en `Sys_Graph_Edges`.
- [ ] Todo sucede sin intervención del usuario más allá de presionar "Aceptar" en la ingesta masiva.
- [ ] La UI actualiza las relaciones instantáneamente (Zero-Trust Data Binding) usando `CACHE::GRAPH_HYDRATED`.
