# Design: S53.3 Interactive Contextual Mutations

## What & Why
- **Problem**: The visual Swimlane layout (S53.2) is read-only. Users need a way to construct the taxonomy hierarchy from the canvas visually.
- **Value**: By attaching a native `<ion-popover>` directly to the `[+]` buttons, users maintain visual context while linking child nodes, vastly improving UX compared to a disconnected multi-step wizard.

## Architectural Approach
We will utilize the existing `window.API_Universal` to mutate `Sys_Graph_Edges` without touching legacy RPCs. 
The UI will instantiate a dynamic popover with a standard selector list.

### Components Affected
1. **`UI_View_SwimlaneGrid.client.js`** (Modify):
   - Replace the simulation `ion-toast` in `_handleNodeAdd` with the logic to build and present an `<ion-popover>`.
   - The popover will contain a mini-app or simple list of available target entities (e.g., if parent is `Unidad_Negocio`, fetch `Portafolio`).
   - Call `window.API_Universal` (via standard data pipeline) to save the relationships.
   - Once saved, re-fetch `Sys_Graph_Edges` from `DataStore` and call `this.refresh()`.

2. **`CSS_TaxonomyCanvas.html`** (Modify):
   - Add styles for the popover content (e.g., search bar, list items, confirm button) to ensure it matches the Premium design language.

### Mutation Strategy (Edge Generation)
Based on the `entityName` of the clicked node, we determine the child entity and edge type:
- If clicked `Unidad_Negocio`:
  - Child Entity: `Portafolio`
  - Edge Type: `UNIDAD_NEGOCIO_PORTAFOLIO`
- If clicked `Portafolio`:
  - Child Entity: `Grupo_Productos`
  - Edge Type: `PORTAFOLIO_GRUPO_PRODUCTO`

**Payload Construction:**
```javascript
const newEdges = selectedIds.map(childId => ({
    id_nodo_padre: parentId,
    id_nodo_hijo: childId,
    tipo_arista: edgeType,
    contexto_id: this.taxonomiaId,
    es_version_actual: true,
    metadata: { created_via: "taxonomia_canvas" }
}));

// We can leverage DataEngine_UI or standard API call:
// google.script.run.API_Universal(...)
```

### Risk Mitigation
- **State Stale**: The `window.DataStore` needs to be updated with the new edges so `this.refresh()` works instantly.
  - *Fix:* After the API call returns success, we manually push the new edges to `window.DataStore.get('Sys_Graph_Edges')` and call `this.refresh()`. This achieves optimistic-like rendering without waiting for a full `Job_WorkspaceSync`.
- **Duplicate Edges**: The API/Backend topological engine automatically resolves `upsert` constraints, preventing double edge creation.

## API / Integration Rules
- No new RPC endpoints. We must use `API_Admin.upsert` or `API_Universal` to save records to `Sys_Graph_Edges`.
- The UI must block (show spinner) inside the popover while saving, then close the popover.
