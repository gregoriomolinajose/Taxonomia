# Story S53.5: Canvas Homologous Contextual Drawers

## Context & Problem Statement
Currently, when a user clicks the `[+]` button on a node within the Taxonomía Canvas (e.g., adding a Portafolio to an Unidad de Negocio), the system opens a generic `TXSearchable` drawer ("Vincular Portafolios"). 

From a UX and design consistency perspective, this breaks the expected pattern. Instead of a generic search component, the user expects to see the standardized "Consulta" (Read-Only/Contextual) Drawer of the parent entity. For example:
- Clicking `[+]` on an **Unidad de Negocio** should open the standardized Unidad de Negocio drawer (in a contextual mode), allowing the user to view its details and select/link Portafolios directly from its native sub-grid or relation selector.
- Clicking `[+]` on a **Portafolio** should open the native Portafolio drawer, allowing the user to select and link Grupos de Productos using the native interface of the Portfolio.

## Objectives
1. **Drawer Homogenization:** Refactor the `_handleNodeAdd` method in `UI_View_SwimlaneGrid.client.js` to invoke the `UI_DrawerManager` using the native schema of the *Parent* entity (e.g., opening the `Unidad_Negocio` drawer) instead of a standalone `TXSearchable` wrapper.
2. **Contextual Linking Mode:** Enhance the Form Engine / Drawer Manager to support a "Contextual Linking Mode" (`mode: 'link'`). When opened in this mode from the Canvas, the Drawer should highlight the specific relation field (e.g., `portafolios_vinculados`) and automatically inject the `contexto_id` (the Taxonomía ID) into any edges created during that session.
3. **Seamless Canvas Sync:** Ensure that any mutations made inside this homologous drawer emit the appropriate events (`FormEngine::InlinePersisted` or similar) so the underlying Canvas can instantly re-fetch and re-render the graph.

## Acceptance Criteria
- [ ] Clicking `[+]` on an Unidad de Negocio card opens the standard `Unidad_Negocio` drawer.
- [ ] The drawer explicitly focuses on or facilitates the addition of Portafolios to that specific Unidad de Negocio.
- [ ] Linking a child entity through this drawer correctly appends `contexto_id = id_taxonomia` to the graph payload.
- [ ] The Canvas automatically repaints upon closing the drawer or upon saving the relations.
- [ ] Generic `TXSearchable` standalone wrappers are completely removed from the Canvas logic.

## Technical Notes
- The `UI_View_SwimlaneGrid` will need to pass `taxonomiaId` down as a globally accessible context or parameter when invoking `DrawerManager.openEntityDrawer()`.
- `UI_FormSubmitter` must intercept sub-grid / relation submissions when a `contexto_id` is present in the environment and append it to the `commitEdges` or `bulkInsert` payloads.

## Definition of Done (DoD)
- Code implemented and tested locally.
- UX pattern fully matches the rest of the system's Entity Drawers.
- Edges persist with the correct topology and context.
- (Replaces previous deprecated Wizard linear linking story).
