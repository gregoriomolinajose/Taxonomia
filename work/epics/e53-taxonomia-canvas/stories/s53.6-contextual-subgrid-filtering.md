# S53.6: Filtrado Contextual de Subgrids (Workspace Isolation)

## 1. Contexto y Problema
Actualmente, gracias a la historia **S53.5**, al hacer clic en una entidad dentro del Canvas de Taxonomía se abre el Drawer Nativo Homologado de dicha entidad. Sin embargo, los subgrids (componentes de relación) que se renderizan dentro de ese cajón muestran **todas** las relaciones globales activas de la entidad en el sistema (el baseline productivo). 

Dado que el Canvas opera como un "Espacio de Trabajo" (Workspace) en estado Borrador para diseñar una Taxonomía específica, mostrar las relaciones globales contamina la experiencia de usuario. El usuario necesita un "escritorio limpio" donde el subgrid **solamente** muestre las aristas que pertenecen al contexto actual (es decir, donde `contexto_id == taxonomiaId actual`), ocultando el resto del baseline que no está siendo editado en este ejercicio.

## 2. Objetivos
- Aislar la vista de relaciones dentro de los subgrids cuando se abren a través de un Contextual Drawer.
- Asegurar que el filtro actúe a nivel de lectura (`UI_SubgridBuilder` / `UI_Component_DynamicList`) para que solo se rendericen los registros cuya arista coincida con el `taxonomiaContext`.
- No afectar el comportamiento global de los subgrids cuando el Drawer se abre desde el DataGrid convencional (donde sí se deben mostrar las relaciones globales).

## 3. Criterios de Aceptación
1. **Detección del Contexto:** El motor de subgrids (`UI_SubgridBuilder` o `UI_Component_DynamicList`) debe detectar la presencia del `dataset.taxonomiaContext` inyectado en el modal padre.
2. **Filtrado Visual:** Si existe un contexto, el subgrid solo debe mostrar los registros hijos cuyas relaciones en `Sys_Graph_Edges` tengan el `contexto_id` igual a dicho contexto.
3. **Comportamiento Seguro:** Si no hay un `taxonomiaContext` (uso normal del sistema), el subgrid debe mostrar las relaciones activas normales.
4. **UX Consistente:** Las operaciones de "Agregar" y "Remover" dentro del subgrid deben seguir operando y registrando en el contexto aislado sin afectar las relaciones globales de producción.

## 4. Diseño Técnico (Propuesta Inicial)
- **UI_SubgridBuilder.client.js**: En el método `build`, interceptar o pasar el `taxonomiaContext` hacia la configuración del `UI_Component_DynamicList`.
- **UI_Component_DynamicList.client.js** / **SubgridState**: En la rutina donde se cargan los datos (`loadData` o `_buildState`), al consultar la base de datos local `Sys_Graph_Edges` o `GraphEngine`, aplicar un filtro adicional `.filter(edge => edge.contexto_id === taxonomiaContext)` cuando este exista en la configuración del componente.
- Considerar si se requiere inyectar este filtro directamente a nivel de `Engine_Graph` (p.ej. `getRelatedNodes({ contextId: ... })`) para mayor limpieza arquitectónica.

## 5. Estimación
- **Esfuerzo:** XS (1 a 2 horas)
- **Riesgo:** Bajo. El impacto está encapsulado en el pipeline de renderizado de lectura del Subgrid.
