# Story S53.8: Canvas UX Refinements: Layout & Auto-Sync

## Context & Problem Statement
El Canvas de Taxonomía necesita tres ajustes críticos de usabilidad (UX) detectados durante las pruebas del nivel `Value_Stream`:

1. **Sincronización Manual Obsoleta**: Actualmente existe un botón de "Sincronizar" explícito. Dado que la aplicación está transicionando a una arquitectura reactiva (Zero-Latency Local Cache) con sincronización en background, este botón representa un paso manual innecesario que puede causar confusión.
2. **Apilamiento Vertical de Value Streams**: Al añadir múltiples Value Streams debajo de un Portafolio, el lienzo los apila verticalmente uno debajo del otro, ocupando demasiada altura y rompiendo el modelo de carril (swimlane) horizontal. Los Value Streams deberían distribuirse horizontalmente (en columnas), reservando el apilamiento vertical exclusivo para el interior de cada columna (para los Grupos de Productos).
3. **Limitaciones de Navegación del Lienzo**: A medida que los nodos se distribuyen horizontalmente y el árbol crece en profundidad, el lienzo rebasa los límites de la pantalla, pero actualmente no proporciona una capacidad clara de "Scroll" interactivo (Pan & Zoom) u over-scroll horizontal/vertical nativo.

## Objectives
1. **Eliminar Botón de Sincronización**: Remover el botón de Sincronización manual de la interfaz de la barra de herramientas del Canvas y asegurar que la recarga dependa estrictamente del EventBus (`CACHE::GRAPH_HYDRATED`).
2. **Reconfigurar Layout de Nivel 3 (Value Streams)**: Modificar el CSS/DOM layout en `UI_View_SwimlaneGrid.client.js` y `CSS_TaxonomyCanvas.html` para que los Value Streams renderizados dentro de un Portafolio se estructuren mediante `display: flex; flex-direction: row;` (Columnas), mientras que los Grupos de Productos dentro de ellos mantengan su `flex-direction: column;` (Apilamiento vertical).
3. **Experiencia de Lienzo (Estilo Miro) - Panning & Zoom**: En lugar de simples barras de desplazamiento, el Canvas debe adoptar una interacción avanzada estilo pizarra virtual (Miro/Figma).
   - **Pan (Desplazamiento)**: Permitir "agarrar y arrastrar" (click and drag) el lienzo para moverse libremente.
   - **Zoom**: Capacidad de hacer Zoom In / Zoom Out (vía rueda del mouse o controles UI).
   - **Estética**: Las barras de scroll nativas del navegador deben estar completamente ocultas (`::-webkit-scrollbar { display: none; }` o similares) para dar una verdadera sensación de lienzo infinito.

## Acceptance Criteria
- [ ] El botón de Sincronización ya no es visible en el UI.
- [ ] El layout visualiza correctamente múltiples `Value_Stream` uno al lado del otro (horizontal) compartiendo el mismo nivel jerárquico bajo un único `Portafolio`.
- [ ] Los `Grupo_Productos` permanecen apilados verticalmente dentro del bloque/columna de su `Value_Stream` padre.
- [ ] El Canvas permite "agarrar y arrastrar" (Pan) para desplazarse libremente en cualquier dirección.
- [ ] El usuario puede hacer Zoom In y Zoom Out interactuando con el lienzo.
- [ ] Las barras de desplazamiento nativas están ocultas al usuario para brindar una experiencia de lienzo infinito estilo Miro.

## Technical Notes
- **CSS Layout**: Para el apilamiento horizontal, en lugar de reutilizar `tax-swimlane-children-vertical`, se deberá crear o utilizar una clase CSS enfocada en layout de fila (`flex-row`) para iterar los hijos del Portafolio.
- **Miro-like Interaction**: Implementar manejo de eventos de ratón (`mousedown`, `mousemove`, `mouseup`, `wheel`) para aplicar `transform: translate(x,y) scale(z)` a un contenedor interno (`canvasDiv`), o bien evaluar integrar una librería ligera (ej. `Panzoom.js`) si la complejidad del DOM (muchos nodos y listeners) genera problemas de rendimiento al hacer drag nativo.
- **Scroll Hide**: CSS explícito para esconder `::-webkit-scrollbar` en el contenedor `rootContainer`.
