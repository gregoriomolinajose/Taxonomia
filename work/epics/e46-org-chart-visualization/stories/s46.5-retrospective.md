# Retrospective: S46.5 - ECharts Capacity Treemap Optimization & Auth Fixes

## Deliverables Completed
- **Treemap Layout Normalization:** Standardized the weight (`value`) of all nodes at the same tree depth in `UI_View_ECharts.client.js` to ensure visual uniformity and eliminate distorted block sizes regardless of underlying child density.
- **Rich Text Integration:** Enabled the `descripcion` field to be displayed inside the capacity cards using ECharts' `rich` formatting blocks (`{title|}`, `{desc|}`, and a transparent `{gap|}`).
- **Crash Resolution & Safe Wrapping:** Removed the native `overflow: 'break'` instruction that caused fatal Canvas engine crashes due to uncalculated bounding boxes. Replaced it with a robust, JavaScript-based manual string wrapper that slices both the title and the description at exactly 35 characters.
- **Google Apps Script OAuth Refresh:** Modified the `UTIL_ForcePermissions` tool in `Code.js` to forcefully invoke `DriveApp.getFiles()` and `AdminDirectory.Users.list()`. This bypassed the Apps Script IDE caching bug and forced the display of the OAuth consent screen in Production, successfully securing the `drive.readonly` token required for ETL Bulk Uploads.

## Learnings
- **ECharts Canvas Engine Limitations:** The ECharts `rich` text formatter does not support CSS-like text justification (`align: 'justify'`) because Canvas requires exact mathematical X/Y coordinates for each letter block. In dynamic layouts like Treemaps, calculating proportional spacing across wrapping lines without a fixed width is unsupported.
- **Apps Script Manifest vs Code Evaluation:** Even if `appsscript.json` declares an explicit scope (`oauthScopes`), the Google IDE often fails to prompt the user for the new permissions unless there is an undeniable, explicit API call to that service outside of a `try...catch` block (or if the `oauthScopes` property is temporarily deleted to force auto-detection).

## Next Steps
