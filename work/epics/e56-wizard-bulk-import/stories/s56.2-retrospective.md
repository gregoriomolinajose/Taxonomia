# Retrospective: S56.2 - UI de Importación Embebida (Inline)

## Context
**Epic:** E56 Wizard Bulk Import
**Story:** S56.2
**Objective:** Migrar la UI del modal de importación masiva a un componente reutilizable sin dependencias forzadas de modal.

## Learnings
1. **Bridge Pattern para Retrocompatibilidad:** Fue fundamental abstraer toda la creación del DOM a una clase *Headless* (`UI_BulkImporter`) y dejar que el modal original (`UI_ETL_Modal`) únicamente actúe como un wrapper de dicho componente, garantizando compatibilidad con el resto del sistema (DataView).
2. **IoC (Inversión de Control) en el FormBuilder:** Registrar el motor `uiComponent` en el `BuilderRegistry` demostró ser la arquitectura más escalable para inyectar flujos complejos dentro de un stepper.
3. **Escapado de Template Literals en Apps Script:** Cuando se genera HTML embebido que usa ES6 Template Literals (con variables como `${}`), el proceso de inyección o evaluación en Apps Script o durante el despliegue requiere cautela extrema para no escapar por accidente los *backticks* u operadores de interpolación, lo que provocaría un "Uncaught SyntaxError".

## Action Items
- [ ] Asegurarse de realizar un chequeo de sintaxis estático o linter automatizado antes de desplegar archivos al entorno de Apps Script para detectar errores tipográficos en el código enbebido.
- [ ] Aplicar este patrón (Headless Component) en futuros modales que deban volverse universales o integrarse dentro de un Canvas/Stepper.
