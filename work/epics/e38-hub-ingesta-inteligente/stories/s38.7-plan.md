- **Size**: M (5 SP)
- **Date**: 2026-04-16

## Tasks

### [Task 1] Inyectar Nuevos Tokens al Design System
- **Descripción**: Añadir los 5 tokens propuestos (`--color-bg-progress-track`, `--color-bg-progress-fill`, `--color-bg-surface-hover`, `--color-border-dropzone`, `--color-bg-dropzone`) en `CSS_DesignSystem.html`. Verificar que `UI_ThemeManager` los hidrata correctamente en Dark Mode.
- **Archivos Modificados**: `src/CSS_DesignSystem.html`
- **Verificación**: Inspeccionar `document.documentElement.style` en consola del navegador y confirmar que los 5 tokens existen como Custom Properties.
- **Size**: XS
- **Dependencias**: Ninguna
- **AC**: AC2

### [Task 2] Crear Bloque de Clases CSS Semánticas `.etl-*`
- **Descripción**: Añadir en `CSS_App.html` un bloque cohesivo de clases para el modal ETL (`.etl-body`, `.etl-card`, `.etl-card-title`, `.etl-btn-action`, `.etl-btn-secondary`, `.etl-input-item`, `.etl-progress-container`, `.etl-progress-bar`, `.etl-progress-label`, `.etl-dropzone`, `.etl-segment`). Todas alimentadas por tokens existentes + los 5 nuevos.
- **Archivos Modificados**: `src/CSS_App.html`
- **Verificación**: `npx stylelint src/CSS_App.html` no reporta violaciones de tokens (regla `scale-unlimited/declaration-strict-value`).
- **Size**: S
- **Dependencias**: Task 1
- **AC**: AC2, AC4

### [Task 3] Refactorizar `UI_ETL_Modal.client.js` — Purgar Estilos Inline
- **Descripción**: Reemplazar todas las instancias de `element.style.*` por asignaciones `element.className`. Sustituir los `innerHTML` con estilos inline del header y cards por clases semánticas. Añadir la zona de progreso (`etl-progress-container`) que se mostrará/actualizará desde el `progressCallback` del Chunker.
- **Archivos Modificados**: `src/UI_ETL_Modal.client.js`
- **Verificación**: `grep -c "\.style\." src/UI_ETL_Modal.client.js` debe retornar `0`. Tests existentes del modal siguen pasando.
- **Size**: M
- **Dependencias**: Task 2
- **AC**: AC1, AC3

### [Task 4] Validación Visual Manual — Light/Dark Mode
- **Descripción**: Abrir el modal ETL en ambos temas (Light y Dark) y verificar visualmente que los colores, bordes, sombras y tipografía se renderizan correctamente. Capturar screenshots como evidencia.
- **Archivos Modificados**: Ninguno (validación)
- **Verificación**: Screenshots muestran coherencia visual en ambos temas. No hay texto invisible, bordes fantasma ni pérdida de contraste.
- **Size**: XS
- **Dependencias**: Task 3
- **AC**: AC4

## Execution Order
1. **Task 1** (Tokens) — Base fundacional, sin dependencias.
2. **Task 2** (CSS Classes) — Consume los tokens de T1.
3. **Task 3** (JS Refactor) — Consume las clases de T2.
4. **Task 4** (Validación Visual) — Integración manual final.

## Risks and Mitigations
| Riesgo | Probabilidad | Mitigación |
|---|---|---|
| Ionic Web Components ignoran clases CSS externas en Shadow DOM | Media | Usar `::part()` selectores o CSS Custom Properties que penetren Shadow DOM de Ionic |
| Regresión visual en componentes existentes al tocar CSS_App.html | Baja | Prefijo `.etl-*` aísla completamente los estilos nuevos del resto del sistema |
| Dark Mode no hereda correctamente los tokens nuevos | Baja | Los tokens usan `var()` chains que automáticamente resuelven según el tema activo |
