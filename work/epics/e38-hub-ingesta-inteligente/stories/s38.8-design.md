# UI/UX Design Specification: Modal ETL (Carga Masiva)

## 1. Patrón Arquitectónico del Layout
El `UI_ETL_Modal` migró de un formulario lineal crudo hacia un patrón de **Vertical Stepper Contextual**, optimizado para el abordaje de usuarios no técnicos y preparado visualmente como PWA inmersiva.

### 1.1 Respeto Mobile-First (Escalabilidad de Vistas)
- **Modo Móvil (`max-width < 768px`)**: El modal reclama `100vw` y `100vh` en un entorno inmersivo puro sin interrupciones visuales, elidiendo el Dropzone de escritorio a favor de interacciones táctiles directas.
- **Modo Escritorio (`min-width: 768px`)**: Escala nativamente mediante un contenedor centrado (`50vw` limitando a un margen legíble), habilitando capacidades Drag&Drop de arrastre libre sobre áreas punteadas.

## 2. Decisiones de Interfaz

### 2.1 Selector de Contexto Horizontal (Radio Grid)
Implementación de Cards interactivas duales (*Google Sheets* vs *Archivo CSV*). 
Se adaptó una `flex-direction: row` con `flex: 1` para ocupar uniformemente el total disponible. Se descartaron *badges* extraños ("Recomendado") delegando la confirmación activa a un borde resaltado `--ion-color-primary` más el `<ion-icon name="checkmark-circle">` anidado.

### 2.2 Reutilización de Factoría Global
Para la frontera visual principal se sustituyeron divisiones manuales conectando activamente:
`window.UI_Factory.buildDivider({ label: 'PASOS PARA IMPORTAR' })`
Heredando la tipografía exacta transversal, mayúsculas y coloraciones de los formularios en producción.

### 2.3 Tipografía Dinámica (Anti-Shadow DOM)
Se inyectó en los CSS nativos de los botones (`.etl-btn-execute`) la captura mandataría de fuentes superiores: `font-family: var(--sys-font-primary, inherit) !important;`. El framework Ionic de Web Components es incapaz ya de sobreescribirlo vía encapsulamiento.

## 3. Estado Cognitivo e Interacciones de Carga (DataUX)

### 3.1 Dropzone Predictiva (CSV)
- **Initial State**: Área punteada estandarizada en azul para denotar área de inserción de ficheros.
- **Filled State (`.filled`)**: Al reconocer una intersección de archivo o invocación vía input, muta el contenedor a estado semitransparente verde (`background: rgba(10, 191, 79, 0.05)`), bordes sólidos color *Success*, y el `<ion-icon>` central transmuta a verde macizo reportando el nombre del payload capturado para eliminar la ambigüedad (Anti-anxiety UI).

### 3.2 Persistencia Anti-Reclonado (Google Sheets)
- Para evitar que los usuarios generen una hoja en blanco por error múltiple:
  - **Memoria de Red**: Se guarda la última URL en caché temporal (`_state.lastGeneratedEtlUrl`).
  - **Auto-Reapertura**: Si se re-invoca la ventana modal en una misma sesión transitoria, el sistema hidrata el input de inmediato (esperando la simulación `ionInput` de 150ms).
  - **Sobrescritura de Trigger**: La Card de "Destino/Generar" sufre una intercepción si hay un `http` activo, disparando directamente un `window.open` sobre ese documento existente y bloqueando el endpoint de Cloud (Ahorro dramático de Request y Time to Interactive).

### 3.3 Asistentes Condicionales (Hint Messages)
- Mensajería *"Hemos agregado la liga..."* forzada a `.etl-hint-text`. 
- Reacciona nativamente apagándose y prendiéndose respondiendo exclusivamente al flujo mecanizado local (o a que un usuario la vacíe manualmente).
- Un Sub-Ícono en paralelo (`search` y `open-outline` intermitente) guía el uso.

## 4. Gobernanza del Payload Cero-Conflicto
En base a descubrimientos de filtración de data, el template genérico de `DataEngine_UI.exportCSV` posee blindaje local forzando exclusión vía array base del sistema (`created_at`, `deleted_by`, etc.), garantizando que la plantilla servida sea estructuralmente pura para ingestión.
