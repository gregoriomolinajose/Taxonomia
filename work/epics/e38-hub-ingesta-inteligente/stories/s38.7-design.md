# S38.7 Design: UI/UX Audit & Redesign del Modal ETL

## Complexity Assessment
- **Components**: 3 (UI_ETL_Modal.client.js, CSS_App.html, CSS_DesignSystem.html)
- **Story Points**: 5 (Moderate)
- **External Integrations**: 0 (pura auditoría visual, sin backend)
- **UX Gate**: ✅ Activado — esta historia toca interacción humana directa.

**Resultado**: Moderate — Core sections + propuesta de tokens.

---

## Problem
El modal ETL actual (`UI_ETL_Modal.client.js`) fue construido como un MVP funcional durante las historias S38.1–S38.4. El marcado DOM se genera enteramente vía `document.createElement` con estilos inline hardcodeados (`style.fontFamily = 'inherit'`, `style.textTransform = 'none'`, `style.flex = '1'`), violando la gobernanza de tokens del Design System y dificultando el mantenimiento temático (Dark Mode, High Contrast).

## Value
Alinear el modal con el sistema de diseño centralizado (`CSS_DesignSystem.html` + `UI_ThemeManager`) garantiza coherencia visual, soporte automático de temas y reduce la deuda técnica CSS en ~45 líneas de estilos inline dispersos.

## Auditoría UX del Modal Actual

### Hallazgos Críticos

| # | Hallazgo | Línea(s) | Severidad | Heurística UX |
|---|----------|----------|-----------|---------------|
| F1 | **Estilos inline hardcoded** — 12 instancias de `element.style.*` en lugar de clases CSS con tokens | L39-41, L56-58, L69, L80-82, L111-112, L127-130, L142-145 | Alta | Consistencia (Nielsen #4) |
| F2 | **Sin feedback de progreso** — No existe barra de progreso ni indicador visual durante el chunking asíncrono | — | Alta | Visibilidad del estado del sistema (Nielsen #1) |
| F3 | **Toast genérico** — `_showToast` usa colores planos de Ionic sin mapear a tokens semánticos del proyecto | L199-206 | Media | Match con mundo real (Nielsen #2) |
| F4 | **Título del modal con HTML inline** — `innerHTML` con `style="..."` para el ícono Google en lugar de clase semántica | L47 | Media | Estética y minimalismo (Nielsen #8) |
| F5 | **Segmento sin indicador visual activo** — El `ion-segment` no tiene estilos personalizados que refuercen la tab activa con tokens de marca | L158-168 | Baja | Reconocimiento vs. recuerdo (Nielsen #6) |
| F6 | **Sin zona de Drop visual** — La carga CSV no tiene drag-and-drop ni affordance visual de "arrastra aquí" | L114-122 | Media | Flexibilidad y eficiencia (Nielsen #7) |

### Hallazgos de Gobernanza de Tokens

| Token Actual | Uso en Modal | Problema |
|---|---|---|
| `--rounded-sm` / `--rounded-md` | No se usa — `borderRadius: '8px'` hardcoded (L69) | Debería ser `var(--rounded-sm)` |
| `--spacing-*` | No se usa — `gap: '20px'` (L41), `gap: '10px'` (L112) | Debería ser `var(--spacing-5)` y `var(--spacing-3)` |
| `--ion-font-family` | `fontFamily: 'inherit'` repetido 5 veces | Redundante, la cascade CSS lo hereda |
| `--shadow-floating` | No se aplica al modal popup | Debería usar `var(--shadow-floating)` |

---

## Approach

Reemplazar los 12 bloques de estilos inline por **clases CSS semánticas** definidas en `CSS_App.html`, alimentadas por tokens existentes del Design System. Añadir una sección de **progress feedback** y proponer **5 nuevos tokens** para cubrir brechas del sistema.

### Componentes Afectados

| Componente | Tipo de Cambio | Descripción |
|---|---|---|
| `src/UI_ETL_Modal.client.js` | Modificación | Reemplazar `element.style.*` por `element.className`, añadir zona de progreso |
| `src/CSS_App.html` | Modificación | Añadir bloque `.etl-*` con clases semánticas del modal |
| `src/CSS_DesignSystem.html` | Modificación | Inyectar nuevos tokens propuestos |

---

## Nuevos Tokens Propuestos

```css
:root {
  /* Progress & Feedback */
  --color-bg-progress-track: var(--color-bg-0);
  --color-bg-progress-fill: var(--color-interactive-primary);
  
  /* Surface Hover (hover genérico para cards interactivas) */
  --color-bg-surface-hover: rgba(var(--ion-color-primary-rgb), 0.04);
  
  /* Drag & Drop Zone */  
  --color-border-dropzone: var(--color-interactive-primary);
  --color-bg-dropzone: rgba(var(--ion-color-primary-rgb), 0.03);
}
```

**Justificación**: Estos tokens no existen en el sistema actual y serán reutilizables fuera del ETL (p.ej. en futuros componentes de upload de avatares, barra de progreso del Dashboard, o cards con hover interactivo).

## Acceptance Criteria

### MUST
- **AC1**: Cero instancias de `element.style.*` en `UI_ETL_Modal.client.js` — todos los estilos deben resolverse mediante clases CSS.
- **AC2**: Todas las clases CSS nuevas del modal deben utilizar exclusivamente tokens del Design System (`var(--spacing-*)`, `var(--rounded-*)`, `var(--color-*)`, `var(--shadow-*)`).
- **AC3**: El modal debe incluir un indicador de progreso visible durante operaciones de chunking (invocado desde `progressCallback`).
- **AC4**: Dark Mode y Light Mode deben renderizarse correctamente sin CSS overrides.

### SHOULD
- **AC5**: Implementar zona de drag-and-drop visual para la sección CSV con affordance "arrastra aquí".
- **AC6**: Los Toasts de error deben mapear al `errorType` semántico definido en S38.6.

### MUST NOT
- **AC7**: No alterar la lógica Javascript de `DataEngine_ETL.client.js` ni `API_Universal.gs`.
- **AC8**: No introducir dependencias externas (librerías CSS, frameworks adicionales).
