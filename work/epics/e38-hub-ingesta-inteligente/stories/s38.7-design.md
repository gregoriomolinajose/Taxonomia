# S38.7 Design v3: UI/UX Audit & Redesign del Modal ETL

> **Revisión v3** — Incorpora AR (H6, H7, H8, H11) + Mobile-First + Touch Fallback.

## Complexity Assessment
- **Components**: 4 (UI_ETL_Modal.client.js, CSS_ETL_Modal.html [NEW], CSS_DesignSystem.html, Index.html)
- **Story Points**: 5 (Moderate)
- **UX Gate**: ✅ Activado

---

## Problem
El modal ETL actual (`UI_ETL_Modal.client.js`) fue construido como MVP funcional con 12 bloques de estilos inline hardcodeados (`element.style.*`), violando la gobernanza de tokens del Design System. Los estilos carecen de soporte temático (Dark Mode), no hay feedback visual de progreso, y el layout no está diseñado mobile-first.

## Value
Alinear el modal al sistema de diseño centralizado con enfoque mobile-first garantiza coherencia visual en todos los dispositivos, soporte automático de temas, y prepara el componente para su futura migración a PWA/Capacitor (E39).

## Decisiones de Diseño

### D1: Modularización CSS — Archivo propio `CSS_ETL_Modal.html` (H11)

**Decisión**: Crear `src/CSS_ETL_Modal.html` como módulo CSS independiente. Sigue el patrón de `CSS_DesignSystem.html`.

### D2: Clases CSS reducidas — Solo ≥2 propiedades (H7)

**Decisión**: **7 clases base** + **breakpoints mobile-first** integrados en cada clase:

| Clase | Props Mobile (default) | Props Desktop (@media ≥768px) |
|-------|----------------------|-------------------------------|
| `.etl-body` | flex-column, gap: `--spacing-3`, padding: `--spacing-3` | gap: `--spacing-5`, padding: `--spacing-5` |
| `.etl-btn-row` | flex-column, gap: `--spacing-2` | flex-row, gap: `--spacing-3` |
| `.etl-btn-action` | text-transform, font-family, font-weight, width: 100% | width: auto |
| `.etl-progress-wrap` | height, bg, radius, overflow | Sin cambios |
| `.etl-progress-bar` | height, bg, transition | Sin cambios |
| `.etl-progress-label` | size: `--sys-font-small`, color, text-align | size: `--sys-font-body` |
| `.etl-dropzone` | **display: none** (touch no soporta drag) | display: flex, border, bg, radius, padding, transition |
| `.etl-dropzone.dragover` | — | border-color, bg |

> **Nota Mobile-First**: La dropzone se oculta completamente en pantallas táctiles (`@media (hover: none)`), donde los usuarios usan el botón "Adjuntar CSV" directamente. Solo aparece en dispositivos con puntero de escritorio. Esto evita un affordance engañoso en móvil.

### D3: Consumo Directo de Tokens Globales (H9 / H8 resueltos)

**Problema**: Añadir alias globales (`--color-bg-progress-fill`) para un solo componente contamina el namespace de `CSS_DesignSystem.html`.
**Decisión**: No se inyectarán nuevos tokens globales. Las clases en `CSS_ETL_Modal.html` consumirán directamente los tokens semánticos core:
- Fondo barra progreso: `var(--color-bg-0)`
- Llenado progreso y bordes: `var(--color-interactive-primary)`
- Fondo Dropzone: Funciones CSS dinámicas sobre variables base como `color-mix(in srgb, var(--ion-color-primary) 5%, transparent)` o la variable de app preexistente `var(--dv-primary-light)`.


### D4: Drag-and-drop complementa al botón CSV (H6)

La `.etl-dropzone` envuelve la sección CSV como affordance visual. En desktop: arrastra activa `.dragover`, suelta dispara `onLocalUpload`. En mobile: la zona no se renderiza; el botón "Adjuntar CSV" es suficiente.

```
Desktop (≥768px):
┌─────────────────────────────────────┐
│  .etl-dropzone                      │
│  ┌─────────────┐ ┌───────────────┐  │
│  │ Bajar Tpl   │ │ Adjuntar CSV  │  │
│  └─────────────┘ └───────────────┘  │
│    Arrastra tu archivo .csv aquí    │
└─────────────────────────────────────┘

Mobile (<768px):
┌─────────────────────────────────────┐
│  ┌─────────────────────────────┐    │
│  │      Bajar Template         │    │
│  └─────────────────────────────┘    │
│  ┌─────────────────────────────┐    │
│  │      Adjuntar .CSV          │    │
│  └─────────────────────────────┘    │
└─────────────────────────────────────┘
```

### D5: Estrategia Mobile-First (nueva)

**Principio**: Todas las clases se definen para **375px** como base. Los overrides desktop se aplican mediante `@media (min-width: 768px)`.

**Regla del Dropzone Touch**: Se usa `@media (hover: hover) and (pointer: fine)` para mostrar la dropzone solo en dispositivos con mouse/trackpad. Esto es más preciso que un breakpoint de ancho, porque tablets grandes con touch tampoco soportan drag nativo.

## Examples

### CSS Mobile-First:
```css
/* Base: Mobile (375px+) */
.etl-body {
  display: flex;
  flex-direction: column;
  gap: var(--spacing-3);
  padding: var(--spacing-3);
}
.etl-btn-row {
  display: flex;
  flex-direction: column;
  gap: var(--spacing-2);
}
.etl-btn-action {
  text-transform: none;
  font-family: var(--ion-font-family);
  font-weight: 500;
  width: 100%;
}
.etl-dropzone {
  display: none; /* Oculto en touch */
}

/* Desktop (768px+) */
@media (min-width: 768px) {
  .etl-body { gap: var(--spacing-5); padding: var(--spacing-5); }
  .etl-btn-row { flex-direction: row; gap: var(--spacing-3); }
  .etl-btn-action { width: auto; }
}

/* Solo dispositivos con puntero preciso (mouse/trackpad) */
@media (hover: hover) and (pointer: fine) {
  .etl-dropzone {
    display: flex;
    flex-direction: column;
    align-items: center;
    gap: var(--spacing-2);
    border: 2px dashed var(--color-border-dropzone);
    border-radius: var(--rounded-sm);
    padding: var(--spacing-5);
    background: var(--color-bg-dropzone);
    transition: all 0.2s ease;
  }
  .etl-dropzone.dragover {
    border-color: var(--color-bg-progress-fill);
    background: var(--dv-primary-light);
  }
}
```

## Acceptance Criteria

### MUST
- **AC1**: Cero instancias de `element.style.*` en `UI_ETL_Modal.client.js` (excepto `width` dinámico del progress bar).
- **AC2**: Todas las clases CSS usan exclusivamente tokens del Design System.
- **AC3**: Indicador de progreso visible durante chunking.
- **AC4**: Dark Mode y Light Mode renderizan correctamente.
- **AC5**: CSS vive en módulo propio `CSS_ETL_Modal.html`.
- **AC10**: Layout mobile-first: botones apilados en <768px, horizontales en ≥768px.
- **AC11**: Dropzone solo visible en dispositivos con puntero preciso (`hover: hover`).

### SHOULD
- **AC6**: Drag-and-drop complementa botón CSV con affordance visual en desktop.
- **AC7**: Toasts de error mapean a `errorType` semántico de S38.6.

### MUST NOT
- **AC8**: No alterar lógica JS de `DataEngine_ETL.client.js` ni `API_Universal.gs`.
- **AC9**: No crear clases CSS con <2 propiedades propias.
