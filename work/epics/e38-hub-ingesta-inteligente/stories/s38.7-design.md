# S38.7 Design v2: UI/UX Audit & Redesign del Modal ETL

> **Revisión v2** — Incorpora recomendaciones del Architecture Review (H6, H7, H8, H11).

## Complexity Assessment
- **Components**: 4 (UI_ETL_Modal.client.js, CSS_ETL_Modal.html [NEW], CSS_DesignSystem.html, Index.html)
- **Story Points**: 5 (Moderate)
- **UX Gate**: ✅ Activado

---

## Problem
El modal ETL actual (`UI_ETL_Modal.client.js`) fue construido como MVP funcional con 12 bloques de estilos inline hardcodeados (`element.style.*`), violando la gobernanza de tokens del Design System. Los estilos carecen de soporte temático (Dark Mode) y no hay feedback visual de progreso durante el chunking asíncrono.

## Value
Alinear el modal al sistema de diseño centralizado garantiza coherencia visual, soporte automático de temas, y reduce la deuda técnica CSS eliminando ~45 líneas de estilos inline dispersos.

## Decisiones de Diseño (Post-AR)

### D1: Modularización CSS — Archivo propio `CSS_ETL_Modal.html` (H11)

**Problema**: `CSS_App.html` ya acumula 4 dominios (`.nav-*`, `.drawer-*`, `.dv-*`, globales). Agregar `.etl-*` ahí incrementa la complejidad y viola SRP.

**Decisión**: Crear `src/CSS_ETL_Modal.html` como archivo CSS independiente, incluido en `Index.html` mediante `<?!= include('CSS_ETL_Modal'); ?>`. Esto sigue el patrón existente de `CSS_DesignSystem.html` como módulo CSS separado.

**Alternativa descartada**: Añadir a `CSS_App.html` — rechazado por acumulación de dominios.

### D2: Clases CSS reducidas — Solo clases con ≥2 propiedades (H7)

**Problema**: La propuesta v1 planteaba 11 clases donde algunas serían wrappers vacíos sobre estilos que Ionic ya resuelve (p.ej. `ion-card` ya tiene border-radius y background).

**Decisión**: Reducir a **7 clases** con valor propio demostrable:

| Clase | Props CSS | Justificación |
|-------|-----------|---------------|
| `.etl-body` | 3 (flex, direction, gap) | Container layout principal |
| `.etl-btn-action` | 3 (transform, font, weight) | Override de defaults Ionic para botones del wizard |
| `.etl-progress-wrap` | 4 (height, bg, radius, overflow) | Track de la barra de progreso |
| `.etl-progress-bar` | 3 (height, bg, transition) | Fill animado de progreso |
| `.etl-progress-label` | 3 (size, color, align) | Texto de estado del lote |
| `.etl-dropzone` | 5 (border, bg, radius, padding, transition) | Zona visual drag-and-drop |
| `.etl-dropzone.dragover` | 2 (border-color, bg) | Estado activo al arrastrar |

**Clases eliminadas**: `.etl-card`, `.etl-card-title`, `.etl-input-item`, `.etl-segment` — Ionic los resuelve nativamente con Custom Properties (`--background`, `--border-radius`).

### D3: Token `--color-bg-surface-hover` eliminado (H8)

**Problema**: `--color-bg-surface-hover` (rgba 0.04) es redundante con `--dv-primary-light` (rgba 0.1).

**Decisión**: Usar `--dv-primary-light` directamente. Reducir tokens nuevos de 5 a **4**:

```css
:root {
  --color-bg-progress-track: var(--color-bg-0);
  --color-bg-progress-fill: var(--color-interactive-primary);
  --color-border-dropzone: var(--color-interactive-primary);
  --color-bg-dropzone: rgba(var(--ion-color-primary-rgb), 0.03);
}
```

### D4: Drag-and-drop complementa al botón CSV (H6)

**Problema**: ¿El drop zone reemplaza o complementa al botón "Adjuntar .CSV"?

**Decisión**: **Complementa** — La `.etl-dropzone` envuelve visualmente la sección CSV completa (botones + input). Al arrastrar un archivo sobre la zona, se activa la clase `.dragover` con feedback visual. Al soltar, se dispara el mismo handler `options.onLocalUpload`. El botón "Adjuntar .CSV" permanece funcional para usuarios que prefieran click.

```
┌─────────────────────────────────────┐
│  .etl-dropzone                      │
│  ┌─────────────┐ ┌───────────────┐  │
│  │ Bajar Tpl   │ │ Adjuntar CSV  │  │
│  └─────────────┘ └───────────────┘  │
│                                     │
│    Arrastra tu archivo .csv aquí    │
│         (texto affordance)          │
└─────────────────────────────────────┘
```

## Examples

### Antes (inline actual):
```javascript
container.style.display = 'flex';
container.style.flexDirection = 'column';
container.style.gap = '20px';
btnGenTpl.style.textTransform = 'none';
```

### Después (clases semánticas):
```javascript
container.className = 'etl-body';
btnGenTpl.className = 'etl-btn-action';
```

### Progress Bar (nuevo):
```javascript
// Invocado por progressCallback(chunkIndex, totalChunks, isDone)
progressWrap.className = 'etl-progress-wrap';
progressBar.className = 'etl-progress-bar';
progressBar.style.width = `${(chunkIndex / totalChunks) * 100}%`;
progressLabel.className = 'etl-progress-label';
progressLabel.textContent = `Lote ${chunkIndex} de ${totalChunks}`;
```

### Dropzone (nuevo):
```javascript
const dropzone = document.createElement('div');
dropzone.className = 'etl-dropzone';
dropzone.addEventListener('dragover', (e) => {
    e.preventDefault();
    dropzone.classList.add('dragover');
});
dropzone.addEventListener('dragleave', () => dropzone.classList.remove('dragover'));
dropzone.addEventListener('drop', (e) => {
    e.preventDefault();
    dropzone.classList.remove('dragover');
    const file = e.dataTransfer.files[0];
    if (file) options.onLocalUpload(entityName, { target: { files: [file] } }, modal);
});
```

## Acceptance Criteria

### MUST
- **AC1**: Cero instancias de `element.style.*` en `UI_ETL_Modal.client.js`.
- **AC2**: Todas las clases CSS del modal usan exclusivamente tokens del Design System.
- **AC3**: Indicador de progreso visible durante chunking (`progressCallback`).
- **AC4**: Dark Mode y Light Mode renderizan correctamente.
- **AC5**: CSS del modal vive en archivo modular `CSS_ETL_Modal.html`, no en `CSS_App.html`.

### SHOULD
- **AC6**: Zona drag-and-drop que complementa al botón "Adjuntar CSV" con affordance visual.
- **AC7**: Toasts de error mapean al `errorType` semántico de S38.6.

### MUST NOT
- **AC8**: No alterar la lógica JS de `DataEngine_ETL.client.js` ni `API_Universal.gs`.
- **AC9**: No crear clases CSS wrapper que aporten <2 propiedades propias.
