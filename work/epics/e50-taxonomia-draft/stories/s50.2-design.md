# Story Design: S50.2 GraphUtils Filter & Wizard Payload

## 1. Frame What & Why
**Problema:** Al usar `Sys_Graph_Edges` nativo para borradores, las consultas globales de la empresa se podrían contaminar si alguien abre un borrador. Además, el Wizard actualmente no sabe inyectar estados de borrador.
**Valor:** Garantizar aislamiento "Zero-Trust" del borrador (GraphUtils) y permitir al Wizard operar atómicamente.

## 2. Approach
- **Lectura:** Modificar `resolveLinkedId` y `resolveAllLinkedIds` en `JS_GraphUtils.client.js` para que ignoren `estado === 'Borrador'`, a menos que se pase el parámetro `contextId` correspondiente.
- **Escritura:** Modificar `UI_FormSubmitter.client.js` o `SubgridBuilder` (dependiendo del ciclo de guardado). Puesto que la UI de Taxonomía funciona embebida en un Wizard, cuando se haga *submit* de una relación asíncrona, se le inyectará `estado: 'Borrador'` y el `contexto_id`. (El ID de Taxonomía se tomará del objeto localEditId del padre).

## 3. Examples
```javascript
// Graph_Utils.resolveAllLinkedIds ignorando borrador
const roles = window.Graph_Utils.resolveAllLinkedIds('USR-123', 'PERSONA_ROL'); // Retorna [] si solo tiene borrador

// Pasando contexto
const drafts = window.Graph_Utils.resolveAllLinkedIds('USR-123', 'PERSONA_ROL', 'TAX-456'); // Retorna [..]
```

## 4. Acceptance Criteria
1. **MUST:** `JS_GraphUtils` no devuelve IDs con `estado = 'Borrador'` sin el parámetro.
2. **MUST:** `UI_FormSubmitter` inyecta `estado = 'Borrador'` al guardar un `Sys_Graph_Edges` si el padre es Taxonomía o si el formulario está en modo borrador.
