# Technical Design: S50.3 UI Hydration Context Flag

## 1. Context & Complexity
- **Complexity:** Moderate. Envuelve 4 componentes del Frontend que deben pasarse el "contextId" para bypassear el Zero-Trust filter de la S50.2.
- **Risk Gate:** Sin riesgos mayores. Todo el alcance es en memoria (UI/DOM).

## 2. Approach
Para asegurar la hidratación y lectura en vivo de los Borradores en el Wizard:
1. **SubgridBuilder (`UI_SubgridBuilder.client.js`)**: Cuando escanea los _child records_ al inicializar, checará si `entityName === 'Taxonomia'` o si el `modalContext` tiene `isDraft`. Si es así, obtendrá el PK temporal/definitivo y lo pasará como 3er parámetro a `Graph_Utils.resolveAllLinkedIds(id, edge, contextId)`.
2. **RelationBuilder (`UI_Component_RelationBuilder.client.js`)**: En los pasos estáticos de relaciones, inyectará `contextId` dentro de `visualTokens` al usar la Factory de UI.
3. **Factory (`UI_Factory_Searchables.client.js`)**: Recibirá el `contextId` y lo asignará como atributo en DOM `<tx-searchable context-id="...">`.
4. **TXSearchable (`UI_Component_TXSearchable.client.js`)**: Al recuperar los _subtitles_ a través del grafo temporal, leerá su atributo DOM `context-id` para pasarlo a `Graph_Utils.resolveLinkedId(...)`.

*Value Preservation Gate (PAT-E-572):* Mantenemos KISS. En vez de crear stores complejas para el Draft, usamos simple DOM attribute delegation (Top-Down prop drilling) que respeta el ciclo de vida PWA nativo del proyecto.

## 3. Examples
```javascript
// TXSearchable Reading Draft
const contextId = this.getAttribute('context-id'); // e.g. "TAX-8B4K2L"
localSubtitleId = window.Graph_Utils.resolveLinkedId(idVal, sFieldMeta.graphEdgeType, contextId);
```

## 4. Acceptance Criteria
- [x] SubgridBuilder pasa contextId.
- [x] RelationBuilder inyecta contextId.
- [x] TXSearchable usa el DOM attribute.
- [x] No side-effects fuera de un modo Borrador de Taxonomía.
