## 2. What went well / what to improve
**Went well:** 
- La implementación _Top-Down_ para hidratar borradores funcionó sin problemas, respetando el Zero-Trust de `JS_GraphUtils`.
- El flujo de Quality Review y Architecture Review demostró su enorme valía al capturar dos fallas silentes (H9 y H6) que nos llevaron a un refactor inmediato.

**To improve:**
- Cuando modificamos los parámetros que pasan a componentes compartidos (ej. la Factory de la UI), debemos pensar desde el primer instante en la firma de las propiedades. Inyectar `contextId` en un objeto llamado `visualTokens` fue un claro _code smell_.

## 3. Heutagogical Checkpoint
1. **What did you learn?** Que asumir la estructura del DOM (`ion-modal`) en proyectos híbridos y migrados (S25) lleva a errores lógicos. El `UI_DrawerManager` cambió el juego, requiriendo usar también `.drawer-panel`.
2. **What would you change about the process?** Realizar búsquedas exhaustivas (`grep`) sobre cómo se instancian los componentes de nivel superior (como modales/drawers) antes de anclar mi lógica a ellos.
3. **Are there improvements for the framework?** La creación de `UI_FormUtils.extractDraftContext()` centralizó una lógica propensa a errores. Si el proyecto escala, el contexto del borrador debería gestionarse mediante el `AppEventBus` o un Store global local.
4. **What are you more capable of now?** Soy mucho más preciso al identificar inconsistencias semánticas entre capas visuales y lógicas en Web Components puramente nativos.

## 4. Patterns Added / Reinforced
- **Pattern Added:** "Al leer estado de la interfaz desde contenedores modales, soportar simultáneamente `ion-modal` y `.drawer-panel` para mantener compatibilidad con `UI_DrawerManager`."
