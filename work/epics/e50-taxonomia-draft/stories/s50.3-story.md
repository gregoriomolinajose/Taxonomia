# Story: S50.3 (DataGrid y Subgrids Contextuales)

## 1. User Story
**As a** taxonomy creator (admin/manager),
**I want** the taxonomy wizard subgrids to show the relationships I just saved as drafts,
**so that** I can continue editing the taxonomy and see my work-in-progress correctly without missing items.

## 2. Context & Rationale
Currently, the UI's `SubgridBuilder` and `TXSearchable` components read relationships using `window.Graph_Utils`. Since we implemented the Zero-Trust filter in S50.2, all "Borrador" edges are hidden by default unless a `contextId` is passed. This means that if a user saves a step in the wizard, the relations they added disappear from the view. We need to pass the current taxonomy's `contextId` from the active modal to the subgrids so they can hydrate drafts.

## 3. Acceptance Criteria
- [ ] **AC1:** `SubgridBuilder.client.js` inyecta el `contexto_id` (o un flag que permita extraerlo del modal padre) en el componente `TXSearchable` o sus llamadas a `Graph_Utils`.
- [ ] **AC2:** Al cargar un subgrid dentro del Taxonomia Wizard, los elementos marcados con estado "Borrador" pertenecientes a ese `contexto_id` son visibles.
- [ ] **AC3:** Las grillas y subgrids renderizados fuera del contexto del Wizard de edición NO muestran los borradores (mantienen el comportamiento por defecto).

## 4. Specification by Example
*Scenario: Reopening the wizard for an existing draft*
- Given the user has a draft Taxonomy "TAX-1"
- And it has a drafted direct leader "PERS-2" (estado: Borrador, contexto_id: TAX-1)
- When the user opens the taxonomy in the wizard
- Then the "Líder Directo" subgrid correctly fetches and displays "PERS-2" by passing `TAX-1` to `Graph_Utils.resolveAllLinkedIds()`.
