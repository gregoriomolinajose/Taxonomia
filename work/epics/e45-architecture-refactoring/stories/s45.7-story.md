# S45.7: Endurecimiento de Reglas ETL y Priorización de Workspace

## Contexto
Durante el cierre de la estabilización del pipeline ETL (Épica 45), se detectaron varios bordes y casos extremos en el manejo de archivos vacíos, validación de columnas obligatorias y la lógica de sincronización con Google Workspace. Era imperativo ajustar la precisión del motor de validación en el cliente y asegurar la integridad de la información persistida.

## Requisitos y Ajustes Realizados

1. **Gestión Nativa de UI para Archivos Inválidos/Vacíos (Fail-Fast):**
   - **Problema:** El backend lanzaba errores al procesar plantillas en blanco o sin datos útiles, pero el orquestador (`API_Universal_Router`) enmascaraba el error HTTP. Esto causaba un "spinner infinito" y un fallo silencioso en la interfaz, sin feedback visual.
   - **Solución:** Se implementó una trampa de error local (`throw new Error(...)`) dentro del `DataView_UI.client.js` que atrapa el estado `error` del router y marca automáticamente el componente `<ion-input id="etl-drive-url">` con una alerta roja nativa.

2. **Validación Temprana de Columnas Obligatorias:**
   - **Problema:** Un archivo sin la columna `Correo` (o `Email`) se procesaba ciegamente, llenando el reporte de errores en lugar de ser bloqueado desde el inicio.
   - **Solución:** Se añadió un bloque de "Fast-Fail" en `DataEngine_ETL.client.js` para la entidad `Persona`, abortando la operación inmediatamente e informando visualmente que *"El archivo no contiene la columna correo"*.

3. **Extracción de Llaves Agóstica (Case-Insensitive):**
   - **Problema:** Si el usuario ingresaba la columna como `Correo` (C mayúscula), la lógica estricta de extracción (`row.correo`) fallaba, asumiendo que el campo estaba vacío e inyectando un error incorrecto.
   - **Solución:** Se implementó una búsqueda de claves robusta `Object.keys(row).find(k => k.trim().toLowerCase() === 'correo' || k.trim().toLowerCase() === 'email')` garantizando que siempre se capture el correo, sin importar las mayúsculas/minúsculas usadas en la plantilla.
   - **Mensajes Personalizados:** Se asignaron los mensajes exactos solicitados: *"El formato del correo no es valido"* y *"El dominio del correo no es valido"*.

4. **Workspace como Fuente Única de Verdad (Single Source of Truth):**
   - **Problema:** `Job_WorkspaceSync` únicamente sincronizaba la data de Google Directory si la celda original del archivo CSV/Sheet venía completamente en blanco.
   - **Solución:** Se re-definió la política de hidratación. Si Google Workspace (Directorio Activo) contiene información válida para un campo, **siempre** sobreescribirá lo proporcionado en el archivo importado. Se conservó la data del archivo únicamente para los campos que el Directorio arroje como vacíos, permitiendo la captura manual de datos no disponibles corporativamente.

## Criterios de Aceptación Cumplidos
- [x] La interfaz marca el input en color rojo indicando errores como "El archivo no contiene la columna correo" en tiempo real antes de procesar lotes.
- [x] El formato y el dominio del correo se evalúan correctamente ignorando la capitalización del título de la columna.
- [x] Google Workspace sobreescribe proactivamente la información proporcionada en la carga masiva.
