# S45.6: Validación Estricta de Correo en Carga Masiva

## Objetivo
Implementar validación estricta para el campo de correo electrónico durante la carga masiva (ETL), asegurando que ninguna fila se procese si el correo está vacío, si no tiene formato válido, o si su dominio no coincide con la lista blanca permitida por el sistema (variables de entorno).

## Requerimientos
1. **Validación de Campo Vacío:**
   - Si la columna de correo está vacía, la fila debe ser rechazada e informada en el feedback con el mensaje: *"El correo es necesario para realizar un registro"*.

2. **Validación de Formato y Dominio:**
   - El correo debe seguir un formato válido (`user@domain.com`).
   - El dominio debe validarse contra las variables de entorno de la plataforma (`Config.allowedDomains` o donde resida la lógica de dominios autorizados para el inquilino/proyecto).
   - Los correos con dominios no autorizados deben marcarse con error e incluirse en el CSV de resultados con un mensaje descriptivo de *"Dominio de correo no autorizado"*.

3. **Rechazo a Nivel de Fila (Feedback Writeback):**
   - El motor de validación en frontend (`DataEngine_ETL.client.js` o `Engine_ETL`) debe detectar la infracción *antes* de proceder a la inserción en la base de datos o el proceso de Workspace Sync.
   - Estos errores deben sumar a la métrica de fallos y devolver la plantilla original marcada para que el usuario pueda corregirlo.

## Tareas
- [ ] Modificar la función iteradora de ingesta ETL (fase de `dry-run` o parseo) para evaluar la presencia del correo.
- [ ] Conectar la validación de dominio con las variables globales del sistema (`CONFIG` / `environments`).
- [ ] Desplegar y probar inyectando un CSV con correos en blanco, malformados y no permitidos.
