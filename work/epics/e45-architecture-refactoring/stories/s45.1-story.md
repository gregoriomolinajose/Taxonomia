# Story 45.1: Evolución de Motor y UI para Refactorización de Estado (Recomendaciones S44)

## Background
Durante el *Architecture Review* de la Épica E44 y la S44.11 (Sincronización Avanzada de Workspace y Topología Organizacional), se identificaron un par de oportunidades para simplificar y fortalecer la mantenibilidad a largo plazo de los motores backend y la UI generada, adhiriéndonos a las reglas de simplicidad de Beck. 

Esta historia toma esas recomendaciones arquitectónicas como deuda técnica planificada y establece el plan de refactorización proactiva.

## Scope & Heurísticas
Las dos áreas a abordar son:

### 1. Refactor de Estado UI para Procesos Batch (H8)
- **Problema Actual:** El loop recursivo que implementamos en `Schema_Studio_UI.html` para sortear el límite de tiempo de ejecución (cuotas GAS) acumula su propio estado local (`acc = { evaluados, actualizados, sin_resultados }`) e itera llamando a `window.SchemaStudio.triggerWsSync`.
- **Solución Propuesta:** Extraer esta lógica de estado efímero hacia un gestor de Background Jobs genérico (ej. `window.JobManager` o dentro de `JS_Core`). Esto evitará que la UI acople estados lógicos de ejecución y estará disponible para cualquier otro proceso masivo de la plataforma.

### 2. Estabilización de Sufijos y Convenciones Temporales de Workspace (H9 / H8)
- **Problema Actual:** Para evitar el anti-patrón de auto-aprovisionamiento de Cargos en capas externas, interceptamos y limpiamos las cadenas que contienen `" (Por definir)"` vía Regex (`.replace(' (Por definir)', '')`) dentro de `Engine_ETL.js`. Esto soluciona la duplicidad, pero deja una gran responsabilidad a la capa léxica (String parsing) expuesta a renombres humanos que cortan el hilo de mapeo si el registro carece de ID de Workspace. Adicionalmente, el campo `lider_directo` requirió aplicar configuración dura (`uiComponent: "select_single"`) para forzar un pintado que la convención del motor podría derivar nativamente para M:1 o 1:N no temporales.
- **Solución Propuesta:**
  - Sustituir la lógica de regex lexical por una tabla de "Etiquetas Temporales" (Flags) o utilizar un Atributo (`estado_origen: 'virtual'`) nativo en la Entidad para manejar inserciones provisionales, permitiendo al deduplicador operar estrictamente por meta-características puras y evitar depender de cadenas hardcodeadas.
  - Endurecer la Convención Estructural (`Config over Conv` H8) del FormRenderer_UI para que las relaciones jerárquicas directas adquieran un componente de interfaz apropiado por defecto si no están declaradas.

## Acceptance Criteria
- [ ] La UI en `Schema_Studio_UI.html` delega toda recursión y tracking de batch a una pieza lógica centralizada.
- [ ] La consolidación de Cargos en `Engine_ETL.js` utiliza banderas o status explícitos para marcar a los provisionales en vez de manipular Strings.
- [ ] Las Convenciones predeterminadas del FormRenderer prevén automáticamente selectores para Entidades de `relationType: 'padre'` o relaciones estáticas 1:N sin `uiComponent` predefinido.
