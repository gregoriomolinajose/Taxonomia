# S45.4: Mejoras de UX y validaciones en Carga Masiva

## User Story

**Como** Usuario del Sistema
**Quiero** tener un proceso de carga masiva más claro, con validaciones preventivas y una visualización inmersiva del progreso
**Para** evitar errores de formato en la URL, prevenir bloqueos en la interfaz y entender exactamente el avance de la sincronización de datos.

## Acceptance Criteria

- **MUST:** Validar el campo de URL en la carga masiva por Google Sheets. Si la URL no es válida o no corresponde a un archivo de Google Sheets, mostrar un mensaje de validación en rojo: *"La URL proporcionada no corresponde a un archivo de googlesheet valido"*.
- **MUST:** Corregir el comportamiento del botón "Cargar" en el modal. Actualmente, tras ejecutar una carga, el evento `onclick` deja de funcionar. Debe rehabilitarse al cerrar el modal y volver a intentar otra carga masiva (sin necesidad de recargar la página).
- **MUST:** Eliminar la barra de progreso superior actual del modal de carga masiva.
- **MUST:** Al seleccionar "Cargar", se debe limpiar la pantalla actual y mostrar una pantalla dedicada (view) con una barra de progreso inmersiva que muestre el avance de los procesos detonados. Al finalizar la carga, el usuario debe ser redirigido automáticamente a la pantalla de resumen.
- **MUST:** Ajustar la tipografía del botón "Aceptar" (en la pantalla de resumen/carga) para que herede y respete correctamente las convenciones del sistema de diseño (`var(--ion-font-family)`, etc.).

## Notas Técnicas

- Se debe revisar el reseteo del estado del componente de carga masiva (`_resetState` o similar al cerrar/abrir el modal) para habilitar de nuevo el botón "Cargar".
- La vista inmersiva de progreso podría integrarse transicionando a un `<ion-content>` o vista exclusiva en lugar de un overlay parcial, enganchando el `AppEventBus` o el `JobManager` para actualizar el UI.
- Validar mediante Regex el patrón de Google Sheets (`https://docs.google.com/spreadsheets/d/...`).
