# S45.3: Abstracción de Lógica de Auto-Provisionamiento

## User Story

**Como** Arquitecto del Sistema
**Quiero** consolidar la lógica de auto-provisionamiento de `Cargo` y `LiderDirecto` en un helper genérico
**Para** eliminar la duplicación de código (Patrón H10), facilitar el mantenimiento y preparar el terreno para que otros campos relacionales puedan adoptar auto-creación de "stubs" mediante configuración.

## Contexto (Architecture Review)

La revisión de arquitectura (AR) de la historia S45.2 levantó un hallazgo **H10 (Pattern Duplication)**. Las funciones `AutoProvisionCargo` y `AutoProvisionLiderDirecto` comparten un 80% del algoritmo:
1. Precarga optimizada O(1) de catálogo (cache).
2. Iteración sobre el lote de guardado (batch).
3. Verificación de existencia.
4. Generación y almacenamiento de un `stub` temporal para mantener la integridad referencial.

## Acceptance Criteria

- **MUST:** Extraer la lógica común hacia una función interna `_provisionStubs` dentro de `Business_Interceptors.js`.
- **MUST:** Reescribir `AutoProvisionCargo` y `AutoProvisionLiderDirecto` para que invoquen a `_provisionStubs` pasando configuraciones y factorías específicas.
- **MUST:** Validar que el comportamiento O(1) de memoria y el Batch Upsert se mantiene intacto.
