# Story Design: S47.5 - Mapeo de Relaciones Jerárquicas para Capacidades

## What & Why
- **Problem:** Aunque el ETL "aplana" el Excel y asigna internamente a cada registro un ID de su nodo padre (`id_dominio_padre`), esta relación jerárquica no está declarada formalmente en el `Schema_Engine.js` de la aplicación. Por lo tanto, el backend lo ignora y no se guardan las aristas (Edges) en la base de grafos (`Sys_Graph_Edges`).
- **Value:** Al declarar esta relación recursiva explícitamente en el Schema, el sistema "comprenderá" automáticamente la jerarquía y el backend almacenará las aristas. Esto permitirá que los gráficos y árboles interactivos se rendericen inmediatamente al recargar.

## Approach
1. Modificaremos el diccionario `Capacidad` dentro de `src/Schema_Engine.js`.
2. Añadiremos metadatos topológicos: `topological_metadata: { parentEntity: "Capacidad", parentField: "id_dominio_padre" }` (o la nomenclatura estándar para permitir recursividad).
3. Agregaremos explícitamente un campo en el array de fields: `{ name: "id_dominio_padre", type: "relation", targetEntity: "Capacidad", graphEdgeType: "CAPACIDAD_HIJO", ... }`.
4. Nos aseguraremos de que esta configuración siga las mismas convenciones que ya usa la entidad "Dominio" para sus recursiones internas.

## Testing & Examples
**Validación de persistencia:**
1. Tras aplicar el parche, el usuario correrá la carga de Google Sheets.
2. Al finalizar la inserción de las capacidades, revisaremos la tabla `Sys_Graph_Edges`.
3. Verificaremos que contenga registros con `type = "CAPACIDAD_HIJO"`.

**Validación UI:**
Al abrir el mapa E2E (O la sección de árbol de la aplicación), el grafo de capacidades se visualizará correctamente.

## Acceptance Criteria
- **MUST**: `Schema_Engine.js` incluye la declaración del campo relación para `id_dominio_padre`.
- **MUST**: El backend es capaz de guardar los edges recursivamente.
- **SHOULD**: La UI puede consumir estas relaciones exitosamente.
