# S47.1 Implementation Plan: UI File Interception & Offset Parser

## Overview
- **Story:** S47.1
- **Size:** M
- **Date:** 2026-04-28

## Tasks

### T1: Setup DataEngine_ETL_Capacidades & SheetJS
- **Description:** Create the new specialized parser class matching the `processFile` signature, and inject the SheetJS CDN into `Index.html` if not already present.
- **Files:** 
  - `src/Index.html` (add `<script src="https://cdn.sheetjs.com/xlsx-latest/package/dist/xlsx.full.min.js"></script>`)
  - `src/DataEngine_ETL_Capacidades.client.js` (create file and scaffold `processFile`)
- **Verification:** Ensure `window.XLSX` and `window.DataEngine_ETL_Capacidades` exist in the browser console.
- **Size:** S
- **Dependencies:** None

### T2: UI Modal Sniffing Logic
- **Description:** Modify `UI_ETL_Modal.client.js` to intercept the dropped file. Check if `file.name` includes "Modelo de Capacidades". If so, invoke `DataEngine_ETL_Capacidades.processFile` instead of standard ETL.
- **Files:** `src/UI_ETL_Modal.client.js`
- **Verification:** Dropping the specific file triggers a `console.log` from the new parser. Standard CSVs continue to trigger the old parser.
- **Size:** S
- **Dependencies:** T1

### T3: Implement Offset & Fill-Down Logic
- **Description:** Implement `processFile` in `DataEngine_ETL_Capacidades`. Use `XLSX.read` to parse the array, ignore rows 0-4. Use row 5 as headers. Iterate from row 6, applying `lastMacro`, `lastCapacidad`, `lastSubcapacidad` memory variables for blank cells (Fill-Down).
- **Files:** `src/DataEngine_ETL_Capacidades.client.js`
- **Verification:** The final `jsonPayloads` array contains properly flattened objects with no missing parents. Output to `console.log` (Walking skeleton).
- **Size:** M
- **Dependencies:** T1

### T4: Manual Integration Test (E2E)
- **Description:** Open the UI, drag and drop the `Modelo de Capacidades de Grupo 2.0 VF.xlsx` file, and verify in the Developer Tools Console that the array output is clean, properly inherited, and correctly offset.
- **Verification:** Console array matches expectations.
- **Size:** XS
- **Dependencies:** T2, T3

## Execution Order
1. **T1** (Foundation)
2. **T3** (Core logic - Riskiest part, we can unit test it in console before wiring)
3. **T2** (Wiring the UI to the parser)
4. **T4** (E2E Validation)

## Risks & Mitigations
- **Risk:** SheetJS CDN might be blocked by CSP.
  - *Mitigation:* Ensure we test the load of the CDN early in T1. If blocked, we will use a backend Google Apps Script `DriveApp` / `Excel` conversion fallback.
