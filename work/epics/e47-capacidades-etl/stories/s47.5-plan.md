# Implementation Plan: S47.5 - Mapeo de Relaciones Jerárquicas para Capacidades

## Overview
- **Story ID**: S47.5
- **Epic**: E47
- **Size**: XS
- **Goal**: Modificar `Schema_Engine.js` para declarar recursivamente la jerarquía de `Capacidad` utilizando los metadatos topológicos estándar. Esto habilitará la construcción de grafos.

## Tasks

### Task 1: Modificar Schema de Capacidad
- **File**: `src/Schema_Engine.js`
- **Description**: 
  - Añadir la propiedad `topological_metadata` a la definición de `Capacidad` declarando a sí misma como entidad padre y `id_dominio_padre` como el campo principal.
  - Añadir el campo explícito `id_dominio_padre` como tipo `relation` (relationType: "padre") hacia "Capacidad", con el graphEdgeType "CAPACIDAD_HIJO".
  - Añadir un campo explícito virtual `capacidades_hijas` como tipo `relation` (relationType: "hijo") hacia "Capacidad" (para visualización inversa en caso de ser necesario).
- **Verificación**: Correr `npx eslint src/Schema_Engine.js` (si está disponible) o comprobar sintaxis JS válida.
- **Dependencias**: Ninguna.

### Task 2: Validación e Integración Manual
- **Description**: 
  1. Desplegar los cambios a Dev (`npm run deploy:dev:auto`).
  2. Ejecutar la ingesta de Capacidades en el entorno de Dev.
  3. Comprobar que en la UI (en el Tree u Org Chart) se renderizan correctamente las jerarquías de las capacidades (por ejemplo, Capacidad debajo de Macrocapacidad).

## Execution Order
1. Task 1 (Modificación del Schema).
2. Task 2 (Validación E2E Manual).

## Risks and Mitigations
- **Risk**: Que la vista de Tree View no soporte la recursividad porque el `graphEdgeType` no esté soportado.
- **Mitigation**: Mantendremos `isTemporalGraph: true` y usaremos el mismo patrón que las otras entidades jerárquicas como `Dominio` para heredar las implementaciones base.
