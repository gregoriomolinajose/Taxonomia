# S47.2 Implementation Plan

## Overview
Transform the flat `record` payload arrays generated in S47.1 into a deduplicated, hierarchical array of individual nodes using an O(1) Hash Map approach, and assign their topology using `Math_Engine`.

## Tasks

### T1: Build Deduplication Hash Map Algorithm
1. Open `src/DataEngine_ETL_Capacidades.client.js`.
2. Inside `processFile`, after the `for` loop that creates the `record` skeleton, add a new pass or modify the loop to populate a `nodesMap = new Map()`.
3. Construct unique keys for each level (e.g., `M:Nombre`, `C:Macro|||Capacidad`, etc.) to prevent collisions.
4. Extract unique entities (Macro, Capacidad, Subcapacidad, Componente) from each row and store them in the Map.

### T2: Integrate Math_Engine Topology Calculation
1. Create a tracking map `childCounters = new Map()` to track how many children a parent has (to act as `siblingItems` replacement for `Math_Engine.buildOrdenPath`).
2. As each node is added to the `nodesMap`:
    - Determine its `parent_order_path`.
    - Compute its new `_order_path` using `window.Math_Engine.buildOrdenPath` (or inline the logic mathematically to stay O(1) if `buildOrdenPath` forces an array scan). *Wait, `buildOrdenPath` in Math_Engine needs an array of siblings. We might need to feed it a mock array or bypass the array scanning.*
    - *Correction:* To guarantee O(1), we will manually assign the `_order_path` using our `childCounters`, bypassing `buildOrdenPath` array iteration, but we *will* use `window.Math_Engine.buildPathName(parentPathName, currentName)` to reuse name string logic.
3. Build the final flat array of nodes `Array.from(nodesMap.values())`.

### T3: Return Valid Array & Logging
1. Ensure the generated array is logged to console and resolved by the promise, representing the 100% flattened graph.
2. Ensure properties like `_nivel` are casted to numbers and labels match the target taxonomy schema exactly.
