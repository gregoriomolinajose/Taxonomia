# S47.1 Retrospective: UI File Interception & Offset Parser

## Summary
- **Story ID:** S47.1
- **Dates:** 2026-04-28
- **Estimated vs Actual:** 60 mins vs 45 mins.

## What Went Well
- Implementación de la librería nativa SheetJS dentro del frontend (browser-side) funcionó perfectamente y mantuvo la simplicidad de la UI.
- La lógica de herencia (Fill-Down) fue modularizada y contenida independientemente de la lógica core del motor.

## What to Improve
- A futuro, sería ideal separar aún más el manejador de eventos del modal de la interfaz visual para facilitar Unit Testing en `UI_ETL_Modal.client.js`.

## Heutagogical Checkpoint
1. **What did you learn?** Aprendimos a aprovechar `SheetJS` para leer archivos binarios `.xlsx` en el navegador y cómo iterar filas aplicando herencia condicional reseteando los nodos hijos cuando cambia un padre.
2. **What would you change about the process?** Añadir más pruebas unitarias independientes para el parser de arreglos en Node puro antes de inyectarlo en GAS.
3. **Are there improvements for the framework?** Extender el framework de ETL para soportar `processFile` asíncrono nativamente sin depender de callbacks inyectados en la modal.
4. **What are you more capable of now?** Podemos ingerir hojas de cálculo jerárquicas con formato "sucio" (celdas vacías/agrupadas) y aplanarlas dinámicamente con O(N).

## Improvements Applied
- Se aplicó la validación estricta de herencia (resetear subcapacidad cuando cambia la macro) descubierta en la Quality Review (QR) para blindar el modelo de datos contra Excel mal formateados.

## Patterns Added/Reinforced
- Añadido patrón técnico: Utilizar parseo nativo en navegador con librerías JS para archivos pesados/complejos antes de delegar a GAS, reduciendo latencia.
