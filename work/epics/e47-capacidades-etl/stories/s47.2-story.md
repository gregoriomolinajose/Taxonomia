# S47.2: Graph Flattening & Math_Engine Consumption

## User Story
**Como** arquitecto de datos empresariales
**Quiero** que el ETL asigne automáticamente la ruta jerárquica (ej. `1.2.3`) y el nombre compuesto (`PATH: Capacidad / Subcapacidad`) a cada registro ingerido
**Para** asegurar que la base de datos mantenga la integridad topológica (Graph Flattening) sin que yo tenga que teclear IDs manualmente, garantizando un rendimiento óptimo en lotes masivos.

## Acceptance Criteria
1. **Re-utilización (DRY):** Se deben utilizar obligatoriamente las funciones `buildOrdenPath` y `buildPathName` del `Math_Engine` en lugar de reescribir lógica de concatenación.
2. **Hash Cache O(1):** El algoritmo debe indexar temporalmente los nodos procesados en un Map/Diccionario para pasar la referencia de los "hermanos/padres" hacia el `Math_Engine` sin tener que recorrer linealmente todo el arreglo previo en cada iteración (evitando un pico de CPU O(N^2)).
3. **Data Shape Válido:** Cada nodo resultante debe contener las propiedades `_nivel`, `_order_path`, `_path_completo_es`, `_tipo_nodo` calculadas correctamente.
4. **Resiliencia Topológica:** Nodos vacíos o sin padre reconocible deben ser descartados silenciosamente o asignados a la raíz si carecen de contexto.
