# S47.2 Design: Graph Flattening & Math_Engine Consumption

## Context
El archivo Excel de origen viene aplanado, donde cada fila contiene hasta 4 niveles de jerarquía a la vez (Macro, Capacidad, Subcapacidad, Componente). Para que la base de datos de Taxonomía lo digiera, necesitamos **Deduplicar** y **Desenrollar** (Flattening) estos datos en un arreglo unidimensional de entidades individuales de tipo `Capacidades`.

## Technical Approach

### 1. Extracción Topológica (Deduplicación O(1))
Se utilizará un **Hash Map** (`const nodesMap = new Map()`) cuya llave será la ruta jerárquica natural (ej. `Macro|Capacidad|Sub`).
Por cada fila del Excel iterada en el Fill-Down:
1. Extraer/Verificar el Nivel 0 (Macro). Si no existe en el Map, se crea y se asigna un contador de orden.
2. Extraer/Verificar el Nivel 1 (Cap). Si no existe en el Map, se crea como hijo del Nivel 0.
3. Extraer/Verificar el Nivel 2 (Subcap). Si no existe en el Map, se crea como hijo del Nivel 1.
4. Extraer/Verificar el Nivel 3 (Componente). Si no existe en el Map, se crea como hijo del Nivel 2.

Esto convierte una matriz de `N` filas y 7 columnas en un listado de `U` nodos únicos (donde `U <= N * 4`).

### 2. Math_Engine Integration
Para mantener el principio DRY, usaremos `window.Math_Engine.buildOrdenPath(siblingItems, currentNode)` y `buildPathName()`.
Sin embargo, `buildOrdenPath` requiere recibir la lista de hermanos (`siblingItems`). Para lograr O(1) real sin escanear el Map entero, mantendremos otro Hash Map interno temporal `countersByParent` que lleve el conteo de hijos por cada nodo padre, emulando la evaluación del `Math_Engine` pero en memoria.

### 3. Asignación de Data Schema
Cada entidad extraída tendrá la siguiente forma (Schema local):
```javascript
{
  nombre: "Nombre",
  descripcion: "Desc",
  _etiqueta: "Macrocapacidad | Capacidad | Sub capacidad | Componente",
  _tipo_nodo: "Macrocapacidad | Capacidad | Sub capacidad | Componente",
  _nivel: 0 | 1 | 2 | 3,
  _order_path: "1.1.2",
  _path_completo_es: "Macro / Cap / Sub"
}
```

## Security / Edge Cases
- Si un Excel tiene vacíos intermedios (ej. Macrocapacidad -> (vacío) -> Subcapacidad), se romperá el orden estricto. La recomendación es heredar o saltar, pero por ahora se ignorarán nodos intermedios vacíos deteniendo la cadena.
- Los caracteres especiales en los nombres pueden afectar las llaves del Map. Usaremos un delimitador fuerte `|||` para las llaves.
