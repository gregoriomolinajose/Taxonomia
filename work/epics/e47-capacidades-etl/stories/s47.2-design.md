# S47.2 Design: Graph Flattening & Math_Engine Consumption

## Context
El archivo Excel de origen viene aplanado, donde cada fila contiene hasta 4 niveles de jerarquía a la vez (Macro, Capacidad, Subcapacidad, Componente). Para que la base de datos de Taxonomía lo digiera, necesitamos **Deduplicar** y **Desenrollar** (Flattening) estos datos en un arreglo unidimensional de entidades individuales de tipo `Capacidades`. Además, como la ingestión de miles de registros puede causar bloqueos (O(N^2)), debemos inyectar soporte O(1) en el `Math_Engine`.

## Technical Approach

### 1. Augmenting Math_Engine para O(1) (DRY + Performance)
Actualmente, `Math_Engine.buildOrdenPath` recibe un `cache` (Array) y realiza un `find` y un `filter`, lo cual es O(N) por cada invocación. Para grandes volúmenes, la complejidad es O(N^2).
Modificaremos `Math_Engine.buildOrdenPath` para que detecte si `cache` es un **Objeto Estructurado** (ej. `{ nodesById: Map, childrenCount: Map }`) en lugar de un Array.
- Si recibe Array: Mantiene su comportamiento retrocompatible O(N) usando iteradores clásicos.
- Si recibe Maps: Usa `.get()` para recuperar el padre y obtener el máximo contador de hermanos en O(1) absoluto.

### 2. Extracción Topológica en el ETL (Deduplicación O(1))
El ETL iterará las filas y gestionará dos estructuras:
- `nodesMap`: Mapa para deduplicar entidades únicas por su ruta.
- `fastCache`: Objeto `{ nodesById: Map, childrenCount: Map }` que pasará al `Math_Engine`.
Por cada fila del Excel iterada en el Fill-Down:
1. Nivel 0 (Macro), Nivel 1 (Cap), Nivel 2 (Sub), Nivel 3 (Comp).
2. Si el nodo no existe en `nodesMap`, se instancia, se le asocia un ID virtual UUID, y se invoca `Math_Engine.buildOrdenPath(nodo, params, fastCache)`.
3. Tras la invocación, se registra el nodo en `fastCache.nodesById` y se incrementa el contador del padre en `fastCache.childrenCount` de manera estricta para el siguiente nodo.

### 3. Asignación de Data Schema
Cada entidad extraída tendrá la siguiente forma (Schema local):
```javascript
{
  _id: "virtual-uuid",
  nombre: "Nombre",
  descripcion: "Desc",
  _etiqueta: "Macrocapacidad | Capacidad | Sub capacidad | Componente",
  _tipo_nodo: "Macrocapacidad | Capacidad | Sub capacidad | Componente",
  _nivel: 0 | 1 | 2 | 3,
  _order_path: "1.1.2",
  _path_completo_es: "Macro / Cap / Sub"
}
```

## Security / Edge Cases
- Mantendremos la retrocompatibilidad estricta en `Math_Engine` para que el DataGrid y el Formulario estándar no sufran regresiones.
- Usaremos UUIDs efímeros en memoria para mapear `id_dominio_padre` durante la extracción.
