# S47.3 Design: Database Batch Dispatch

## Context
Tras haber aplanado la estructura jerárquica O(1) en la historia previa, ahora debemos enviar estos cientos de registros a la base de datos de App Script para que el modelo persista y la UI lo cargue.

## Technical Approach

### 1. Invocación de DataEngine_ETL
Inyectaremos el método asíncrono `window.DataEngine_ETL._dispatchChunks(finalPayloads, entityName, progressCallback)` justo después del log "Graph Flattening Completado".
- `_dispatchChunks` dividirá el arreglo total (ej. 300 nodos) en baches de 50 registros para evitar el límite de 6 minutos (360s) o bloqueos de carga (Payload Size Limit) en Google Apps Script.

### 2. Gestión de Progreso y UX
`DataEngine_ETL._dispatchChunks` invoca el `progressCallback` con la siguiente firma: `(chunkIndex, totalChunks, isDone, metrics, customText)`.
Redirigiremos este callback hacia `window.UI_ETL_Modal.updateProgress` para que la UI estándar de importación (barra de progreso verde) ofrezca un feedback dinámico en tiempo real.

### 3. Finalización E2E
Dado que `UI_ETL_Modal` actualmente intercepta y no retransmite el evento hacia `DataView_UI` (como ocurre en la importación genérica de CSV), el propio `DataEngine_ETL_Capacidades` será responsable de evaluar la finalización.
Cuando `_dispatchChunks` resuelva su Promesa o cuando el `progressCallback` emita `isDone === true`, invocaremos `window.UI_ETL_Modal.showResults(metrics)` para inyectar la pantalla de éxito con la estadística final de Nodos Insertados.

## Edge Cases
- Si `_dispatchChunks` falla, capturamos el `catch` y lanzamos `showResults` con un objeto de error `{ success: 0, duplicate: 0, error: finalPayloads.length }`.
