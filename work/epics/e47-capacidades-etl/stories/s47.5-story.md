# S47.5: Mapeo de Relaciones Jerárquicas para Capacidades

## Story Description
Como administrador del sistema,
Quiero que el esquema de Capacidades soporte explícitamente relaciones topológicas de "Padre/Hijo",
Para que el motor de renderizado (DataView_Tree, OrgChart) pueda generar el árbol interactivo y los gráficos de agrupación de las capacidades ingeridas por el ETL.

## Context
Actualmente el ETL asigna el \`id_dominio_padre\` en memoria para cada Capacidad para poder aplanar la matriz de Excel. Sin embargo, en el \`Schema_Engine.js\`, la entidad \`Capacidad\` no cuenta con un campo relacional (tipo "relation") que instruya a \`Engine_DB.js\` a persistir los vértices/aristas en la tabla \`Sys_Graph_Edges\`. Sin esta relación, las vistas topológicas en el frontend fallan al no poder reconstruir el árbol jerárquico.

## Acceptance Criteria (Gherkin)

**Scenario 1: Actualización del Esquema Relacional**
- Given que el esquema de la entidad \`Capacidad\` es cargado en la plataforma,
- When se verifica su configuración estructural,
- Then debe incluir el campo relacional \`id_dominio_padre\` apuntando hacia sí mismo (Topología Recursiva).

**Scenario 2: Persistencia de Aristas Topológicas**
- Given que el usuario realiza la Ingesta Masiva de Google Sheets,
- When los registros son procesados y enviados al Backend,
- Then el \`Engine_DB\` debe reconocer el campo relacional e insertar automáticamente las aristas "CAPACIDAD_HIJO" en la base de datos \`Sys_Graph_Edges\`.
