# S51.7: Contextual Hierarchy Builder Design

## Problem & Value
**Problem**: Users need to build relationships between core business entities (Unidad de Negocio, Portafolio, Grupo de Producto) without leaving the Taxonomía workspace, but the standard `workspaceMode` only supports fixed parent relationships.
**Value**: Enhances the Taxonomía workspace by enabling dynamic, multi-tier hierarchy building, reducing context switching and improving UX for portfolio leaders.

## Approach
1. **Schema Enhancements**: 
   - Add three new fields to `APP_SCHEMAS.Taxonomia` in `Schema_Engine.js`: `id_unidad_negocio` (select_single), `portafolios` (searchable_multi), and `grupos_productos` (searchable_multi).
   - Introduce a new schema property `dynamicParentField` for relational fields. This tells the system "my parent ID comes from the value of another field in this same form".
2. **Form Submitter Refactor (`UI_FormSubmitter.client.js`)**:
   - Update `_processTripartiteRelationalField` (or the equivalent logic handling `workspaceMode`) to respect `dynamicParentField`. If present, the `id_nodo_padre` will be extracted from the current form data rather than a fixed ID.
3. **Relation Builder & UI Hydration (`UI_RelationBuilder.client.js` or `DataView_UI.client.js`)**:
   - Ensure the UI correctly hydrates these fields when editing a Taxonomía, reading the edges where `contexto_id` equals the Taxonomía ID.

## Examples
**Schema Definition**:
```javascript
{ name: "id_unidad_negocio", type: "relation", uiComponent: "select_single", targetEntity: "Unidad_Negocio", workspaceMode: true, graphEdgeType: "TAX_UNIDAD" } // Or just stored as plain value if it only acts as anchor
{ name: "portafolios", type: "relation", uiComponent: "searchable_multi", targetEntity: "Portafolio", workspaceMode: true, dynamicParentField: "id_unidad_negocio", graphEdgeType: "UNIDAD_NEGOCIO_PORTAFOLIO", relationType: "hijo" }
```

**Form Submitter Logic**:
```javascript
let parentId = field.fixedParentId;
if (field.dynamicParentField) {
    parentId = formData[field.dynamicParentField];
}
```

## Acceptance Criteria
- **MUST**: Schema_Engine supports `dynamicParentField` to resolve parent IDs at runtime.
- **MUST**: Saving the Taxonomía creates `UNIDAD_NEGOCIO_PORTAFOLIO` edges using the selected Unidad de Negocio and Portafolio.
- **MUST**: Saving creates `PORTAFOLIO_GRUPO_PRODUCTO` edges using the selected Portafolios and Grupos de Productos.
- **MUST**: The edges are saved with the Taxonomía ID as `contexto_id`.
- **MUST**: Re-opening the Taxonomía correctly hydrates the selected entities.
