# Scope: S51.7 Contextual Hierarchy Builder para Taxonomía

## In Scope
- Agregar nuevos campos en el esquema de `Taxonomia` (`Schema_Engine.js`) para "Unidad de Negocio", "Portafolio" y "Grupo de Producto".
- Usar el componente `TXSearch` (probablemente a través de `uiComponent: 'searchable_multi'` o adaptaciones especiales para dependencias en cascada) para la selección de estos elementos.
- Integrar estos campos en un paso adicional (nuevo `Step` en el Wizard/Stepper de Taxonomía).
- Modificar el interceptor de guardado (`FormSubmitter` o interceptor de negocio de Taxonomía) para detectar estas selecciones y generar dinámicamente las aristas de grafo:
  - `UNIDAD_NEGOCIO_PORTAFOLIO` (Unidad de Negocio -> Portafolio)
  - `PORTAFOLIO_GRUPO_PRODUCTO` (Portafolio -> Grupo de Producto)
- Asegurar que estas nuevas aristas se guarden inyectando el `id_taxonomia` actual como `contexto_id`.

## Out of Scope
- Validaciones topológicas extremas en tiempo real si el usuario mezcla ramas incompatibles (se asumirá "happy path" en esta iteración donde la lógica de guardado consolida lo seleccionado).
- Creación de Unidades de Negocio, Portafolios o Grupos de Producto desde cero en el mismo Drawer (solo se permitirá buscar y seleccionar nodos existentes).

## Done Criteria
- [ ] El esquema de Taxonomía cuenta con los 3 nuevos campos de vinculación jerárquica.
- [ ] El Wizard de Taxonomía renderiza un nuevo paso dedicado a "Estructura" o "Jerarquía".
- [ ] Al guardar, el sistema genera las aristas correctas `[UN -> Portafolio]` y `[Portafolio -> GP]` dentro de la base de datos `Sys_Graph_Edges`.
- [ ] El `contexto_id` de dichas aristas corresponde al ID de la Taxonomía donde se realizó la acción.
- [ ] La recarga del formulario re-hidrata correctamente estos campos leyendo desde las aristas contextualizadas.
