# Story Design: S51.8 Visual Taxonomy Builder Canvas

## 1. Context & Objective
The linear stepper approach in the `Taxonomia` form successfully maps a strict 1-to-1-to-N hierarchy but fails to scale when a single Taxonomy needs to map multiple Portfolios, each with isolated, context-aware Product Groups. To support complex N-ary hierarchy building, we will implement a Visual Workspace Canvas similar to the existing Domain and Capacity maps.

## 2. Approach & Strategy
We will extract the "Jerarquía Estratégica" logic out of the main `Taxonomia` creation form and into a dedicated Visual Builder Route (`#taxonomia/canvas/:id`).

1. **Schema Simplification:** The Taxonomia wizard will only request `Nombre`, `Descripción`, and `Unidad_de_Negocio`.
2. **Visual Canvas View:** A new UI view that loads an ECharts Tree, using the `Taxonomia`'s root `Unidad de Negocio` as the initial node.
3. **Interactive Popovers:** Clicking on nodes within the Tree Canvas will summon the standard `TXSearchable` components in a modular popover, allowing users to inject Portfolios into BUs, and Product Groups into Portfolios.
4. **Contextual Edge Routing:** Node additions will trigger background Graph writes injected with `contexto_id` targeting the active `Taxonomia`.

## 3. Architecture Changes

### 3.1. Schema (Schema_Engine.js)
- Remove `id_portafolio` and `grupos_productos` from `APP_SCHEMAS.Taxonomia.fields`.
- Retain `id_unidad_negocio` as the only contextual topological anchor in the Wizard.

### 3.2. Router (UI_Router.client.js)
- Register a new route: `#taxonomia/canvas/:id`.
- Intercept Datagrid actions: When clicking a row in the `Taxonomía` datagrid, users will have the option to "Diseñar Jerarquía" (opens Canvas) or "Editar Metadatos" (opens Drawer).

### 3.3. Canvas Engine (UI_View_TaxonomyCanvas.client.js)
- Build a full-screen layout using `ion-content` and `ECharts`.
- **Node Hydration:** Query `Sys_Graph_Edges` for all edges matching `contexto_id = :id`.
- **Event Listeners:** `chart.on('click', handler)` to intercept clicks on tree nodes.

### 3.4. Edge Mutations (API_Universal.js)
- Provide a minimal backend RPC `upsertContextualEdges` optimized for the Canvas to push specific `id_nodo_padre` + `[id_nodo_hijo_1, id_nodo_hijo_2]` mappings dynamically without needing the full schema payload.

## 4. UI/UX Flow
1. User clicks **"Diseñar Jerarquía"** on a Taxonomía.
2. Fullscreen loads. A central node is shown: **[Unidad de Negocio]**.
3. User clicks the node. A popover asks: *"Vincular Portafolios"*. User selects `Portafolio A` and `Portafolio B`.
4. Tree re-renders with two children.
5. User clicks `Portafolio A`. Popover asks: *"Vincular Grupos de Producto"*. User selects `Grupo 1` and `Grupo 2`.
6. Tree re-renders perfectly mapping groups isolated to their parent portfolios.

## 5. Rollback / Safety
If the canvas approach fails, the database structure (`Sys_Graph_Edges`) remains entirely agnostic. We are only changing the visual ingestion method. No schema migrations are required on the DB level.
