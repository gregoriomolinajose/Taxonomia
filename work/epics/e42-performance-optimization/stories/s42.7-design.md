# Story Design: S42.7 (Actualizada con Recomendación Arquitectónica)

## What & Why
**Problem:** La API de Google tiene un límite físico de 2-6 segundos por petición. Usar loading-screens paraliza la operatividad humana, quebrando la UX dinámica.
**Value:** Una sensación de Zero-Latency (0.01ms) simulada empodera al usuario y hace sentir a la plataforma como una base de datos local súper ligera (Sincronía Background), permitiendo enrutar instantáneamente tras crear registros.

## Approach
Reescribiremos el evento submit en `UI_FormSubmitter.client.js`. 
- Se elimina el componente HTML bloqueante para siempre.
- Si es actualización: Se inyecta al DataStore local y se cierra el Modal al instante. 
- **[RECOMENDACIÓN INCORPORADA]** Si es creación nueva (Insert virgen): El frontend generará un ID temporal "falso" (`TEMP_PK-...`) para la entidad padre e hijos, repintará la interfaz al instante dejándote ver tu nuevo catálogo y navegar, y cuando la promesa de background termine, de fondo, rastreará tu ID Temp local y lo reemplazará silenciosamente por el ID Canónico ("Definitivo") emitido por el servidor.
- Despachamos un `Promise.race` a segundo plano con un `catch()` acoplado a un Callback.
- Si el Callback asíncrono fracasa (ej OCC o Timeout), tomaremos un Snapshot clonado de tu vista justo antes de tu acción y pisaremos el DataStore para "Deshacer" mágicamente el registro falso de tu pantalla.

## Value Preservation Gate (PAT-E-572)
Al despojar la API de la inmediatez visual, ganamos fluidez sin alterar el motor de Persistencia Nuclear (`Engine_DB`). El Backend sigue evaluando reglas en nube, nosotros alteramos la capa cosmética del Front delegando a un robusto motor de Rollbanks y sustitución de PK Tempos.

## Examples

**Generación de Temporary PK y Parche Asíncrono:**
```javascript
// Step 1: Clone snapshot as backup
const stateBackup = JSON.parse(JSON.stringify(window.DataStore.get(this.entityName) || []));

// Step 2: Optimistic UI Patch con TEMP_ID si es creación
let optimisticPK = payload[pkField] || ('LOCAL_TMP_' + Math.random().toString(36).substr(2, 9));
const fakeResponse = { pk: pkField, pkValue: optimisticPK, data: {} };
this._patchFrontendCache(this.entityName, fakeResponse, payload);
window._closeTopModal(); // Instante: Cero Bloqueos, Enrutamiento Liberado

// Step 3: Fire and forget
this.apiService.call(action, entity, safePayload).then(response => {
     if(response.error) throw new Error(response.error);
     // Reconciliación Silenciosa: Reemplazar LOCAL_TMP con Server ID
     this._reconcileTemporaryId(this.entityName, optimisticPK, response.pkValue);
     this._showToast("✔ Sincronizado");
}).catch(e => {
     // Rollback inminente!
     window.DataStore.set(this.entityName, stateBackup);
     window.AppEventBus.publish('DATA::UPDATED', { entityKey: this.entityName });
     this._showToast("❌ Error al guardar. Revirtiendo..", 'danger');
});
```

## Acceptance Criteria
- **MUST** Inyectar valores simulados en el Data Store instantáneamente antes del envío.
- **MUST** Ocurrir sustitución transparente de Temporary PKs (Swapping) en segundo plano para registros nuevos.
- **MUST** Cerrarse la ventana asincrónicamente e invocar navegación nativa como si el guardado fuese inmediato.
- **MUST** Ocurrir un Repintado Inverso (Deshacer) si el servidor tira Error.
