# Story S42.6: Limpieza Quirúrgica de Ghost Records (Rollback Prevencion)

**As a** Usuario Final
**I want** que si el backend falla transaccionalmente, o si la red es lenta, la UI no duplique registros visuales
**So that** mi experiencia Optimista (Local-First) permanezca integra de fallas fantasmas.

### Acceptance Criteria
- [x] Adición de `_optimistic_session` tracking tag a entidades forjadas en cliente.
- [x] Reversión automática de Caché Temporal cuando la latencia exceda el Time-box (25s) y emita "Falla de red severa".
- [x] Limpieza atómica antes de proceder a the "Backend Hydration Phase".
