# Story: Async Job Processing

## User Story
As a user performing large data imports,
I want the data processing to happen asynchronously in the background,
so that my browser does not freeze or timeout during massive uploads (>10k rows).

## Acceptance Criteria

### Scenario: Mass upload initiates background job
```gherkin
Given a user submits a file with 10,000 rows
When the backend receives the payload
Then the system should enqueue an asynchronous job
And return a job ID immediately to the frontend
```

### Scenario: Job processes in chunks
```gherkin
Given a queued job with thousands of rows
When the backend worker executes the job
Then it should process the rows in chunks to respect Google Apps Script execution time limits
And update the job status (e.g. progress percentage, completed rows)
```

### Scenario: Frontend polls job status
```gherkin
Given the frontend has received a job ID
When the frontend polls for the job status
Then it receives the current progress and status (PENDING, PROCESSING, COMPLETED, FAILED)
```

## Examples (Specification by Example)

| Input | Action | Expected Output |
|-------|--------|-----------------|
| 10,500 rows CSV | Submit import | Returns Job ID, UI shows "Processing" loader, finishes in background. |
| Job ID `job_123` | Poll status | Returns `{status: "PROCESSING", processed: 5000, total: 10500}` |

## Notes
- See ADR-061 and ADR-062 for ETL architecture context.
- Dead Letter Queue (DLQ) data structure must be populated by the job, but the UI for it is deferred to S61.5.
- Beware of GAS 6-minute quota.
