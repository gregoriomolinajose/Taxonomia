# S61.15 Design: Intra-batch Deduplication Bugfix

## Approach
To address the bug where intra-batch duplicates lacking UUIDs are treated as new records by the database adapter, we will:
1. Detect when a `matchedRow` lacks a `pkField`. This indicates it is a newly inserted row in the same batch.
2. In this case, we merge the duplicate payload properties into the matched row.
3. We assign a flag `_dropFromBatch = true` to the redundant payload so that it gets discarded before batch insertion.
4. Filter out any items with `_dropFromBatch` set to `true` before the function returns the data.

## Components Affected
- `Engine_ETL.js`:
  - `hydrateAndDeduplicate` function: Identity resolution loop and final batch filtering.

## Key Decisions
- Flagging duplicates with `_dropFromBatch` prevents modifying the array in place during iteration, which is safer and easier to maintain.
- `Object.assign(matchedRow, payload)` correctly merges information, giving precedence to later records while keeping the primary record object instance.
