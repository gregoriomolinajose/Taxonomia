## Rationale
Since this is an XS story involving a simple check within a single function, the implementation and its unit tests are grouped into one atomic task. The integration test is strictly required as the final step to ensure the Error propagates correctly in the deployed environment. There are no circular dependencies. Risk-first approach is handled by doing the core logic early.

## Risks & Mitigations
- **Risk**: Modifying the overlap logic could inadvertently block valid spreadsheets with few matching columns.
- **Mitigation**: The check explicitly uses `maxOverlap <= 0`, meaning *zero* columns matched. As long as at least one column matches (`maxOverlap > 0`), the pipeline will continue. The unit test must verify the failing condition without breaking existing tests.
