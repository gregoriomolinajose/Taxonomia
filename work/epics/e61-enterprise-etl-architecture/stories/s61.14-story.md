# S61.14: ETL Job Mutex Lock

## User Story
**As a** system worker executing ETL jobs
**I want** to exclusively claim a pending job using a cache-based mutex
**So that** concurrent triggers or UI pulses do not process the same job multiple times and cause race conditions.

## Acceptance Criteria
- Given a `job` is fetched from `JobQueue.getPendingJob()`,
- When the script attempts to claim it before updating its status to PENDING,
- Then it checks `CacheService.getScriptCache()` for a key `'JOB_LOCK_' + job.jobId`.
- And if the key exists, the process releases the `LockService` lock and returns early with `{ debug: "job_already_processing" }`.
- And if the key does not exist, the process writes `"1"` to the cache for that key with an expiration of 240 seconds.
- And after the job is completely processed or fails, a `finally` block removes the lock from the cache.
