# Story S61.5: Dead Letter Queue (DLQ)

## As a
Data Admin

## I want to
View a temporal table containing rows that threw errors during asynchronous ingestion, along with an interface to manually resolve these conflicts.

## So that
I can correct erroneous data without having to re-upload the entire massive load file and prevent data loss during background processing.

## Acceptance Criteria
- Given an asynchronous ETL job that encounters validation or processing errors for specific rows
- When the job finishes processing
- Then those erroneous rows should be saved in a temporary DLQ (Dead Letter Queue) table.
- And the UI should display a specific view/modal that lists these conflicting rows with their error metadata.
- And I should be able to edit and re-process the rows directly from the UI.
