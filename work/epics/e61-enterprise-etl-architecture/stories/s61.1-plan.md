## Execution Order & Rationale
1. **Task 1 (Interface & Mock)**: Establishes the core contract and allows us to verify the abstraction works in memory without dealing with platform-specific APIs.
2. **Task 2 (Real Adapter & Engine Refactor)**: Replaces the concrete implementation in the engine with the new contract. This is the main refactoring effort and is riskier, but relies on the contract from Task 1.
3. **Task 3 (Manual Integration)**: Validates that the Google Apps Script environment still works correctly after the abstraction. Deployment and manual test are required to ensure the real spreadsheet API interactions are valid.

## Risks and Mitigations
- **Risk**: `GoogleSheetsProvider` might miss some nuanced behavior of `SpreadsheetApp` that the `ETLEngine` implicitly relied on.
- **Mitigation**: Task 3 explicit manual integration testing with real spreadsheets. TDD will ensure the logic behaves as expected for standard records.
- **Risk**: Dependency injection might be tricky if `ETLEngine` is deeply coupled.
- **Mitigation**: Update tests for `ETLEngine` to use `MockDataProvider` to ensure DI works smoothly.
