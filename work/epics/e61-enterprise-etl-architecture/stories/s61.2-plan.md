# Story Plan: S61.2 (Metadata Hooks Engine)

## Overview
- **Story ID:** S61.2
- **Size:** S (Moderate)
- **Date:** 2026-07-08

## Tasks

### Task 1: Update Schema_Engine.js
- **Description**: Add `etlHooks` configuration for the `Dominio` entity, containing the `onRowTransform` method that maps legacy header names (e.g., 'nivel subdominio') to standard DB properties (e.g., 'nivel_tipo').
- **Files**: `src/Schema_Engine.js`
- **Verification**: `npx vitest run`

### Task 2: Refactor ETLEngine.js
- **Description**: Update the `extractData` method in `ETLEngine.js` to iterate over raw records and invoke `schema.etlHooks.onRowTransform(row)` if defined. Ensure the original behavior of returning rows is preserved if no hook is defined.
- **Files**: `src/core/ETLEngine.js`
- **Verification**: `npx vitest run`

### Task 3: Refactor Engine_ETL.js
- **Description**: Remove the hardcoded `if (entityName === 'Dominio')` conditional block inside the `extractDriveData` method of `Engine_ETL.js`.
- **Files**: `src/Engine_ETL.js`
- **Verification**: `npx vitest run`

### Task 4: Manual Integration Test
- **Description**: Desplegar a DEV y realizar una importación masiva de prueba de un Excel de "Dominio" para verificar que las columnas siguen mapeándose correctamente al pasar por el frontend y llegar a BD sin perder los campos 'nivel_tipo', 'orden_path', 'descripcion', etc.
- **Verification**: Manual upload in the UI.

## Execution Order
Task 1 -> Task 2 -> Task 3 -> Task 4 (Sequential)

## Risks & Mitigations
- **Risk**: Breaking existing Dominio imports.
- **Mitigation**: We will manually test the import process using the exact headers mapped in the new hook before merging.
