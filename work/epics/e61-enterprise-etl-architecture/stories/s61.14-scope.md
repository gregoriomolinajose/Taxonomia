# S61.14 Scope

## In Scope
- Implementing cache-based mutex logic in `processNextJobChunk()` to prevent concurrent processing of the same job.
- Creating the lock key using the `job.jobId`.
- Returning `{ debug: "job_already_processing" }` when a lock is hit.
- Removing the lock from the cache in the `finally` block at the end of the process.
- Updating both `src/Job_Worker.js` and `packages/core/src/Job_Worker.js` if the latter exists.

## Out of Scope
- Changes to the underlying JobQueue fetching mechanism.
- Changes to other worker functions outside of `processNextJobChunk()`.

## Done when:
- Cache mutex is acquired successfully before job processing begins.
- Lock is cleared successfully after job completes (or fails).
- Concurrent threads correctly abort if they hit an existing cache lock.
- Tests (if any applicable) pass.
