### Recommended (simplify before next cycle)
- `src/Job_Worker.js:98` and `src/Job_Worker.js:241`: [H10] Pattern Duplication. The exact same logic block for building DLQ error records (`id_dlq`, `job_id`, `estado`, `error_message`, `payload`) and appending to `chunkFeedback` is duplicated in two separate catch blocks (one for `hydrateAndDeduplicate` errors, one for `upsertBatch` errors). This should be extracted into a pure helper function (e.g. `_buildDlqErrorRecords(chunk, error, job, entityName)`) to reduce boilerplate and ensure future schema changes are applied consistently.

The manually generated ID uses `"DLQ-" + new Date().getTime()` instead of matching the `SDLQ` prefix officially registered in `APP_SCHEMAS.Sys_DLQ`. ¿Hay alguna limitación en el `Adapter_Sheets.upsertBatch` para no delegarle la creación del ID vía `lexical_id` estándar, o deberíamos al menos usar el prefijo oficial `SDLQ`?
