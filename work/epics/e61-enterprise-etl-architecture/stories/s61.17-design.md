# Story S61.17: Fail-fast Validation UI Integration

## Technical Design

### Objective
Ensure that if a schema validation error ("Formato Estricto Incompatible") is thrown during extraction, it is displayed immediately on the URL input field without transitioning the user to the progress wizard.

### UI Component Updates (`UI_Component_BulkImporter.client.js`)

1. **Defer Progress Wizard Transition**
   Currently, `_defaultDriveSync` calls `updateProgress` immediately. This needs to be deferred until the API call `etl_extract_sheet_data` resolves successfully.

2. **Loading State**
   While waiting for the API call (which can take a few seconds), the `#btn-sync-drive` button must show a loading spinner and text `Validando...` to provide visual feedback.

3. **Safe Progress Injection**
   The `updateProgress` method previously overwrote `this.containerNode.innerHTML`, completely destroying the form DOM. This meant that on error, restoring the form or selecting the `urlInput` would fail (returning `null`).
   The fix is to wrap the progress UI in a `.etl-progress-wrapper`, and instead of overwriting, we just set `display: none` on the original children of the container, appending the new wrapper.

4. **Error Handling & Reversion**
   In the `catch` block of `_defaultDriveSync`:
   - Restore the button state.
   - Remove the `.etl-progress-wrapper` and un-hide the original children if they were hidden.
   - Detect `err.message.includes('Formato Estricto Incompatible')`.
   - Set the `error-text` on `#etl-drive-url` to: `"El archivo ingresado no coincide con el formato de la plantilla para '[Entidad]'"`
   - Add `ion-invalid` and `ion-touched` classes to the input.
