# Story S61.2: Metadata Hooks Engine - Design

## What & Why

**Problem:** El motor `Engine_ETL.js` contiene reglas de negocio *hardcodeadas* (como el mapeo de columnas históricas de `Dominio`), violando el principio de responsabilidad única (SRP) y limitando la escalabilidad del sistema ETL para nuevas entidades.
**Value:** Al extraer estas reglas al `Schema_Engine.js` usando un sistema de *hooks*, el motor de ingesta se vuelve genérico. La inteligencia del dominio residirá exclusivamente en su esquema.

## Approach

Implementar un ciclo de vida en el pre-procesamiento del `ETLEngine`.

**Componentes Afectados:**
- `src/Schema_Engine.js` [MODIFY]: Añadir propiedad `etlHooks: { onRowTransform }` a la entidad `Dominio`.
- `src/Engine_ETL.js` [MODIFY]: Eliminar las condicionales estáticas `if (entityName === 'Dominio')`.
- `src/core/ETLEngine.js` [MODIFY]: Implementar invocación de `onRowTransform` en los datos extraídos para estandarizar las llaves (keys) de los objetos antes de pasarlos a BD.

**Estrategia:**
El `GoogleSheetsProvider` extrae los datos usando los encabezados reales de la hoja. El `ETLEngine`, al recibir el arreglo de registros, llamará a `schema.etlHooks.onRowTransform(record)` por cada registro. El hook de `Dominio` se encargará de mutar el objeto, mapeando las propiedades con nombres de encabezados históricos (ej. "nivel subdominio") a los campos esperados por la DB ("nivel_tipo").

**Missing-entity strategy (PAT-E-523):**
Si el esquema de la entidad a cargar no existe, la operación fallará devolviendo un error (Comportamiento existente mantenido). Las filas sin llaves mapeables simplemente perderán esas propiedades silentes y fallarán luego en el `ValidationEngine` si son campos obligatorios.

## Examples

**Schema Definition (`Schema_Engine.js`):**
```javascript
APP_SCHEMAS.Dominio = {
    // ...
    etlHooks: {
        onRowTransform: function(row) {
            const rawKeys = Object.keys(row);
            rawKeys.forEach(k => {
                let lowKey = k.toLowerCase().trim();
                if (lowKey === 'nivel subdominio') { row['nivel_tipo'] = row[k]; delete row[k]; }
                else if (lowKey === 'orden. subdominio' || lowKey === 'orden') { row['orden_path'] = row[k]; delete row[k]; }
                else if (lowKey === 'subdominio') { row['nombre_ingles'] = row[k]; delete row[k]; }
                else if (lowKey === 'nombre español' || lowKey === 'nombre espanol') { row['nombre'] = row[k]; delete row[k]; }
                // ...
            });
            return row;
        }
    }
};
```

**ETLEngine Invocation:**
```javascript
class ETLEngine {
    extractData(entityName) {
        let rawRecords = this.provider.read(entityName);
        const schema = getAppSchema(entityName);
        
        if (schema && schema.etlHooks && typeof schema.etlHooks.onRowTransform === 'function') {
            rawRecords = rawRecords.map(row => schema.etlHooks.onRowTransform(row));
        }
        return rawRecords;
    }
}
```

## Acceptance Criteria

- **MUST**: `Engine_ETL.js` no debe tener referencias fuertes a entidades específicas (ej. `Dominio`).
- **MUST**: El `ETLEngine` debe ejecutar `onRowTransform` (si existe) en los registros importados.
- **MUST**: La importación actual de `Dominio` no debe romperse; debe seguir mapeando correctamente.
