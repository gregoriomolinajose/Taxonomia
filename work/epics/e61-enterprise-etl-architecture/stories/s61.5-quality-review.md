## Quality Review: S61.5

### Critical (fix before merge)

1. **Security Vulnerability - Missing Authorization (API Audit):** 
   - **File:** `src/API_Universal.js:126` (`dlq_reprocess`)
   - **Why:** The new `dlq_reprocess` endpoint allows injecting arbitrary JSON payloads into the database but completely lacks ABAC authorization checks. Unlike `etl_extract_sheet_data`, it skips `_guardAbac`. Any user can bypass permissions.
   - **Fix:** Add `if (typeof _guardAbac === 'function') { _guardAbac('update', targetEntity, null); }` at the beginning of the block.

2. **Semantic Bug - Uncaught ReferenceError:** 
   - **File:** `src/API_Universal.js:143` 
   - **Why:** The code calls `SchemaUtils.getPrimaryKey(targetEntity);` but the utility class is named `JS_SchemaUtils` (or `APP_SCHEMAS`). This will throw a runtime `ReferenceError`, preventing any DLQ row from being re-processed.
   - **Fix:** Change `SchemaUtils` to `typeof JS_SchemaUtils !== 'undefined' ? JS_SchemaUtils.getPrimaryKey(targetEntity) : ...`.

3. **Error Handling - Swallowed Exception (Data Loss):** 
   - **File:** `src/Job_Worker.js:253`
   - **Why:** When persisting new DLQ errors to `Sys_DLQ` using `Engine_DB.upsertBatch`, any failure is caught and silently logged (`catch (dlqErr) { Logger.log(...) }`). The job continues and marks itself as `COMPLETED`. The DLQ records vanish forever, defeating the entire purpose of the story.
   - **Fix:** Remove the broad catch or ensure the job status accurately reflects a failure to persist to the DLQ (e.g., throwing the error or pushing the job to a failed state).

### Recommended (improve code quality)

1. **Test Muda (Waste):**
   - **File:** `scratch/test_import.js` and `scratch/test_import_existing.js`
   - **Why:** These files are scratch scripts using `console.log` rather than actual automated tests. They fail the *Mutation Survival* heuristic completely (they never fail regardless of code behavior). 
   - **Fix:** Convert them to proper `vitest` unit tests with assertions (`expect()`), or delete them.

### Observations (no action needed)

- **Job Worker Chunk Failure:** In `src/Job_Worker.js:115`, if the `Engine_ETL.hydrateAndDeduplicate` interceptor pipeline throws a fatal exception, the *entire chunk* (up to 50 rows) is dumped into the DLQ. This is acceptable for preventing worker deadlock, but means one severely malformed record will drag down 49 healthy records alongside it.
- **Hardcoded State Check:** In `src/Adapter_Sheets.js:495`, `_isNodeLogicallyDeleted` relies on a hardcoded string `'Eliminado'` to check logical deletions. This works for current schemas, but might be fragile if states change.
