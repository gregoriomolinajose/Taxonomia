### T1: Scaffold Engine_Validation & Base Structure
- **Description:** Create the `ValidationEngine` module and write tests for basic schema field presence (required fields validation).
- **Files to modify:**
  - `src/Engine_Validation.js` (create)
  - `tests/Engine_Validation.test.js` (create)
- **TDD Cycle:** Write failing test for missing required field -> Implement basic check using `APP_SCHEMAS` logic -> Refactor.
- **AC Reference:** AC1 (ValidationEngine validates data against corresponding schema in APP_SCHEMAS)
- **Verification:** Run unit tests (`npm run test` or equivalent).

### T2: Type & Format Validation Logic
- **Description:** Implement validation for specific data types and formats (e.g., email, dates) based on schema definitions.
- **Files to modify:**
  - `src/Engine_Validation.js`
  - `tests/Engine_Validation.test.js`
- **TDD Cycle:** Write failing tests for invalid types/formats -> Implement type checking rules -> Refactor.
- **AC Reference:** AC1, AC2
- **Verification:** Run unit tests.

### T3: Response Standardization & Partial Validation
- **Description:** Ensure the engine returns a standardized response `({ isValid, errors, validatedData })` and supports partial validation logic.
- **Files to modify:**
  - `src/Engine_Validation.js`
  - `tests/Engine_Validation.test.js`
- **TDD Cycle:** Write failing test expecting standardized response and partial validation -> Implement response formatting -> Refactor.
- **AC Reference:** AC2
- **Verification:** Run unit tests.

### T4: Manual Integration Test
- **Description:** Integrate `ValidationEngine` with existing mock/real UI or ETL scripts to manually verify end-to-end functionality using actual `APP_SCHEMAS`. Ensure the standard GAS deployment flow is followed if testing on Google Apps Script environment.
- **Files to modify:** N/A (Manual testing / Execution only)
- **TDD Cycle:** N/A
- **AC Reference:** AC1, AC2, AC3
- **Verification:** Validate that valid/invalid data behaves as expected in the UI/ETL flow.

## Rationale
The execution order follows a logical progression from establishing the basic structure to adding complex logic, finishing with standardizing the output and integration testing. Since it's a single core module, tasks are strictly sequential.

## Risks & Mitigations
- **Risk:** `APP_SCHEMAS` structure might be too complex or inconsistent for a generic validation engine.
  - **Mitigation:** Focus on supporting the most common rules first (required, type, basic formats).
- **Risk:** Differences between local testing and Google Apps Script execution.
  - **Mitigation:** Ensure pure JS logic without environment-specific dependencies in the core `ValidationEngine`.
