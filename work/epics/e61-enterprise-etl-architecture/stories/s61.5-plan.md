# Plan de Implementación: Reglas de Negocio en ETL Desacoplado

## Objetivo

Restaurar y estandarizar la ejecución de reglas de negocio complejas (conexión a Workspace, descubrimiento de linaje, generación de aristas M:N) dentro del nuevo motor ETL asíncrono, asegurando que sea una arquitectura escalable, reutilizable para cualquier entidad y de grado empresarial.

## Análisis del Problema

Durante el refactor de desacoplamiento del motor ETL (Epic 61), se eliminó la lógica condicional "dura" (`if (entityName === 'Persona')`) que estaba incrustada directamente en `Engine_ETL.js`. Esto provocó que:
1. La entidad principal no consultara el directorio de Google Workspace para auto-rellenar los datos faltantes (Nombre, Cargo, Líder Directo, etc.).
2. Al no tener el campo de *Líder Directo* en memoria (porque el CSV no lo traía y Workspace no lo rellenó), el interceptor `AutoProvisionLiderDirecto` no se ejecutó.
3. Lo mismo ocurrió con los cargos y roles ágiles; el pipeline subsiguiente falló por falta de datos.

## Propuesta de Arquitectura Empresarial (Pipeline Pattern)

Para mantener el motor ETL agnóstico y escalable, implementaremos el **Patrón Interceptor / Pipeline**.
En lugar de tener reglas escritas en el motor de base de datos, cada entidad declarará su "tubería de procesamiento" en el `APP_SCHEMAS`.

El motor ETL simplemente pasará los datos por la tubería definida.

Para la entidad `Persona`, el flujo será:
1. **Deduplicación:** (Ya implementado) Evita registros duplicados y enlaza el ID con la DB existente.
2. **Interceptor: `HydrateWorkspace` (NUEVO):** Llama a la API de Google Workspace. Si el correo existe, rellena los campos vacíos (Nombre, Centro de Costos, Cargo, Líder Directo, etc.).
3. **Interceptor: `AutoProvisionCargo`:** Toma el campo "Cargo" (ahora rellenado), verifica si existe en la base de datos de cargos, y si no, genera el registro y la relación `CARGO_PERSONA`.
4. **Interceptor: `AutoProvisionLiderDirecto`:** Toma el correo del "Líder Directo" (ahora rellenado), consulta Workspace de manera recursiva, dibuja el árbol de liderazgo hacia arriba y genera las aristas `PERSONA_LIDER_DIRECTO`.
5. **Interceptor: `AutoLinkAgileRoles`:** Crea las aristas para Dueño de Producto, Team Coach, etc.
6. **Provisión Relacional (Automática):** Genera `PERSONA_TAXONOMIA`, `PERSONA_ROL`, `PERSONA_EQUIPO`, etc.
