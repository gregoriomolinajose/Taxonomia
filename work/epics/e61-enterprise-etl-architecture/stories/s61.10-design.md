# S61.10 Design: ETL Pipeline Enhancements

## Problem & Value
**Problem:** The `getDataRange().getDisplayValues()` method in Google Apps Script parses formats for thousands of empty rows due to Data Validation rules applied during template generation. This causes ETL pipelines to take minutes to load, even for small datasets.
**Value:** By implementing 'Acotamiento de Rango Real' (bounding the true data range), we reduce ETL extraction times from minutes to seconds, significantly improving the ETL administrator experience.

## Approach
**Solution Approach:** 
We will modify the extraction logic to first fetch raw `getValues()` (which is fast), scan backward to find the true last row with text content, and then execute the expensive `getDisplayValues()` exclusively for that bounded subset.

**Components Affected:**
- `src/Engine_ETL.js` (modify): Update `extractDataFromDrive` to perform bounded range extraction instead of using `getDataRange().getDisplayValues()` directly.

**Missing Entity Strategy:** 
Not applicable for data extraction logic, as this story focuses on reading optimization, not data mutation. (Any business rules are applied later in the pipeline).

**Value preservation gate (PAT-E-572):**
The domain logic around sheet selection and column matching is fully preserved. We are strictly optimizing the physical cell reading operation.

## Examples

**API/CLI usage & Algorithm:**
Instead of extracting the full `getDataRange().getDisplayValues()` immediately:

```javascript
// Current inefficient code:
// const data = sheet.getDataRange().getDisplayValues();

// Optimized bounded approach:
const rawDataRange = sheet.getDataRange();
const rawValues = rawDataRange.getValues();

let trueLastRow = 0;
for (let r = rawValues.length - 1; r >= 0; r--) {
    if (rawValues[r].some(cell => cell !== "")) {
        trueLastRow = r + 1;
        break;
    }
}

if (trueLastRow < 2) {
    throw new Error("La hoja de cálculo está vacía o carece de registros.");
}

const data = sheet.getRange(1, 1, trueLastRow, rawDataRange.getNumColumns()).getDisplayValues();
```

## Acceptance Criteria
- **MUST**: The extraction process only calls `getDisplayValues()` on rows containing actual data.
- **MUST**: A real Google Sheet with 1000 validation rows but few data rows processes in seconds (PAT-E-539: Real infrastructure testing).
- **MUST**: Throws an error correctly if no data exists.
