## What went well / What to improve
- **Went well**: Discovered and bypassed a severe limitation in Ionic v7 Shadow DOM when attempting to use Glassmorphism effects for ETL loaders. Bypassing the native framework element with a native HTML `div` on the Light DOM resulted in an elegant fix.
- **To improve**: Design phase should ideally catch UI framework limitations regarding Shadow DOM encapsulation before implementation. We should avoid relying on `<ion-loading>` when we want complete control over the aesthetics and background filters.

## Heutagogical Checkpoint
1. **What did you learn?**
   Ionic's overlay components (like `<ion-loading>`) severely restrict HTML structure via `message` sanitization and encapsulate their backdrop in the Shadow DOM, which blocks custom backdrop-filters from affecting the whole screen in some scenarios.
2. **What would you change about the process?**
   Early prototyping of complex UI elements (like glassmorphism) should be done natively to detect framework encapsulation blockers sooner.
3. **Are there improvements for the framework?**
   Establish a new design rule: avoid Ionic's overlay components when rich custom HTML injection is required. Use native Light DOM components orchestrated via `UI_Factory`.
4. **What are you more capable of now?**
   More capable of identifying when to abandon an encapsulated framework component in favor of a native DOM solution for the sake of Enterprise-grade UI quality (KISS principle).

## Improvements Applied
- Extracted the custom loader markup into a reusable `window.UI_Factory.showPremiumLoader(message)` utility.
- Applied the new utility across 5 points of duplication in `UI_Component_BulkImporter.client.js` and `DataView_UI.client.js`.

## Patterns Added / Reinforced
- **Added**: Avoid Ionic overlay components (ion-loading, ion-alert) when injecting complex HTML/CSS (like glassmorphism) due to Shadow DOM sanitization; use Light DOM div wrappers instead. (Technical)
