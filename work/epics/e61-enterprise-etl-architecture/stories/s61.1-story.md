# Story: IDataProvider Interface

## User Story
As a developer,
I want an IDataProvider interface that abstracts Google Sheets from the main ETL engine,
so that I can test the core logic in memory and easily support new data sources in the future.

## Acceptance Criteria

### Scenario: Reading data through adapter
```gherkin
Given a configured GoogleSheets adapter implementing IDataProvider
When the ETL engine requests to read data
Then the adapter returns standard records without the engine knowing about SpreadsheetApp
```

### Scenario: Testing in memory
```gherkin
Given a MockDataProvider implementing IDataProvider
When the ETL engine runs a test suite
Then it processes the data correctly entirely in memory without Google Apps Script dependencies
```

## Examples (Specification by Example)

| Input | Action | Expected Output |
|-------|--------|-----------------|
| Spreadsheet context | `provider.read('Sheet1')` | Standardized array of objects |
| Standardized records | `provider.write('Sheet2', records)` | Data is written to the physical sheet |
| In-memory array | `mockProvider.read('Entity')` | Standardized array of objects returned |

## Notes
- See ADR-061: Uso de IDataProvider para abstraer orígenes de datos.
- Goal: El sistema lee/escribe sin hacer llamadas explícitas a `SpreadsheetApp` en el core.
