# Design: S61.3 Centralized Validation

## 1. Complexity Assessment
- **Components**: 1-2 (`Engine_Validation.js`)
- **Story Points**: Moderate
- **External Integrations**: None (uses internal schemas)
- **Algorithm Complexity**: Custom schema traversal and validation rules.
- **Verdict**: Moderate. Core sections implemented.

**Risk/UX/Integration Gates**: Evaluated. Integration tests with actual schemas from `APP_SCHEMAS` will be needed.

## 2. What & Why
- **Problem**: We lack a unified, schema-driven validation approach for both data ingestion and UI inputs, leading to duplicated logic or inconsistent validation.
- **Value**: A centralized `ValidationEngine` reduces technical debt, ensures consistent data integrity, and provides standardized error formats everywhere.

## 3. Approach
- **Solution**: Implement `Engine_Validation.js` exposing a central `ValidationEngine` object with methods like `validate(row, schemaName)` which leverages rules derived from `APP_SCHEMAS`.
- **Missing Entity Strategy**: If a row references a missing entity (e.g., in a foreign key or lookup), the engine will reject the field with a specific validation error, reporting partial success for the rest of the valid row data.
- **Components Affected**:
  - `src/Engine_Validation.js` (create)
  - `tests/Engine_Validation.test.js` (create)
- **Value preservation gate**: Domain intelligence (the schema rules) is preserved. The generic validation engine allows mapping custom rules based on our specific `APP_SCHEMAS` structure.

## 4. Examples

### Scenario: Validating a correct row
```javascript
const schemaName = 'Employee';
// Assuming APP_SCHEMAS['Employee'] has a required 'email' field of type 'email'
const row = { name: 'John Doe', email: 'john@example.com' };

const result = ValidationEngine.validate(row, schemaName);
// Expected output:
// {
//   isValid: true,
//   errors: [],
//   validatedData: { name: 'John Doe', email: 'john@example.com' }
// }
```

### Scenario: Validating an incorrect row
```javascript
const schemaName = 'Employee';
const row = { name: 'John Doe', email: 'invalid-email' };

const result = ValidationEngine.validate(row, schemaName);
// Expected output:
// {
//   isValid: false,
//   errors: [
//     { field: 'email', message: 'Formato de email inválido', value: 'invalid-email' }
//   ],
//   validatedData: { name: 'John Doe' }
// }
```

## 5. Acceptance Criteria
- **MUST**:
  1. `ValidationEngine` accurately validates row data against `APP_SCHEMAS` constraints.
  2. The engine returns a standardized response object `({ isValid, errors, validatedData })`.
  3. The engine covers required fields, type checks, and basic format validation (e.g., email, dates).
- **SHOULD**:
  1. Support partial validation (ignoring specific fields for draft saves).
- **MUST NOT**:
  1. Have side effects (it should be a pure validation layer, not modifying the original input by reference implicitly).
