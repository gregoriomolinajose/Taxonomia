# Story Design: S61.1 - IDataProvider Interface

## 1. Frame What & Why
**Problem:** The main ETL engine currently depends directly on Google Apps Script (`SpreadsheetApp`). This couples it tightly to the platform and prevents purely in-memory testing.
**Value:** By abstracting the data source behind an `IDataProvider` interface, we can test the core logic instantly in memory and easily plug in new data sources in the future.

## 2. Describe Approach
**Solution:** Define an `IDataProvider` interface with standardized `read` and `write` methods. Implement this interface with `GoogleSheetsProvider` (which encapsulates `SpreadsheetApp`) and `MockDataProvider` (which holds data in memory). Refactor the `ETLEngine` to accept an `IDataProvider` via dependency injection.
**Data Mutation Strategy:** If an entity (e.g. sheet) does not exist when reading or writing, the provider will reject with a clear error rather than dropping data silently.
**Value Preservation Gate:** `GoogleSheetsProvider` preserves the domain intelligence of translating between standardized generic records and specific Google Sheets API calls (`getRange`, `getValues`, headers mapping).

### Components affected:
- `src/core/IDataProvider.ts` (new)
- `src/adapters/GoogleSheetsProvider.ts` (new)
- `src/adapters/MockDataProvider.ts` (new)
- `src/core/ETLEngine.ts` (modify)

## 3. Create Examples

### API Usage
```typescript
// Example 1: In-memory mock testing
const mockProvider = new MockDataProvider({
  'Sheet1': [
    { id: 1, name: 'Alice' },
    { id: 2, name: 'Bob' }
  ]
});
const etl = new ETLEngine(mockProvider);
const testData = mockProvider.read('Sheet1');
// Expected testData: [{ id: 1, name: 'Alice' }, { id: 2, name: 'Bob' }]

// Example 2: Real Google Sheets adapter
const gsProvider = new GoogleSheetsProvider(SpreadsheetApp.getActiveSpreadsheet());
const realData = gsProvider.read('Sheet1');
// Expected realData: [{ id: 1, name: 'Alice' }, { id: 2, name: 'Bob' }]
```

### Data Structures
```typescript
interface IDataProvider {
  read(entityName: string): Record<string, any>[];
  write(entityName: string, records: Record<string, any>[]): void;
}
```

## 4. Define Acceptance Criteria
- **MUST**: The `IDataProvider` interface is defined with `read(entityName)` and `write(entityName, records)` methods.
- **MUST**: `GoogleSheetsProvider` encapsulates all calls to `SpreadsheetApp` and is able to read/write standard objects.
- **MUST**: The core ETL engine uses dependency injection to receive an `IDataProvider` rather than using `SpreadsheetApp` directly.
- **MUST**: `MockDataProvider` allows running the engine entirely in memory for test suites.
- **MUST**: Include at least one test/scenario running with real infrastructure (GoogleSheetsProvider against actual spreadsheet).
- **MUST NOT**: The core ETL engine makes direct calls to Google Apps Script (`SpreadsheetApp`).
