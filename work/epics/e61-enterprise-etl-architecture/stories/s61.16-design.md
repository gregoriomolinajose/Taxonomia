# Story S61.16 Design: Fail-fast Schema Format Validation

## 1. Frame What & Why

- **Problem**: `Engine_ETL.extractDataFromDrive` does not reject files with entirely unmatching headers (`maxOverlap <= 0`). This allows invalid or irrelevant Google Sheets to proceed in the pipeline, which leads to confusion, silent data drops, or downstream errors.
- **Value**: Failing fast with a clear message prevents wasted time and allows users to immediately understand that they uploaded a malformed or incorrect spreadsheet.

## 2. Approach

- **Solution**: Add a validation check in `extractDataFromDrive` right after computing `maxOverlap` across all sheets (around line 316). If `schema` and `schema.fields` are valid, and `maxOverlap <= 0`, throw an explicit Error with message `"Formato Incompatible: Los encabezados del archivo no coinciden con la entidad..."`.
- **Components affected**: `src/Engine_ETL.js` (modification).

## 3. Examples

### Example: Validation of mismatched headers
```javascript
// GIVEN:
// A Google Sheet without any recognized columns for the "Persona" schema.
// All sheets in the workbook result in maxOverlap = 0.

// WHEN:
// extractDataFromDrive is called
try {
  const records = Engine_ETL.extractDataFromDrive('Persona', '1A2B3C_invalid_sheet_id');
} catch (e) {
  // THEN:
  // It should fail fast and throw a precise error.
  console.assert(e.message === "Formato Incompatible: Los encabezados del archivo no coinciden con la entidad...");
}
```

## 4. Acceptance Criteria

- **MUST**: Throw an Error containing "Formato Incompatible: Los encabezados del archivo no coinciden con la entidad..." when `maxOverlap <= 0` and the entity has a valid schema.
- **MUST**: Stop the extraction process immediately upon encountering this condition, preventing unnecessary row processing.
- **MUST NOT**: Affect normal extraction when `maxOverlap > 0`, even if the overlap ratio is low.
