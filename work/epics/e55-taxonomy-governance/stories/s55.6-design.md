# S55.6 Design: Autoguardado Universal en el Wizard

## What & Why
**Problem:** The wizard only autosaves progress during the specific transition to the Taxonomia Canvas. If a user navigates between steps in other entities (or other steps within Taxonomia), their progress is not saved to the database until they manually click the primary "Guardar" button. This can cause data loss or prevent relationships in later steps from linking to a valid UUID.
**Value:** Transparent and continuous persistence ensures data safety, provides an immediate UUID for relational assignments on subsequent steps, and improves the overall UX.

## Approach
- **Component:** `UI_FormStepper.client.js` (Modification)
- **Strategy:** Refactor the interception logic within `goToSection` to remove the hardcoded restrictions (`this.entityName === 'Taxonomia'` and `this.currentStepIndex === 0`). Instead, apply the `FormEngine.saveForm(..., false)` logic universally for any step transition when moving forward or using the sidebar.

## Examples
**Usage Scenario:**
1. User opens the wizard to create a new `Portafolio` (Entity: Portafolio).
2. User fills the "Configuración General" step.
3. User clicks "Siguiente" or clicks on Step 2 in the sidebar.
4. The stepper disables the "Siguiente" button, invokes `window.FormEngine.saveForm()` with `isFormModal = false` to save the data in the background.
5. Upon successful callback, the stepper reenables the button and completes the transition to Step 2.

## Acceptance Criteria
- **MUST**: The stepper triggers a background save when transitioning between steps.
- **MUST**: The `isFormModal = false` flag is passed so the drawer doesn't close on auto-save.
- **MUST NOT**: The stepper must not advance to the next step if the save operation fails validation or returns an error.
