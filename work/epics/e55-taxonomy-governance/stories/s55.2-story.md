# S55.2 Inmersión UX (Full-Screen & Accesos)

## User Story
**Como** Arquitecto de Negocio
**Quiero** acceder rápidamente a la Taxonomía desde el dashboard y poder expandir el lienzo a pantalla completa
**Para** tener una experiencia inmersiva libre de distracciones y enfocarme exclusivamente en el diseño topológico.

## Acceptance Criteria

### Scenario 1: Acceso rápido desde el Dashboard
**Given** que el usuario está en el Dashboard (Self-Service Home)
**When** visualiza las tarjetas de acceso rápido
**Then** debe existir un card destacado para "Taxonomía"
**And** al hacer clic, debe navegar al router en la vista de Taxonomía.

### Scenario 2: Toggle de Pantalla Completa
**Given** que el usuario está diseñando una taxonomía en el Canvas
**When** hace clic en el botón "Expandir" (icono expand-outline) en el header
**Then** el contenedor principal del Wizard debe expandirse para ocupar el 100% de la altura y anchura disponible (z-index superior si es necesario)
**And** el ícono debe cambiar a "Contraer" (contract-outline)
**And** las herramientas de pan y zoom deben recalcular sus límites correctamente para seguir funcionando en la vista expandida.

## Technical Implementation Details
- **Dashboard Access**: Añadido 'Taxonomia' a la configuración de `SelfService_Home_UI.client.js` para crear el acceso directo de forma inmersiva.
- **Wizard Fullscreen Engine**: 
  - Se reestructuró `UI_Router.client.js` y `UI_FormStepper.client.js` para desacoplar la inicialización del lienzo (Canvas) de los cajones laterales (Drawers), permitiendo su montaje en `#wizard-fullscreen-zone`.
  - Se implementó la ocultación dinámica de la barra lateral izquierda en el paso 2, asignando 12 columnas a la sección del lienzo para ocupar el 100% del espacio horizontal.
  - Se aplicó `box-sizing: border-box` a `.tax-canvas-container` en `CSS_TaxonomyCanvas.html` para prevenir desplazamientos verticales (scroll) accidentales causados por el padding.
- **Relational Integrity via Eventing**:
  - Se restauró el campo `id_unidad_negocio` en el esquema de `Taxonomia` (`Schema_Engine.js`) como campo `hidden`, eliminando por completo el componente UI `TXSearchable` pero preservando la integridad de la persistencia.
  - Se implementó un "Event Listener" en `UI_View_SwimlaneGrid.client.js` para interceptar la creación de una Unidad de Negocio (a través del botón `+` del lienzo). Este inyecta el nuevo ID en el formulario oculto y fuerza el refresco optimista inmediato del lienzo.

## Architecture & Quality Review
- **Architecture Review**: PASS. La solución es proporcional (Beck's Simple Design). Evita el sobre-diseño al reutilizar el `AppEventBus` existente y mantener la validación nativa del DOM (inputs hidden). No se crearon abstracciones redundantes.
- **Quality Review**: PASS. El modelo de inyección de eventos (`dispatchEvent(new Event('change'))`) respeta la cadena reactiva. Los selectores DOM son resilientes y las modificaciones CSS previenen de manera robusta los desbordamientos. No se introdujeron vulnerabilidades semánticas.
