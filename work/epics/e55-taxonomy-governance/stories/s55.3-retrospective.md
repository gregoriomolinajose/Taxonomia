# Retrospective: S55.3 Motor de Diffing de Grafos

## Resumen de Resultados
Se implementó con éxito el motor de Diffing Topológico (`GraphTopologyDiffer.computeDelta`). La lógica demostró ser eficiente, utilizando complejidad O(N) gracias al uso de Mapas (Maps) de ES6. Las pruebas en Jest validaron todos los flujos de adición, eliminación y conservación.

## Verificación de Acceptance Criteria
- [x] AC1: Identifica correctamente aristas a agregar (ADD). (Validado vía Test Unitario).
- [x] AC2: Identifica correctamente aristas a eliminar (REMOVE). (Validado vía Test Unitario).
- [x] AC3: Identifica correctamente aristas a mantener (KEEP). (Validado vía Test Unitario).

## Learnings
- **Pure Functions:** Separar la lógica de negocio pura (el differ) de las transacciones de base de datos (`patchSCD2Edges` o similares) permite un Testing mucho más robusto. No tuvimos que simular (mockear) la DB para validar algoritmos topológicos complejos.
- **Composite Hashing:** El uso de `${id_nodo_padre}::${id_nodo_hijo}::${tipo_relacion}` demostró ser la manera más confiable de identificar la firma única de una arista, ya que los IDs primarios generados (UUID) varían entre entornos (Borrador vs Producción).
