# S54.4: Estrategia ETL y Pre-hidratación (Resolución JIT)

## User Story
**Como** analista de datos / usuario de la tabla
**Quiero** ver nombres y etiquetas amigables en los filtros en lugar de UUIDs incomprensibles
**Para** poder realizar búsquedas y segmentaciones precisas sin tener que memorizar claves relacionales.

## Acceptance Criteria

**Scenario 1: Resolución de Diccionario (Lookups)**
- **Given** un campo de tipo relación o FK (ej. `id_departamento`)
- **When** el `UI_UniversalFilter` extrae los valores únicos para poblar los checkboxes
- **Then** traduce el UUID usando el diccionario en memoria (`window._LOOKUP_DATA`), mostrando el texto amigable en el frontend.

**Scenario 2: Comunicación de Filtros Invertida**
- **Given** que el usuario selecciona la opción "Sistemas" (cuyo valor interno original es un UUID: `dpt-123`) en el Drawer
- **When** se emite el evento `onFilterChange`
- **Then** el motor de estado y la UI mantienen el UUID original intacto para realizar la intersección matemática pura. Solo la vista (etiquetas de checkbox) es modificada.
