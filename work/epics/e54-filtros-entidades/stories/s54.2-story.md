# S54.2: Lógica Base del Motor de Filtros

## User Story
**Como** usuario del sistema
**Quiero** que el panel de filtros lea la configuración real del sistema y mis datos cargados
**Para** poder armar un filtro basado en la metadata real de la entidad, con opciones deducidas del dataset.

## Acceptance Criteria (Gherkin)

**Scenario 1: Lectura del esquema dinámico**
- **Given** que el panel se inicializa para la entidad (ej. "Personas")
- **When** abro el selector de campos
- **Then** veo únicamente los campos declarados en `APP_SCHEMAS.Personas` excluyendo campos `hidden` y `divider`.

**Scenario 2: Generación de Opciones Dinámicas**
- **Given** que activo un campo para filtrar
- **When** se renderiza la tarjeta del campo
- **Then** las opciones de checkbox se extraen mediante deduplicación (Set) de los valores presentes en el dataset cargado.

**Scenario 3: State Management**
- **Given** que he seleccionado opciones múltiples en diversos campos
- **When** interactúo con los checkboxes
- **Then** el componente mantiene y emite un estado de filtrado interno que obedece al contrato (ej. `{ "departamento": ["Identidad", "Core"], "estado": ["Activo"] }`).
