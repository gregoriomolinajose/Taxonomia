# S54.2: Diseño Técnico - Lógica Base del Motor de Filtros

## What & Why
- **Problem**: El Drawer visual creado en la S54.1 es un *mock*. Necesitamos dotarlo de la lógica capaz de extraer qué columnas se pueden filtrar y qué valores existen, dependiendo de la entidad en uso.
- **Value**: Universalidad. Con esta lógica, la misma base de código servirá para desplegar un filtro de "Portafolios", "Personas", o "Dominios" sin escribir código ad-hoc.

## Approach
- Convertir el objeto estático en una estructura instanciable: `class UI_UniversalFilter`.
- El constructor recibirá la metadata global `APP_SCHEMAS`, el `entityName` y el array de `records`.
- Se implementará un mecanismo local de DOM listeners (Vanilla JS) para manejar los cambios de checkboxes e invocar el callback `onFilterChange()`.

## Examples (API)
```javascript
const filter = new UI_UniversalFilter({
    entityName: 'Personas',
    schemaConfig: APP_SCHEMAS,
    records: [ { departamento: 'TI', estado: 'Activo' }, ... ],
    containerEl: document.getElementById('drawer-container'),
    onFilterChange: (newState) => {
        // newState = { "departamento": ["TI"] }
    }
});

filter.render();
```
