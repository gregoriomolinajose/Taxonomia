# S54.1: Diseño Técnico - UI/UX Filtro Universal

## What & Why
- **Problem**: Requerimos validar visualmente el componente Drawer (Jira-like) antes de inyectarle la complejidad algorítmica de la metadata `APP_SCHEMAS`.
- **Value**: Asegurar responsividad, encapsulamiento CSS y una UX de primera clase de manera aislada.

## Approach
- Crear `src/UI_UniversalFilter.client.js` y `src/CSS_UniversalFilter.html`.
- La función principal (`renderUniversalFilterDrawer`) retornará un contenedor puro usando datos simulados (mocks).
- El estilo se encapsulará bajo la clase principal `.tx-filter-drawer`.

## Examples (DOM Structure)
```html
<div class="tx-filter-drawer">
  <div class="drawer-header">
     <h3>Filtros</h3>
     <button class="close-btn">×</button>
  </div>
  <div class="drawer-body">
     <!-- Mock Field: Área de Producto -->
     <div class="filter-card">
         <label>Área de Producto</label>
         <input type="search" placeholder="Buscar..." />
         <div class="checkbox-list">
             <label><input type="checkbox"/> Identidad</label>
         </div>
     </div>
  </div>
</div>
```

## Acceptance Criteria
- **MUST**: Ref. a los escenarios Gherkin en `s54.1-story.md`.
- **MUST**: Todo el CSS debe estar encerrado dentro de la clase `.tx-filter-drawer`.
- **MUST**: El componente renderizado no debe ejecutar peticiones al backend ni mutar estado global en esta etapa.
