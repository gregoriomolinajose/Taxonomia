## Architecture Review: S67.1 (scope: story)

### Critical (fix before merge)
- packages/core/src/Engine_DB.js:853, H9 (Semantic Duplication / Mismatched Intent)
  - **Concern:** The cache retrieval logic explicitly bypasses the cache when `format === 'tuples'` (using `format !== 'tuples'`). This directly violates the Acceptance Criteria which states that `Engine_DB.list` must use the tuple cache avoiding database hits.
  - **Simplification:** Remove the `&& format !== 'tuples'` condition from both the read and write caching logic in `Engine_DB.list` to properly leverage the caching mechanism for tuples.

### Recommended (simplify before next cycle)
- environments/Config.dev.js:4, H8 (Configuration Over Convention)
  - **Concern:** `ALLOWED_DOMAINS` contains hardcoded fallback domains (`@gmail.com`, `@bellfy.app`). Since the story addresses Domain Leakage, leaving these in a file that might be exposed to the client or version control contradicts the goal of hiding sensitive domain data.
  - **Simplification:** Remove the hardcoded fallback domains and rely strictly on the `PropertiesService` (`APP_CONFIG__allowed_domains`) to inject this data safely at runtime.

### Questions (require human judgment)
- packages/core/src/Auth_UI.html:79, H2 (Wrapper Without Logic)
  - **Concern:** `renderAccessDenied` dynamically injects a raw `div` with absolute positioning over the `body`. Is this raw DOM manipulation strictly necessary, or could we route to a dedicated "Unauthorized" Ionic view or use a standardized `ion-modal` to stay consistent with the framework?
  - **Simplification:** Use standard Ionic routing or modal controllers to manage the access denied state instead of raw DOM overlays.

### Observations (patterns noted)
- packages/core/src/JS_Core.client.js:594, H1 (Single Implementation)
  - **Concern:** The `bindAvatar` function properly parses the URL and restricts it to safe protocols (`http:`, `https:`, `data:`), which effectively satisfies the XSS mitigation requirements without unnecessary abstractions.
- packages/core/src/Auth_UI.html:42, H1 (Single Implementation)
  - **Concern:** `AuthManager.init()` employs a simple boolean lock (`this._initialized`) to prevent redundant calls. This meets the performance optimization goals efficiently.
