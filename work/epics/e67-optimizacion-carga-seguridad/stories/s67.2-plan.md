# S67.2 Implementation Plan: Bootstrap Selectivo y Diferimiento

## Overview
- **Story ID**: S67.2
- **Size**: M
- **Date**: 2026-08-08

## Tasks

### 1. Defer CDNs in Index.html
- **Description**: Add `defer` attribute to heavy libraries (like Chart.js or similar) in `Index.html` to prevent rendering blocks.
- **Files**: `Index.html`
- **TDD Cycle**: RED (Verify CDNs block parsing) -> GREEN (Add `defer` attributes) -> REFACTOR
- **AC Reference**: Defer CDNs
- **Verification**: Run local server, check network tab for non-blocking script loads.
- **Size**: XS
- **Dependencies**: None

### 2. Implement Schema Pruning
- **Description**: Create a filtering mechanism to prune backend-only metadata from `APP_SCHEMAS` before it is injected.
- **Files**: Backend scripts handling schema injection
- **TDD Cycle**: RED (Write test checking injected schema contains backend fields) -> GREEN (Implement pruning function) -> REFACTOR
- **AC Reference**: Prune schema
- **Verification**: Unit test the pruning logic; verify output schema payload.
- **Size**: S
- **Dependencies**: None

### 3. Selective Tab Data on Bootstrap
- **Description**: Modify `getAppBootstrapPayload` to only return data for the default tab (e.g., Dashboard).
- **Files**: Backend scripts handling `getAppBootstrapPayload`
- **TDD Cycle**: RED (Write test expecting only default tab data) -> GREEN (Filter payload) -> REFACTOR
- **AC Reference**: Lazy load tabs
- **Verification**: Unit test `getAppBootstrapPayload`.
- **Size**: S
- **Dependencies**: None

### 4. Asynchronous Data Fetching for Non-Default Tabs
- **Description**: Update frontend tab navigation logic to asynchronously fetch tab data if it wasn't included in the initial bootstrap payload.
- **Files**: Frontend UI scripts for tabs
- **TDD Cycle**: RED (Test clicking tab fails without data) -> GREEN (Add fetch logic for missing tab data) -> REFACTOR
- **AC Reference**: Lazy load tabs
- **Verification**: UI component test / Manual verification.
- **Size**: M
- **Dependencies**: Task 3

### 5. Manual Integration Test
- **Description**: Validate end-to-end with running software to ensure correct rendering, fast initial load without CDN blocking, pruned schema, and functioning tab data loading.
- **Files**: N/A
- **TDD Cycle**: N/A
- **AC Reference**: All
- **Verification**: Launch full app stack, click through all tabs, monitor network tab for lazy loads and payload sizes.
- **Size**: XS
- **Dependencies**: Task 1, 2, 3, 4

## Execution Order
1. **Task 1** (Parallelizable)
2. **Task 2** (Parallelizable)
3. **Task 3** (High priority for data reduction)
4. **Task 4** (Dependent on Task 3, implements UI reaction)
5. **Task 5** (Final integration test)

**Rationale**: 
Risk-first ordering. Tasks 1, 2, and 3 tackle the main backend payload reduction and HTML parsing optimization independently. Task 4 ties the backend changes of Task 3 to the frontend UI, representing the most integration risk. Task 5 validates everything.

## Risks & Mitigations
- **Risk**: Deferring CDNs might break inline scripts that depend on them synchronously.
  - *Mitigation*: Audit inline scripts and move dependent logic to `DOMContentLoaded` or module scopes.
- **Risk**: Missing tab data might leave UI in a broken state if the async fetch fails.
  - *Mitigation*: Add proper loading states and error handling to the async fetch logic in Task 4.
