# Design: S67.3 - Refactorización Server-Side (I/O y Caché ABAC)

## 1. Context & Complexity
- **Complexity:** Moderate (Touches core I/O and security cache, but logic changes are contained).
- **Risk Gate:** High risk of breaking configuration if properties are not fully mapped. High risk of cross-tenant leakage if cache keys are generic.
- **Integration Gate:** Requires real Apps Script `PropertiesService` and `CacheService` validation; mocks are insufficient to measure true I/O latency reduction.

## 2. What & Why
- **Problem:** Scattered `getProperty()` calls cause massive I/O overhead in Apps Script. ABAC caching needs multi-tenant isolation without breaking E68's GViz Zero-Trust model.
- **Value:** Reading properties in a single batch will heavily reduce `doGet` execution time, contributing to the epic's <2.5s load time goal. Isolated ABAC caching ensures security compliance.

## 3. Approach
1. **Properties Consolidation:** Implement a memory cache object populated by a single `PropertiesService.getScriptProperties().getProperties()` call at the start of `doGet`. Replace all `getProperty(key)` calls in `Code.js` and `Controller_Action.js` with property lookups on this object.
2. **ABAC Cache Isolation:** Modify the cache writing/reading logic in `Engine_ABAC.js` to use tenant-aware cache keys (e.g., `abac_cache_${tenantId}_${role}`).
3. **GViz Zero-Trust Compatibility:** Ensure that cache misses or hits still funnel through `Engine_ABAC.validatePermission` properly so the deny-by-default behavior (E68) is strictly maintained. 

**Missing-Entity Strategy:** If a critical property (like `DB_ID`) is missing from the batch read, the application must hard-fail immediately with an explicit error, rather than degrading gracefully or silently dropping. (PAT-E-523)

## 4. Examples (Crucial)

**Properties Batching:**
```javascript
// Before
const dbId = PropertiesService.getScriptProperties().getProperty('DB_ID');
const apiKey = PropertiesService.getScriptProperties().getProperty('API_KEY');

// After
// At bootstrap:
const AppConfig = PropertiesService.getScriptProperties().getProperties();
// Usage:
const dbId = AppConfig['DB_ID'];
const apiKey = AppConfig['API_KEY'];
```

**ABAC Tenant-Aware Caching:**
```javascript
// Building the cache key
const cacheKey = `abac_tenant_${userTenantId}_role_${userRole}`;

// Checking cache
const cachedAbac = CacheService.getScriptCache().get(cacheKey);
if (cachedAbac) {
  return JSON.parse(cachedAbac);
}

// Generate topology and cache it
const topology = generateAbacTopology(); // GViz based from E68
CacheService.getScriptCache().put(cacheKey, JSON.stringify(topology), 21600);
```

## 5. Acceptance Criteria
- **MUST:** `PropertiesService.getScriptProperties().getProperties()` is called exactly once during the server request lifecycle.
- **MUST:** All previous `getProperty(key)` calls are replaced with in-memory object lookups.
- **MUST:** The ABAC cache mechanism strictly isolates permissions per tenant using composite cache keys.
- **MUST NOT:** The E68 Zero-Trust GViz queries and strict deny-by-default logic must not be altered or bypassed.
- **SHOULD:** `doGet` server execution time demonstrates a measurable reduction compared to baseline.
