# S67.3 Implementation Plan: Refactorización Server-Side (I/O y Caché ABAC)

## Overview
- **Story ID:** S67.3
- **Size:** M
- **Date:** 2026-08-08

## Tasks

### Task 1: Consolidar I/O de PropertiesService
- **Description:** Implement a memory config object by calling `PropertiesService.getScriptProperties().getProperties()` once at the start of `doGet`. Replace all `getProperty(key)` calls with object lookups. Ensure missing critical entities hard-fail immediately.
- **Files:** `Code.js`, `Controller_Action.js`
- **Verification:** Code compilation and verification that `doGet` executes without configuration errors.
- **Size:** S
- **Dependencies:** None

### Task 2: Aislar Caché ABAC Multitenant
- **Description:** Update `Engine_ABAC.js` to use composite, tenant-aware cache keys (`abac_tenant_${userTenantId}_role_${userRole}`) when writing/reading permissions cache.
- **Files:** `Engine_ABAC.js`
- **Verification:** Code inspection / mock validation that different roles/tenants generate distinct cache keys.
- **Size:** S
- **Dependencies:** None

### Task 3: Verificar Compatibilidad Zero-Trust
- **Description:** Ensure the cache logic properly handles cache misses and forwards them to the E68 GViz Zero-Trust pipeline, maintaining deny-by-default behavior.
- **Files:** `Engine_ABAC.js`
- **Verification:** Verify permissions lookup fallback behavior.
- **Size:** XS
- **Dependencies:** Task 2

### Task 4: Manual Integration Test
- **Description:** Deploy the codebase and manually validate end-to-end with the running software. Measure server execution time for `doGet` to ensure reduction from baseline. Verify ABAC security behaves correctly across test accounts.
- **Files:** N/A
- **Verification:** End-to-end manual testing.
- **Size:** M
- **Dependencies:** Task 1, Task 2, Task 3

## Execution Order
1. **Task 1** (Riskiest configuration change, foundational for backend execution)
2. **Task 2** (Can be executed in parallel with Task 1, isolates security logic)
3. **Task 3** (Dependent on Task 2 to ensure integration)
4. **Task 4** (Integration test dependent on all above)

**Rationale:** Task 1 affects global configuration so it's best done early to catch any widespread failures. Tasks 2 and 3 affect a specific module (ABAC) and can be done safely. Finally, Task 4 validates everything end-to-end.

## Risks and Mitigations
- **Risk:** Missing properties in the batched read causing runtime errors.
  - **Mitigation:** Implement explicit missing-entity validation that hard-fails immediately if critical keys (like `DB_ID`) are absent.
- **Risk:** Cache key collision or leakage.
  - **Mitigation:** Strict enforcement of the `abac_tenant_${userTenantId}_role_${userRole}` naming convention.
- **Risk:** Integration gate requires real Apps Script validation.
  - **Mitigation:** Strict reliance on Task 4's manual integration tests on real Google infrastructure.
