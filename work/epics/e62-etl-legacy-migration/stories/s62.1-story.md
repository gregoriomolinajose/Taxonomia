# Story: Migrate Persona Rules (Allowed Domains & Auto-Sync)

## User Story
As a system administrator,
I want the legacy Persona validation rules and Workspace Sync logic to run via the backend Job Worker,
so that we can safely remove the legacy ETL client scripts without losing functionality or data integrity.

## Acceptance Criteria

### Scenario: Validating allowed domains
```gherkin
Given a user attempts to update or import a Persona
When the email domain is evaluated
Then the validation must enforce ALLOWED_DOMAINS through Business_Interceptors or hydrateAndDeduplicate on the backend.
```

### Scenario: Workspace Sync triggers on completion
```gherkin
Given an ETL job processing Persona entities finishes successfully
When the Job Worker finalizes the ETL job
Then the system must automatically trigger the Workspace Sync job via Job Queuing chaining.
```

## Examples (Specification by Example)

| Input | Action | Expected Output |
|-------|--------|-----------------|
| Persona record with valid domain | Backend processing | Validation passes, Persona saved |
| Persona record with invalid domain | Backend processing | Validation fails, Error logged |
| Persona ETL Job finishes | Job completion | Workspace Sync Job queued |
