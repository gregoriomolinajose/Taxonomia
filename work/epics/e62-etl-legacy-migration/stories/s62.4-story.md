# S62.4 Clean up legacy ETL modules

**As a** system maintainer
**I want** to completely remove legacy frontend ETL modules (`DataEngine_ETL.client.js` and `DataEngine_ETL_Capacidades.client.js`)
**So that** the application strictly routes all ETL work through the centralized backend API, reducing frontend payload size and avoiding dual-maintenance of ETL logic.

### Acceptance Criteria

**Scenario 1: Legacy files are removed from the repository**
* Given the repository codebase
* When a search is performed for `DataEngine_ETL.client.js`
* Then no physical files should exist in the source directory.

**Scenario 2: HTML templates no longer import legacy modules**
* Given the main `Index.html` or script loader templates
* When the application renders
* Then no `<script>` tags should point to the deleted legacy `.client.js` files.

**Scenario 3: The Bulk Importer gracefully uses the backend pipeline**
* Given a user wants to upload a file
* When the Bulk Importer UI initializes
* Then it should default to calling the backend API `etl_extract_sheet_data` without attempting to load entity-specific frontend clients.
