# Plan S62.2: Migrate Dominio Dynamic Topology

## Overview
- **Story ID**: S62.2
- **Size**: M
- **Date**: 2026-07-16
- **Status**: Planned

## Task List

### Task 1: Implement `CalculateDominioTopology` Interceptor
- **Description**: Create the backend interceptor function `CalculateDominioTopology(entityName, items)` in `Business_Interceptors.js`. Because the ETL engine processes items in chunks of 50, the interceptor MUST fetch all existing `Dominio` records from the database (`Engine_DB.list('Dominio', 'objects').rows`) to build a comprehensive lookup map by `orden_path`. It will then deduce and assign `relaciones_padre` to each item based on its parent's `orden_path` (e.g., splitting by '.'). If a parent is missing, it leaves `relaciones_padre` untouched.
- **Files**: `src/Business_Interceptors.js`, `__tests__/Business_Interceptors.test.js` (or `src/TEST_Suite.js` if local tests are added there).
- **TDD Cycle**: 
  - RED: Write test asserting the topological assignment logic with mock DB response simulating cross-chunk parent existence.
  - GREEN: Implement the function.
  - REFACTOR: Optimize the lookup map creation.
- **AC Reference**: Scenario: Calculate relaciones_padre from orden_path
- **Verification Command**: `npm run test`
- **Size**: M
- **Dependencies**: None

### Task 2: Register Interceptor in Schema Engine

## Execution Order & Rationale

1. **Task 1 (Backend Logic)**: Riskiest part of the story due to the required database lookup per chunk. Implementing this first isolates the complex logic.
2. **Task 2 (Registration)**: Straightforward wiring of the interceptor.
3. **Task 3 (Frontend Cleanup)**: Deleting code is easy but we do it after the backend is ready so the system conceptually moves from the old way to the new way.
4. **Task 4 (E2E Test)**: Final verification step to ensure the integration point between frontend payloads and the new backend interceptor behaves flawlessly across chunks.

## Risks & Mitigations
- **Risk**: Fetching all Dominios from the DB on every chunk (e.g. 10 chunks) could slow down the ETL process or hit Apps Script execution limits.
- **Mitigation**: We might need to implement a simple memoization/cache within the execution context of the `CalculateDominioTopology` function if performance becomes an issue during the manual integration test.
