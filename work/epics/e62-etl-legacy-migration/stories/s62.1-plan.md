# Story Plan: S62.1 - Migrate Persona Rules

## Overview
- **Story ID:** S62.1
- **Size:** M
- **Date:** 2026-07-16

## Tasks

### 1. Implement EnforceAllowedDomains Interceptor
- **Description:** Update `src/Business_Interceptors.js` to include an interceptor for the `Persona` entity. This interceptor must validate the `email` field against `CONFIG.ALLOWED_DOMAINS` and reject the mutation if the domain is not allowed.
- **Files:** `src/Business_Interceptors.js`
- **TDD Cycle:** RED (failing test for domain rejection and acceptance) → GREEN (minimal code to validate domain) → REFACTOR (clean up logic).
- **AC Reference:** AC1 (Backend validation rejects Persona mutations if their email domain is not in ALLOWED_DOMAINS)
- **Verification Command:** `npm test` (or equivalent unit test command)
- **Size:** S
- **Dependencies:** None

### 2. Implement Auto-Sync Chaining in Job Worker
- **Description:** Update `src/Job_Worker.js` to hook into the job completion phase. If the job processed `Persona` entities and finished successfully, it must enqueue a new background job for `Job_WorkspaceSync`.
- **Files:** `src/Job_Worker.js`
- **TDD Cycle:** RED (failing test for auto-chaining logic) → GREEN (minimal code to enqueue Job_WorkspaceSync) → REFACTOR (clean up execution logic).
- **AC Reference:** AC2 (Upon successful ETL job completion for Persona entities, the Job Worker triggers the Workspace Sync Job queue)
- **Verification Command:** `npm test` (or equivalent unit test command)
- **Size:** S
- **Dependencies:** None

### 3. Manual Integration Test (End-to-End)
- **Description:** Validate the complete end-to-end functionality. Ensure valid domains are processed, invalid domains are rejected with an error, and the Workspace Sync job queues upon ETL success.
- **Files:** None (System test)
- **TDD Cycle:** N/A
- **AC Reference:** AC1, AC2
- **Verification Command:** `npm run deploy:dev:auto` followed by manual user verification in Google Apps Script (as per project rules).
- **Size:** XS
- **Dependencies:** Task 1, Task 2

## Execution Order
1. **Task 1** (EnforceAllowedDomains Interceptor): Core data integrity logic; ensures bad data is stopped early.
2. **Task 2** (Auto-Sync Chaining): Operational chaining logic. Independent from Task 1, can be executed sequentially or in parallel.
3. **Task 3** (Manual Integration Test): Executed last after codebase changes are complete.

## Risks and Mitigations
- **Risk:** `CONFIG.ALLOWED_DOMAINS` is not properly injected or available in the backend context when the interceptor runs.
  - **Mitigation:** Verify `global.CONFIG` or `ENV_CONFIG` availability early during Task 1 development.
- **Risk:** Unintentional infinite loops or duplicate queuing of `Job_WorkspaceSync`.
  - **Mitigation:** Strictly scope the trigger to only fire when the completing job's entity is `Persona` and its status is `COMPLETED`.
