# Design S62.2: Migrate Dominio Dynamic Topology

## 1. What & Why
- **Problem**: The calculation of `relaciones_padre` from `orden_path` for the `Dominio` entity is currently executed in the frontend script, mixing UI logic with business rules.
- **Value**: Moving this logic to a backend interceptor centralizes topology rules and ensures consistent data mutations regardless of the entry point, deprecating the legacy frontend ETL logic.

## 2. Approach
- **Solution**: Implement a backend `Business_Interceptor` (e.g., `CalculateDominioTopology`) that runs before persistence. It will sort the `Dominio` batch by `orden_path` and assign the `relaciones_padre` field based on matching the parent's `orden_path`. Remove the equivalent logic from `DataEngine_ETL.client.js`.
- **Components Affected**:
  - `src/Business_Interceptors.js`: Create `CalculateDominioTopology` interceptor.
  - `src/Schema_Engine.js`: Register `CalculateDominioTopology` in the `mutationInterceptors` for `Dominio`.
  - `src/DataEngine_ETL.client.js`: Remove the frontend `relaciones_padre` calculation.
- **Missing Entity Strategy**: If a parent is missing (i.e., we split `orden_path` but the parent isn't in the batch or map), we leave `relaciones_padre` blank (as the frontend script did: `if (parent) { r.relaciones_padre = parent.id_dominio; }`). No error, just partial linkage. This preserves existing behavior.
- **Value Preservation Gate**: The domain intelligence is the topological mapping `A.B.C` -> parent `A.B`. This is preserved and moved to the appropriate backend abstraction.

## 3. Examples

### Example 1: Standard topology calculation
```javascript
const items = [
    { id_dominio: "DOM-1", orden_path: "1", nombre: "Root" },
    { id_dominio: "DOM-2", orden_path: "1.1", nombre: "Child A" },
    { id_dominio: "DOM-3", orden_path: "1.2", nombre: "Child B" },
    { id_dominio: "DOM-4", orden_path: "1.1.1", nombre: "Grandchild" }
];
CalculateDominioTopology('Dominio', items);

// Expected output (items is mutated in place):
// [
//    { id_dominio: "DOM-1", orden_path: "1", nombre: "Root" },
//    { id_dominio: "DOM-2", orden_path: "1.1", nombre: "Child A", relaciones_padre: "DOM-1" },
//    { id_dominio: "DOM-3", orden_path: "1.2", nombre: "Child B", relaciones_padre: "DOM-1" },
//    { id_dominio: "DOM-4", orden_path: "1.1.1", nombre: "Grandchild", relaciones_padre: "DOM-2" }
// ]
```

### Example 2: Missing parent
```javascript
const items = [
    { id_dominio: "DOM-2", orden_path: "1.1", nombre: "Child A" }
];
CalculateDominioTopology('Dominio', items);

// Expected output (items is mutated in place):
// [
//    { id_dominio: "DOM-2", orden_path: "1.1", nombre: "Child A" } // relaciones_padre is left untouched
// ]
```

## 4. Acceptance Criteria
- **MUST**: The `CalculateDominioTopology` interceptor correctly deduces `relaciones_padre` from `orden_path` by splitting on '.' and matching the prefix.
- **MUST**: The frontend logic for `relaciones_padre` in `DataEngine_ETL.client.js` is completely removed.
- **MUST**: The interceptor handles cases where a parent is not found in the current batch gracefully (leaves `relaciones_padre` empty or untouched).
